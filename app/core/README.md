# app/core — 全仓公共约定

主要维护：规则计算方向（问谁，不是评审权限）
PRD 层级：横切

## 职责

放全仓都需要、且与业务编排无关的基础约定：

| 文件 | 内容 |
| --- | --- |
| `config.py` | 运行配置 `Settings` 与规则阈值 `RuleThresholds` |
| `enums.py` | 受控枚举，对应 PRD V1.2 与数据分析说明书的口径表 |
| `timeutil.py` | 时间语义：业务时区、四类时间、泄露判定 |

## 边界

这是唯一可被所有模块 import 的模块，因此**只放不会引起争议的东西**。判断标准：如果一段代码需要知道「业务流程走到哪一步」，它就不属于 `core`。

不允许放进来的：ORM 模型、业务规则、状态机、HTTP 相关、模型调用。

不允许 import 任何 `app.*` 兄弟模块。一旦反向依赖立刻成环，`make lint-arch` 会失败。

## 改动这里的成本很高

`enums.py` 的取值直接影响 JSON Schema 校验与历史数据可复算性。增删枚举值需要：

1. 确认对应 PRD / 数据分析说明书的口径表是否已更新。
2. 评估历史数据是否需要迁移，以及旧值如何映射。
3. 同步 `contracts/ai/` 中相关 Schema 的 enum 列表——这一步会触发 `contracts/` 的 approve 要求。

改 `enums.py` 本身不强制评审，但几乎总要连带改 `contracts/`，届时那个 PR 需要 1 个 approve。想让人看时在 PR 里说明旧值映射方案。

`RuleThresholds` 的阈值变更需记版本（`version` 字段），历史结论不得被新阈值覆盖。改阈值同时要说明是否需要重算已有的状态建议。

## 关键约定

**时间语义**（数据分析说明书 T9）。必须同时保存四类时间：事实发生、公开披露、数据入库、AI 生成。收益检验只能使用信号生成时已公开可得的信息。

`timeutil.ensure_aware` 拒绝 naive datetime 静默入库。这条约束用于拦截样例交付包里的时区混用问题：台账 xlsx 是 naive UTC，CSV/JSON 是业务时区，两者有 8 小时系统性偏差。不拦截会让 DQ-003（披露时间不得晚于信号生成时间）给出错误结论。

**枚举分离**。`ImpactDirection`（证据相对假设的影响方向）与 `SignalDirection`（AI 候选信号方向）是两个枚举，字段字典 FLD-007 明确要求区分。两者都不是股价方向。写代码时不要合并。

**配置开关**。未完成能力的开关放在 `Settings` 里，默认关闭。引入开关时在 PR 描述里登记预期移除时间。

## 测试

`tests/unit/core/`。时间工具需覆盖：带时区输入、naive 输入抛错、跨时区取日历日、泄露判定边界（相等时不算泄露）。
