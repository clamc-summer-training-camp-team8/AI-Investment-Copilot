# app/ingest — 投研资料管道

负责人：数据管道负责人
PRD 层级：数据资源层

## 职责

把上传的文件变成可检索文本和可定位的引用位置。对应数据分析说明书的 A 类管道与 `DocumentIngest` 契约。

```
ingest/
├── parsers/     PDF / DOCX / TXT 解析，每种格式一个模块
└── ...          切片、指纹去重、引用定位、实体线索识别
```

MVP 支持 PDF / DOCX / TXT（FR-T-001）。

## 管道最低要求

数据分析说明书 7.1 的四条，全部是硬要求：

1. **原文件不可覆盖。** 解析结果必须记录原文件哈希（`content_hash`）和解析版本（`parser_version`）。改版生成新版本，不覆盖旧记录。
2. **每条 AI 结论必须能回到文件、页码或段落位置。** 这是 `evidence_locator` 的基础，格式 `{document_id}#paragraph-{n}`，存在 `document_segment` 表。
3. **同一内容多渠道转载去重，但保留最早公开时间和权威来源。** 去重靠 `content_hash`，来源集合存 `source_document_ids`（FR-R-005）。
4. **内部资料带权限标签，不得进入无权限用户的检索范围。** `visibility_label` 随文档走，证据可见性不得高于来源文档（PRD 12.1）。

## 边界

**不 import `app.ai`。** 解析是确定性步骤。想在解析阶段调模型补全字段是个常见冲动，但会让同一份文件两次解析得到不同结果，破坏 `parser_version` 的意义。语义抽取由 `app/workers` 在解析完成后调用 `app/ai`。

**不写业务表。** 只写 `document`、`document_segment`。`thesis`、`evidence` 由 `app/services` 写。

**不做 OCR。** 扫描件按解析失败处理，保留文件并展示失败原因（PRD 7.4 异常流程）。OCR 是后续能力。

## 定位精度决定产品可信度

`evidence_locator` 必须能打开原文并高亮到具体段落。FR-R-001 要求"结果可纠错并保留原文"，PRD 12.2 要求"正式 AI 结论展示来源、引用、模型版本和确认状态"。

定位不准的直接后果：研究员点开引用发现对不上，就不会再信任任何 AI 输出。这个模块的质量上限就是整个产品的可信度上限。

因此切片策略需要在段落语义完整与定位精度之间取平衡，切得太粗定位没用，切得太碎语义丢失。切片规则变化算 `parser_version` 变更。

## 时间字段

上传时必须能确定 `published_at`（首次公开可得时间）。DQ-001 规定此字段为空是阻断级错误，数据进隔离区，禁止生成正式信号。

无法从文件推断时，要求用户填写，不允许用入库时间兜底。用入库时间填充会直接造成未来信息泄露。

## 实体识别

识别证券主体线索，但**不自动绑定**。PRD 7.4 明确：证券实体歧义时要求用户选择。自动绑定错公司的代价远大于让用户多点一次。

## 失败处理

`DocumentIngest` 契约的失败处理是「隔离失败文件并记录原因」。要求：

- 保留原文件，不删除。
- 记录失败原因，允许重新上传或转为纯文本录入（PRD 7.4）。
- 失败记录写 `data_quality_result`，可在管理页查看并重试（FR-A-004）。

## 测试

- `tests/unit/ingest/` 切片与指纹逻辑，用小样本文件。
- `tests/integration/ingest/` 完整解析链路。
- 夹具放 `tests/fixtures/`，只用 `docs/data/数据分析交付包/业务样例包/` 的派生数据，禁止提交真实投研资料。
