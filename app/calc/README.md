# app/calc — 确定性计算与规则引擎

主要维护：规则计算方向（问谁，不是评审权限）
PRD 层级：AI 与规则层（规则侧）

## 职责

所有关键数值与状态判定。PRD 10.5 与 FR-V-002 要求数值计算由确定性程序完成，模型只解释结果。这个模块就是那个"确定性程序"。

```
calc/
├── backtest.py       研究验证型事件回测、净值、风险和交易审计
├── deterministic.py  预期差、同比环比、趋势、同业比较、超额收益
└── rules.py          失效条件判定、状态建议生成、证据聚合
```

## 硬约束

**纯函数模块。** 不 import `app.ai`、`app.db`、`app.services`、`app.api`、`app.ingest`。输入是值对象（`Observation`、`EvidenceSummary`），输出是带口径信息的数据类。

理由：DA-AC-04 要求预期差、同比环比、趋势和简单同业比较可复核。可复核意味着同样输入必须永远得到同样输出，并且能脱离数据库写单元测试穷举阈值边界。任何 IO 依赖都会破坏这一点。

**`Decimal` 而非 `float`。** 样例台账里出现过 `-0.019999999999999997` 这类浮点残留。研究员看到的数值不能有这种东西，超额收益 `-0.02` 就得是 `-0.02`。统一 `QUANT = Decimal("0.000001")` 量化。

**只产生建议，不改状态。** `suggest_status` 返回 `StatusSuggestion`，带 `requires_human_confirmation=True`。正式状态变更由 `app/services` 在人工确认后执行（PRD 5.4 / FR-S-002）。这个模块没有任何写路径。

**缺失不推算。** 数据缺失一律返回 `ValidationVerdict.INSUFFICIENT` 并说明原因，不做插值、不做外推。研究员需要知道"这里没数据"，而不是拿到一个编出来的数。

## 已实现的口径

| 函数 | 口径 | 来源 |
| --- | --- | --- |
| `expectation_gap` | 实际值−预期值，同时给绝对差与相对差 | 说明书 T13 / FR-V-001 |
| `period_over_period` | 同比或环比，由调用方选对照观测 | FR-V-002 |
| `trend` | 最近 4–8 期，只给方向、OLS 斜率和连续性，不做预测 | FR-V-002 |
| `peer_comparison` | 同业中位数与分位，披露有效样本数与缺失数 | FR-V-003 |
| `excess_return` | AR = R − Rb，MVP 只做简单基准调整 | 说明书 T15 |
| `run_event_backtest` | T+1 事件回测、成本/滑点、净值与风险指标 | 量化研究 MVP |
| `check_invalidation` | 连续突破阈值判定，按建立日裁剪观察窗口 | PRD 4.7 / FR-S-002 |
| `suggest_status` | 重大风险 > 出现分歧 > 维持当前 | PRD 5.2 |

## 两个容易写错的地方

**口径冲突要抛错，不要静默比较。** `_assert_comparable` 检查单位、报告期口径、指标版本三项一致，不一致抛 `CalibrationConflictError`。指标管道明确要求单季度/累计/年度/滚动不允许混算。静默比较会产出看起来合理但完全错误的结论，比报错危险得多。

**失效判定必须按逻辑建立日裁剪。** 样例数据里 2025Q2（11%）和 2025Q3（13%）连续两期低于 15% 预期，但两期都早于逻辑建立日 2026-01-15。不裁剪的话，导入样例数据的瞬间就会误判 H2 失效，给研究员发一条错误的重大风险提醒。`check_invalidation` 的 `excluded_periods` 与 `note` 字段就是为了让这个裁剪动作在界面上可见、可解释。

## 阈值参数化

阈值都在 `app.core.config.RuleThresholds`，不硬编码在函数里。PRD 5.2 对"重要支持与冲突同时存在""接近失效条件"的描述是散文，必须参数化才能实现和回归测试。

阈值变更记 `version`，历史结论不被新阈值覆盖。

## 测试要求

`tests/unit/calc/`。每个阈值类函数必须覆盖四种情形：

1. 明确达到阈值
2. 接近但未达到（`near_invalidation_ratio` 边界）
3. 明确未达到
4. 数据缺失

这不是形式要求。这些分支直接决定是否给研究员发重大风险提醒，误报会让人不再信任系统，漏报会造成实际损失。

另外必须有一个用样例包数据的回归测试，断言"导入样例数据后 H2 不被判失效"。这是上面那个坑的守门测试。
