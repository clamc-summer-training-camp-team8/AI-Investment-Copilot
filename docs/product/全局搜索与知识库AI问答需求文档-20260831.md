> 文档版本：v1.0
>
> 日期：2026-08-31
>
> 状态：待评审
>
> 适用基线：`main` / `800276c`（已合入 Phase 3 受治理量化环境）
>
> 目标页面：本地 `http://127.0.0.1:5173` 及共享集成环境

## 1. 需求摘要

当前产品顶部已有“搜索公司、行业、事件或输入投研问题”的静态输入框，但没有状态、请求、结果
展示和跳转逻辑。资产治理页已经提供权限感知的关键词/向量混合召回，后端也具备 Graph RAG、
文档原文定位、模型网关、Schema 校验和审计能力，但这些能力尚未形成面向研究员的统一入口。

本次开发交付两个相互协作、职责不同的功能：

1. **顶部全局搜索**：快速查找公司、行业、投资逻辑、事件和知识库资料，并跳转到已有业务页面
   或打开可追溯的原文片段；搜索输入过程不调用大模型。
2. **右下角知识库 AI 助手**：研究员用自然语言提问，系统仅基于当前用户有权访问的知识库内容
   生成带原文引用的候选回答；证据不足时明确说明不足，不用模型常识补造投资事实。

两个入口复用同一套权限优先检索底座，但不能混为一个接口：搜索强调稳定、快速、可导航；AI
问答强调问题理解、证据组织、引用校验和风险提示。

## 2. 当前基线与约束

| 能力 | 当前状态 | 对本需求的影响 |
| --- | --- | --- |
| 顶部搜索框 | `web/src/App.tsx` 中仅有静态 `<input>` | 需要补齐组件状态、请求、结果面板、键盘操作和跳转 |
| 资产混合检索 | 已有 `GET /api/assets/hybrid-search` | 可复用权限、证券、行业、时间过滤及关键词/向量排序 |
| Graph RAG | 已默认启用 Evidence Fusion | 仅在已解析、权限可见且有研究上下文时增强问答召回，不替代原文 |
| 原文回查 | 已有文档片段接口和 locator | 每个事实型回答必须能打开对应片段 |
| AI 网关 | 已有 local/http provider、版本化提示词和输出校验 | 新增“知识问答”任务，不在前端直接调用模型服务 |
| 身份权限 | 本地、可信网关、JWT 三种模式均有明确 Actor | 所有搜索和问答请求必须携带 Actor，并在排序前过滤 |
| 数据资产 | 3,792 份活动文档均已归档、授权已核验 | 可作为知识库资产范围 |
| 正文覆盖 | 3,784 份仍为“标题索引”，不是完整正文 | 标题可用于发现资料，不能单独支撑正文事实回答 |
| 前端响应式 | 宽度小于 1050px 时当前搜索框隐藏 | 本次必须增加移动端/窄屏搜索入口 |
| 运行环境 | 共享环境为 2 vCPU / 4 GiB 单机 Compose | 第一版控制候选数、上下文长度和并发，不引入常驻大模型服务 |

本需求不改变以下产品红线：AI 结果只是研究候选；模型不能自动确认关系、发布逻辑、修改状态、
生成交易指令或替代研究员决策。

## 3. 产品目标

### 3.1 目标

- 研究员可以从任意已登录页面在 3 次以内键盘/鼠标操作中找到目标公司、逻辑、事件或资料。
- 研究员可以在不离开当前研究页面的情况下，基于知识库提出问题并获得可回查引用的回答。
- 搜索和问答都遵守文档、逻辑、团队、证券和历史时点权限，不泄露对象是否存在。
- 每条事实型回答都能定位到当前用户可见的原文片段；不满足时返回“证据不足”。
- 搜索、检索、模型和用户反馈具备可观测性，但日志不保存问题、提示词或受限正文的明文。

### 3.2 非目标

本次第一版不包含：

- 互联网实时搜索、新闻聚合或外部网页问答；
- 对 3,784 份标题索引 PDF 进行本需求之外的全量正文解析；
- 跨用户共享会话、服务端长期聊天历史、收藏问答或知识库写回；
- 语音、图片、文件附件或多模态问答；
- AI 自动维护投资逻辑、确认候选证据、创建量化信号或执行交易；
- token 级流式输出；第一版使用有超时的单次回答接口，后续再评估 SSE；
- 无研究上下文的全库 Graph 遍历；第一版只在当前可见逻辑/证券上下文中启用 Graph RAG。

## 4. 目标用户与核心场景

### 4.1 目标用户

- **研究员**：查找覆盖对象、已有逻辑、事件和资料，快速形成初步理解。
- **研究负责人/复核人**：回查结论引用，判断 AI 回答是否可用于后续研究。
- **资产管理员**：验证不同权限账户的检索范围和内容状态，不通过问答修改资产。

### 4.2 核心场景

1. 输入“吉利”后，看到公司、对应投资逻辑、相关事件和资料，选择结果进入对应页面。
2. 输入“新能源汽车 毛利率”后，看到行业/公司对象及权限可见的知识片段，并可进一步“向 AI
   提问”。
3. 在某条投资逻辑页打开 AI 助手，询问“最近有哪些证据挑战了核心假设？”，系统默认带入当前
   逻辑和证券上下文，引用已确认关系及原始片段。
4. 对只有公告标题、没有解析正文的问题，系统展示标题型检索结果，但回答明确提示“当前只有标题
   索引，无法从正文验证”。
5. 模型服务不可用时，全局搜索继续工作；AI 助手显示可重试错误，不影响主页面操作。

## 5. 产品结构与交互原则

### 5.1 入口关系

- 顶部搜索框始终是**搜索入口**。输入问题不会在每次按键时触发模型。
- 搜索结果面板底部提供“向 AI 助手提问”操作，将完整输入带到右下角助手，但仍由用户显式发送。
- 右下角悬浮按钮是**问答入口**。助手打开后保留当前页面，桌面端以侧边浮层呈现，窄屏端以
  全屏抽屉呈现。
- 两个入口共享当前研究上下文，包括当前 `thesisId`、`securityId` 和可选历史时点；用户可在助手
  中移除上下文限制。

### 5.2 交互原则

- 搜索结果先展示确定性业务对象，再展示知识库片段，不把不可比较的对象分数混成单一排行榜。
- AI 回答中的“事实”“推断”“证据不足”必须视觉可区分。
- 引用是回答的一部分，不是折叠在调试面板中的附加信息。
- 任一错误只影响当前入口，不遮挡主页面或清空用户尚未发送的问题。
- 符合现有“AI 候选、人工闸门、可审计、可追溯”的产品视觉和文案规范。

## 6. 功能需求

### 6.1 顶部全局搜索

#### FR-S-001 打开与关闭

- 点击搜索框、按 `/` 或 `Ctrl/Cmd + K` 打开搜索面板；用户正在输入表单时 `/` 不抢占焦点。
- `Esc` 关闭面板；再次按 `Esc` 清空输入；点击面板外关闭。
- 面板关闭后再次打开，当前页面生命周期内保留最近一次输入。
- 未登录页面不展示搜索入口。

#### FR-S-002 查询触发

- 去除首尾空格，输入 2 个字符后等待 250ms 发起防抖请求；证券代码等精确查询允许 1 个字符
  通过回车发起。
- 回车立即执行当前查询；前一请求未完成时取消或忽略其过期响应。
- 相同查询短时间内使用 React Query 缓存，切换页面不重复请求。
- 搜索输入和建议阶段不调用 AI 模型，不产生模型费用。

#### FR-S-003 检索范围

第一版必须返回以下分组：

| 分组 | 匹配字段 | 权限要求 |
| --- | --- | --- |
| 公司/证券 | 名称、代码、ticker、别名、行业 | 已认证用户可见的证券主数据 |
| 行业 | 行业名称及行业下匹配公司 | 只聚合当前用户可见的证券/资料范围 |
| 投资逻辑 | 标题、核心观点、证券名称/代码 | 复用逻辑私有/团队/授权范围校验 |
| 事件 | 事件摘要、类型、关联公司 | 必须至少关联当前用户可见资料或可见证据 |
| 知识资料 | 文档标题、可检索片段 | 在关键词/向量排序前应用文档权限、证券、行业和时间过滤 |

证券检索需要补齐当前实现尚未覆盖的 `aliases` 和 `industry` 匹配。事件检索需要新增仓储查询，
不能把全量事件取回后在 API 层做权限过滤。

#### FR-S-004 排序与展示

- 各组内部优先级为：代码/名称精确匹配、前缀匹配、文本相关性、向量相关性、时间新鲜度。
- 默认每组最多 5 条，总计最多 20 条，提供“查看全部资料”进入数据中心并带入查询参数。
- 结果必须显示类型、标题、上下文副标题；知识片段还要显示来源标题、披露时间、内容状态和
  “关键词/混合/图文”检索模式。
- “标题索引”结果明确显示“公告标题（非正文）”，不得使用与完整正文相同的样式。
- 不向前端返回不可见结果数量，也不通过空分组暗示某个受限对象存在。

#### FR-S-005 结果跳转

- 公司/证券：有可见逻辑时进入该逻辑页；无逻辑时进入覆盖管理页并定位公司。
- 行业：进入覆盖管理页并应用行业筛选。
- 投资逻辑：进入 `/theses/{thesisId}`。
- 事件：有关联的可见证据时进入证据详情；否则打开其可见来源片段。
- 知识资料：打开原文片段抽屉；不得直接拼接未经校验的外部 URL。
- 所有目标在跳转时再次由后端执行对象权限检查，搜索结果本身不构成访问授权。

#### FR-S-006 状态与异常

- 初始态显示最近搜索（仅当前标签页）和示例问题，不展示伪造业务结果。
- 加载态使用骨架或进度提示；无结果区分“没有匹配结果”和“输入更具体的公司/指标/事件”。
- API 超时或失败时保留输入，显示“重新搜索”；AI 服务失败不影响搜索接口。
- 用户退出登录时清除最近搜索和前端缓存。

#### FR-S-007 键盘与窄屏

- 支持上下方向键选择、回车打开、`Tab` 正常遍历，当前项有可见焦点样式和可读的 ARIA 状态。
- 宽度小于 1050px 时不能继续隐藏全部搜索能力；顶部改为搜索图标，点击后打开全屏搜索层。
- 不依赖 hover 才能显示关键内容，遵守 `prefers-reduced-motion`。

### 6.2 右下角知识库 AI 助手

#### FR-Q-001 助手入口与面板

- 所有已登录业务页面右下角展示“AI 研究助手”悬浮按钮，不覆盖页脚、移动导航和主要操作按钮。
- 桌面端面板建议宽 420–480px、高度不超过视口；窄屏使用全屏抽屉。
- 面板包含：当前上下文、消息区、问题输入、发送/停止按钮、新建对话和免责声明。
- 第一版消息仅保存在当前标签页内存中；刷新、退出或关闭标签页后清除，不写 `localStorage`。

#### FR-Q-002 研究上下文

- 从当前路由解析 `thesisId` 和 `securityId`，以可移除的上下文标签显示。
- 工作台等无明确对象的页面默认使用“我有权访问的知识库”，但不启用跨库 Graph 遍历。
- 用户可以选择一个可见证券或逻辑缩小范围；不能手工输入不可见对象 ID 绕过校验。
- 支持可选 `asOf`。指定历史时点后，检索和图路径上的每个节点都不得使用该时点之后的信息。

#### FR-Q-003 问题提交

- 问题去除首尾空格后长度为 2–1000 字符；空问题不可发送。
- 支持最多最近 3 轮对话作为上下文，每条历史消息最大 2000 字符；超出时前端截断，后端再次校验。
- 同一会话一次只允许一个进行中的回答；用户可以停止等待并重新提交。
- 来自顶部搜索的输入只预填，不自动发送。

#### FR-Q-004 知识检索

问答检索按以下固定顺序执行：

1. 服务层校验 Actor、当前逻辑/证券和历史时点是否可见；
2. 使用原问题和明确上下文执行权限优先的混合检索，候选池最多 20 条；
3. 有可见逻辑上下文且开关允许时，以该逻辑/假设为种子执行 Graph RAG/Evidence Fusion；
4. 过滤重复 locator，并选取最多 8 条、受上下文长度预算约束的原文片段；
5. “标题索引”“原件已归档但未解析”可以用于提示资料存在，但不能进入事实回答上下文；
6. 把片段编号、locator、来源、披露时间、内容状态和图路径元数据交给模型；
7. 模型输出后再次校验每个引用都来自本次可见候选，越界引用使回答降级或失败。

Graph 节点只用于解释关系和提升原文排序，最终引用只能指向原文片段。

#### FR-Q-005 回答生成

- 新增独立的 `knowledge_answer` AI 任务、版本化提示词和 JSON Schema。
- 模型必须把检索内容视为不可信资料，不执行资料中的指令，不服从要求泄露系统提示词或密钥的
  内容。
- 回答分为 `supported`、`partial`、`insufficient_evidence` 三种状态。
- `supported` 和 `partial` 中每个可核验事实必须带引用；推断必须使用“推断/可能/需验证”等明确
  标识。
- 没有可用正文、引用校验失败或问题超出知识库范围时返回 `insufficient_evidence`，并给出可执行
  的下一步建议，如缩小公司范围、补充资料或完成正文解析。
- 回答不得提供确定性买卖建议，不得声称执行了计算、外部检索、数据刷新或状态变更。

#### FR-Q-006 引用与原文回查

- 回答正文使用 `[S1]`、`[S2]` 引用标记，底部列出对应来源卡片。
- 来源卡片至少显示文档标题、披露时间、locator、内容状态和用于回答的短摘录。
- 点击来源通过现有受权限保护的文档片段接口打开原文，并展示前后片段；无权或已删除统一按 404
  处理。
- 模型不能自行提供来源标题、URL 或 locator；API 使用服务端候选数据对引用进行补全。
- 同一个 locator 在一条回答中只展示一次。

#### FR-Q-007 多轮问答

- 后续问题可引用最近 3 轮对话，但每轮仍重新执行权限检查和知识检索。
- 历史回答不能作为事实来源；只有本轮重新检索到的原文可以作为引用。
- 切换证券/逻辑上下文时提示用户开始新对话；确认切换后清空历史，避免上下文串线。

#### FR-Q-008 异常与降级

| 情形 | 行为 |
| --- | --- |
| 没有正文命中 | 返回证据不足，不调用或最小化调用模型 |
| 只有标题索引 | 展示命中标题及“非正文”说明，不生成事实结论 |
| 模型未配置/不可用 | 返回可重试错误，保留问题和检索入口 |
| 模型超时 | 30 秒终止，显示重试；不自动无限重试 |
| 输出不符合 Schema | 允许网关执行一次有限修复；仍失败则标记“解析失败” |
| 引用越界/丢失 | 不返回未经验证的正文，降级为证据不足或解析失败 |
| 权限或时点不合法 | 不泄露对象存在性，返回统一不可用结果 |
| 用户取消 | 中止前端请求，不把取消显示成系统错误 |

#### FR-Q-009 用户操作

- 支持复制回答、点击引用、对回答标记“有帮助/无帮助”。
- 反馈只记录回答请求 ID、反馈值和可选原因枚举；第一版不保存问题或回答明文。
- 不提供“采纳并写入逻辑”“自动确认”快捷按钮，避免绕过人工闸门。

## 7. 建议接口契约

接口仍按 ADR-0004 先写入 `contracts/api/openapi.yaml`，实现与前端分别对契约开发。

### 7.1 全局搜索

```http
GET /api/search?q=吉利毛利率&types=security,industry,thesis,event,document&limit_per_type=5
```

建议响应：

```json
{
  "query": "吉利毛利率",
  "groups": [
    {
      "type": "security",
      "items": [
        {
          "id": "0175.HK",
          "title": "吉利汽车",
          "subtitle": "新能源汽车 · 0175.HK",
          "match_kind": "name",
          "target": {"kind": "thesis", "id": "THS-..."}
        }
      ]
    },
    {
      "type": "document",
      "items": [
        {
          "id": "DOC-...#paragraph-12",
          "title": "2026 年中期业绩公告",
          "subtitle": "完整正文 · 2026-08-20",
          "excerpt": "……毛利率……",
          "content_status": "完整正文",
          "retrieval_mode": "hybrid",
          "target": {"kind": "document_segment", "id": "DOC-...#paragraph-12"}
        }
      ]
    }
  ],
  "request_id": "SEARCH-..."
}
```

约束：`q` 1–200 字符；`types` 只能取固定枚举；`limit_per_type` 1–10；接口列表 P95 不超过 2 秒。

### 7.2 知识库回答

```http
POST /api/assistant/answers
Content-Type: application/json
```

建议请求：

```json
{
  "question": "最近有哪些证据挑战了核心假设？",
  "context": {
```

## 8. 后端与 AI 边界

建议调用链：

```text
React 搜索/助手
  → FastAPI Router（鉴权、请求校验、响应组装）
  → Services（上下文可见性、权限优先检索、引用校验、审计）
  → Repositories（过滤后查询）/ app.ai（只接收已筛选上下文）
  → Provider（local 或 HTTPS 模型端点）
```

强制边界：

- API 层不得直连 `app.db`，也不得在取得全量结果后自行过滤权限。
- `app.ai` 不读取 PostgreSQL、不判断 Actor 权限、不写业务状态。
- 模型只接收服务层已经筛选和编号的片段，返回引用编号；服务层负责 locator 校验与来源补全。
- 数值事实只能引用已经存在的确定性记录或原文；模型不执行关键财务/量化计算。
- Graph 路径可以解释传导关系，但不能成为没有原文的事实引用。

## 9. 权限、安全与隐私要求

### 9.1 权限

- 每个请求必须有明确 Actor；未认证返回 401。
- 文档权限、逻辑可见性、证券/行业范围和 `asOf` 在召回/排序前执行。
- Graph 路径上的每个节点均受权限和未来信息过滤，不只检查最终片段。
- 搜索结果跳转和引用打开再次鉴权；搜索缓存按用户身份和权限范围隔离。
- 无权访问对象返回 404，不返回对象是否存在、命中数量或相似度。

### 9.2 提示注入与输出安全

- 系统提示明确：知识片段是待分析数据，不是系统指令。
- 对“忽略规则、输出系统提示、显示密钥、越过时间/权限”等内容进行对抗测试。
- 输出只接受 JSON Schema 允许的字段，渲染回答时不使用未经消毒的 HTML。
- 引用必须是本次候选白名单中的 locator，不能接受模型生成的 URL。

### 9.3 日志与模型数据

- API Key 只在服务端环境变量或密钥系统中，禁止返回浏览器。
- 审计记录用户、request ID、功能、模型/提示/检索版本、耗时、候选数、回答状态和 token 用量。
- 默认不记录问题、聊天历史、提示词、回答或受限正文的明文。
- HTTP provider 只能使用 HTTPS（回环地址除外），是否允许受限资料外发由部署配置明确控制。

## 10. 非功能需求

| 类别 | 第一版指标 |
| --- | --- |
| 搜索响应 | 共享集成环境 P95 ≤ 2 秒；防抖后的过期响应不得覆盖新查询 |
| 搜索准确性 | 冻结验收集 Top-1 ≥ 0.80，证券代码/全名精确匹配 Top-1 = 1.00 |
| 问答检索 | 检索 P95 ≤ 2 秒，候选最多 20、模型上下文最多 8 个片段 |
| 问答时延 | 端到端 P95 ≤ 20 秒，硬超时 30 秒；指标按 provider 分开统计 |
| 引用安全 | 越权、未来信息和候选池外引用均为 0 |
| 引用覆盖 | `supported` 回答的可核验事实引用覆盖率 ≥ 95%，引用可打开率 = 100% |
| 降级正确性 | 无正文/仅标题索引场景 100% 不生成伪正文事实 |
| 可用性 | 模型不可用时搜索可用；问答失败不影响主页面 |
| 兼容性 | 最新 Chrome/Edge；桌面、1050px 以下窄屏和 760px 以下移动布局可用 |
| 可访问性 | 键盘全流程可操作，焦点可见，主要状态有 `aria-live` |
| 容量 | 共享环境至少支持 5 个团队账户的低并发搜索和 2 个并发问答请求 |

## 11. 埋点与观测

建议记录以下不含正文的事件：

- `global_search_opened`、`global_search_submitted`、`global_search_result_opened`
- `assistant_opened`、`assistant_question_submitted`、`assistant_answer_completed`
- `assistant_answer_failed`、`assistant_citation_opened`、`assistant_feedback_submitted`

公共字段包括：Actor、request ID、时间、页面路由、上下文对象 ID、结果类型、结果位置、耗时、
候选数量、检索模式、模型/提示/图快照版本、回答状态、错误码和反馈值。问题和回答只记录长度或
不可逆摘要，不记录明文。

上线看板至少展示：

- 搜索成功率、无结果率、结果点击率、P50/P95 时延；
- 问答完成率、证据不足率、超时率、引用打开率、有帮助率；
- 每个 provider 的模型时延与 token 用量；
- 权限、未来信息和引用校验失败次数。

## 12. 验收标准

### 12.1 全局搜索

- [ ] 从任意已登录页面可点击或使用快捷键打开搜索。
- [ ] 公司代码、名称、别名、行业、逻辑、事件和资料均有真实后端结果，不使用静态 Mock 冒充。
- [ ] 输入新查询后，旧请求结果不会覆盖新结果。
- [ ] 每类结果可进入正确页面或打开受权限保护的原文片段。
- [ ] 标题索引和完整正文视觉及文案不同。
- [ ] 无权限账户无法通过结果、数量、跳转或缓存获知受限对象。
- [ ] 1050px 以下仍有可用搜索入口，键盘操作和焦点顺序通过检查。

### 12.2 AI 问答

- [ ] 右下角入口在主要路由可用，不遮挡关键操作。
- [ ] 当前逻辑/证券上下文可见、可移除，切换上下文会阻止历史串线。
- [ ] 每轮重新检索，并只把当前用户可见片段传给 AI。
- [ ] 每个事实引用都能打开对应原文；模型生成的候选池外引用被拦截。
- [ ] 只有标题索引、无命中、模型失败、超时、Schema 失败均有明确降级状态。
- [ ] 回答不自动修改逻辑、证据、信号或业务状态。
- [ ] 退出登录或关闭标签页后会话被清除，服务端日志没有问题/回答明文。

### 12.3 工程门禁

- [ ] OpenAPI 与 `knowledge_answer` JSON Schema 先于实现落库并有契约测试。
- [ ] Python 全量测试、Ruff、format、mypy、Import Linter、OpenAPI 校验全部通过。
- [ ] PostgreSQL + pgvector 集成测试覆盖权限、时点、标题索引和引用白名单。
- [ ] 前端 ESLint、TypeScript、生产构建和新增交互测试通过。
- [ ] 共享集成环境用至少三个不同权限账户完成联合验收。
- [ ] 功能开关关闭后可独立回退问答，搜索和既有业务链路不受影响。

## 13. 发布决策

第一版按以下顺序启用：

1. 本地环境打开全局搜索和 local provider 问答；
2. 共享环境打开全局搜索，问答先对指定测试账户开放；
3. 完成权限/未来信息对抗测试和引用抽样后，扩大到三个团队账户；
4. 连续观察 3 个工作日，无泄漏、引用错误和严重超时后再默认开放；
5. 任一权限泄漏、未来信息泄漏或不可回查引用，立即关闭问答功能开关，保留确定性搜索。

## 14. 已确定的第一版取舍

| 问题 | 第一版决策 |
| --- | --- |
| 顶部输入是否自动调用 AI | 否；只搜索，用户显式选择“向 AI 提问” |
| 搜索和问答是否共用接口 | 否；共用检索底座，保留不同延迟与错误边界 |
| 是否全库 Graph 问答 | 否；仅在可见逻辑/证券上下文启用 Graph RAG |
| 标题索引能否支撑回答 | 否；只能用于资料发现和“需解析”提示 |
| 是否保存聊天历史 | 否；第一版仅当前标签页内存，后续另立治理需求 |
| 是否流式输出 | 否；第一版单次响应并设置 30 秒硬超时 |
| AI 是否能写回业务 | 否；仅回答候选和引用，不提供采纳写回入口 |
| 模型失败是否影响搜索 | 否；两者独立降级 |
