# 模型与因子（量化研究）功能模块需求文档

> 文档日期：2026-09-01  
> 文档状态：P0、P0.1 与 P1.1 已实施；P1 其余能力继续受数据准入门禁  
> 开发基线：`feature/knowledge-answer-intent-routing`（当前 HEAD `370a89e`）  
> 集成基线：`phase3-all-features-integrated-20260901`（`9349e89`）  
> 产品边界：研究验证与模拟组合，不连接券商，不生成订单、评级或调仓指令

## 1. 需求结论

本轮不从零建设量化引擎，而是把仓库中已经存在的冻结行情、人工确认信号、组合回测和历史运行能力，产品化为前端正式模块“模型与因子”。

P0 的重点是：

1. 统一产品命名和入口，让顶部“模型与因子”正确进入 `/quant`，不再错误跳转到投资逻辑 `/theses`；
2. 沿用已完成的工作台视觉语言、页面壳层、全局搜索和跨模块跳转，不改造工作台主体；
3. 将当前单页参数表单升级为“概览—研究信号—新建验证—运行详情—历史运行”的完整研究流程；
4. 正确接入已登记的量化 V3 数据，明确它是候选版本而非当前默认版本；
5. 把数据能力、人工确认、时点约束和三轨评测隔离变成用户可见的运行门禁；
6. 用真实 API 和真实冻结资产展示结果，真实模式不得用静态样例冒充成功结果。

P0 中“因子”指进入量化验证的受治理研究信号，以及回测结果中的市场、市值、行业等风险暴露；不在本轮建立通用因子表达式、在线训练、自由回测代码或自动选股平台。通用因子库和模型模板管理进入 P1。

## 2. 背景与现状

### 2.1 分支与集成背景

Phase 3 已合并认证、搜索与知识问答、数据中心、复盘中心、公司覆盖、指标中心、自动采集、研究动态和量化资产治理。当前功能分支在该集成基线上增加了知识问答意图路由和结构化引用，工作区在需求调研开始时无未提交修改。

工作台已经具备主要 UI 设计、内容布局和交互跳转，本模块应复用其产品壳层，不再建立另一套导航、色彩、卡片和交互语言。

### 2.2 当前前端状态

| 项目 | 当前实现 | 问题 |
| --- | --- | --- |
| 顶部导航 | 显示“模型与因子”，链接到 `/theses` | 与“投资逻辑”概念混用，无法进入量化页 |
| 左侧主导航 | 显示“量化实验”，链接到 `/quant` | 与顶部命名不一致 |
| 工作台左侧研究功能 | “投资逻辑”正确链接 `/theses` | 应继续保留，不改名为模型与因子 |
| 量化页面 | `QuantPage` 位于大型 `web/src/pages.tsx` | 单页过长，缺少模块化路由和独立测试边界 |
| 量化交互 | 数据集、信号集、证券代码、窗口和成本参数可配置 | 证券使用逗号文本输入，门禁和错误解释不充分 |
| 结果 | 指标、walk-forward、风险归因、诊断、历史运行已展示 | 缺少净值可视化、稳定详情 URL、来源追溯和运行状态层次 |
| 数据中心联动 | 数据集详情可跳转 `/quant?marketDatasetId=...` | 应继续兼容，并在量化页保留返回数据资产的深链 |

### 2.3 当前后端能力

已有正式 API：

- `GET /api/quant/catalog`
- `GET /api/quant/market-datasets/{dataset_id}`
- `POST /api/quant/market-datasets/register-default`
- `POST /api/quant/signal-sets`
- `POST /api/quant/portfolio-backtests`
- `GET /api/quant/portfolio-backtests`
- `GET /api/quant/portfolio-backtests/{run_id}`

已有持久化对象：

- `quant_market_dataset`：不可变行情数据集；
- `quant_signal_set`：只接受人工确认、`alpha_validation` 轨的不可变信号集；
- `quant_backtest_run`：绑定数据集、信号集、方法版本、参数与结果的不可变运行。

历史运行已按 `requested_by` 隔离，详情接口对非本人运行返回 404。量化计算位于确定性计算层，AI 不参与收益、风险、IC 或归因数值计算。

## 3. 产品目标与成功标准

### 3.1 产品目标

- 让研究员从工作台或数据中心进入模型与因子模块后，能看懂“用什么数据、什么信号、什么方法、得出什么结果、有哪些限制”；
- 让一次组合验证可以被刷新、复制链接和再次打开，参数、版本和结果不丢失；
- 让数据不足、权限不足和时点不匹配在运行前或运行时明确失败，而不是生成看似完整的结果；
- 让研究信号与人工确认的证据、关系保持可追溯，不把 AI 候选直接当作因子；
- 让模型与因子模块在视觉和交互上成为现有工作台的一部分，而不是独立工具页面。

### 3.2 P0 成功标准

1. 顶部和侧栏均以“模型与因子”命名并进入 `/quant`，`/theses` 继续只表示“投资逻辑”；
2. V3 在目录中显示为“已登记候选/非默认”，不会被前端按时间误判为默认；
3. 用户能完成数据集选择、信号集选择、证券选择、参数校验、运行、结果查看和历史恢复闭环；
4. 运行详情具备稳定 URL，刷新或复制链接后恢复同一 `QPF-*` 运行；
5. 市值中性、混币种、信号时点、证券覆盖和数据能力缺口有明确状态与错误说明；
6. 结果页展示数据集 ID、信号集 ID、方法版本、参数和诊断，任何收益数字旁均保留研究验证声明；
7. 真实模式无静态量化结果兜底；接口失败显示可重试错误，不显示 Mock 成功态；
8. 新增前端测试、后端契约测试、生产构建、响应式与键盘验收全部通过；
9. 关闭模块功能开关后不显示入口，直接访问返回产品内 404，且不影响工作台、投资逻辑和数据中心；
10. 前端量化模块采用路由级动态加载，不继续放大集成记录中已出现的主 chunk 体积告警。

## 4. 用户与核心场景

### 4.1 目标用户

| 用户 | 核心诉求 | P0 权限 |
| --- | --- | --- |
| 研究员 | 用人工确认信号执行受控历史验证并复看本人运行 | 查看数据集/信号集，创建和查看本人运行 |
| 研究负责人 | 检查版本、方法、限制和结果是否可复算 | 查看目录和受权限约束的运行；团队共享能力另行评审 |
| 数据/量化研发 | 核对能力矩阵、诊断和版本哈希 | 通过数据中心查看资产；正式发布仍走受控命令 |
| 只读团队成员 | 理解已授权范围内的冻结资产与研究结果 | P0 不新增跨用户运行读取权限 |

### 4.2 核心用户故事

- 作为研究员，我从工作台点击“模型与因子”，能够直接看到当前可用数据、信号和最近运行；
- 作为研究员，我选择 V3 时能够立刻知道它不是当前默认版本，以及它能做和不能做什么；
- 作为研究员，我只能从数据集与信号集共同覆盖的证券中选择验证对象；
- 作为研究员，我启用市值中性时，系统会解释为什么纯 A 股可用、包含港股时不可用；
- 作为研究员，我能够在详情页查看净值、样本外窗口、IC、风险归因和被跳过信号；
- 作为研究负责人，我能够用运行编号、数据集哈希、信号集哈希、参数和方法版本复核结论；
- 作为数据研发，我能从量化页跳回数据中心查看数据资产和授权限制。

## 5. 术语与业务边界

| 术语 | 本产品定义 |
| --- | --- |
| 投资逻辑 | 公司级观点、假设、指标和证据对象，路由为 `/theses` |
| 研究信号 | 从已人工确认 Evidence/Relation 冻结出的点时方向信号 |
| 因子 | P0 指研究信号及结果中的市场、市值、行业等暴露；不等于任意用户公式 |
| 模型 | P0 指确定性组合研究方法及其参数版本，如 `portfolio-research-v2`；不指大语言模型 |
| 行情数据集 | 受授权策略、Manifest 和子资产 SHA-256 约束的不可变版本 |
| 运行 | 数据集、信号集、方法与参数唯一绑定的 `QPF-*` 结果快照 |
| Alpha 验证 | 独立评测轨；不能替代语义准确率、检索质量或人工确认 |

模型与因子模块只回答“冻结信号在冻结历史数据和明确假设下表现如何”。它不回答“现在应该买什么”，不生成实盘仓位，不进行自动调仓，也不把回测结果写回投资逻辑状态。

## 6. 信息架构与路由

继续使用 `/quant` 作为正式模块路径，避免破坏数据中心现有深链。P0 路由如下：

```text
/quant                         模型与因子概览
/quant/signals                 研究信号集列表
/quant/signals/:signalSetId    信号集详情与来源追溯
/quant/new                     新建组合验证
/quant/runs                    本人历史运行
/quant/runs/:runId             运行详情
```

兼容要求：

- `/quant?marketDatasetId=...` 继续生效，并转入新建验证页或在概览保留所选数据集上下文；
- 数据中心“使用此版本进入量化实验”文案改为“使用此版本新建验证”；
- `/theses` 和 `/theses/:thesisId` 不改路由、不改为模型页；
- 旧书签 `/quant` 不重定向到新命名路径；
- 所有子路由共享现有产品顶部栏、侧栏、全局搜索、页脚声明和登录状态。

## 7. P0 功能需求

### FR-01 统一命名、入口与高亮

- 顶部导航“模型与因子”链接 `/quant`；
- 左侧主导航“量化实验”改为“模型与因子”，链接 `/quant`；
- `/quant/**` 下顶部和左侧入口均保持激活；
- 工作台覆盖面板中的“投资逻辑”仍指向 `/theses`；
- 模块入口受 `quant_research_enabled` 独立功能开关控制。

验收：从工作台进入后落在模型与因子概览；浏览 `/theses` 时仅“投资逻辑”语义生效；关闭开关后入口和路由均不可见。

### FR-02 模块概览

概览展示四类状态：

1. 当前显式默认数据集；
2. 已登记候选数据集数量及 V3 状态；
3. 可用人工确认信号集及真实信号数量；
4. 当前用户最近运行、成功结果和数据能力告警。

概览的主要动作：

- “新建组合验证”；
- “查看研究信号”；
- “查看历史运行”；
- “前往数据中心查看冻结资产”。

没有数据集时不得向普通研究员显示“登记默认冻结行情”按钮。正式登记和默认切换仍是运维/治理动作；页面只展示缺口、受控发布说明和数据中心入口。

### FR-03 数据集选择与能力说明

- 数据集选择器必须使用后端 `default_market_dataset_id` 标记默认版本，不能用最新时间推断；
- V3 显示“已登记候选”“非默认”“冻结”“清单完整”等独立状态；
- 展示覆盖日期、证券数、复权口径、授权状态和 Manifest 短哈希；
- 能力矩阵用用户可理解的中文展示，原始 capability key 可在详情中保留；
- 限制按“阻断运行”“允许运行但限制解释”“信息提示”分级；
- 数据集卡和运行详情均可深链到 `/assets/market-datasets/{datasetId}`；
- 数据集不可在前端编辑、删除或覆盖。

### FR-04 研究信号集列表与详情

列表至少展示：名称、版本、信号数、冻结状态、人工确认标识、评测轨、冻结时间和内容哈希。

详情至少展示：

- `signal_id`、证券、方向、强度、置信度；
- 披露时间、人工确认后生成时间；
- `source_evidence_id`、`source_relation_id`；
- 信号是否落在所选数据集覆盖区间内；
- 跳转证据/影响详情的受权限保护链接；
- “使用该信号集新建验证”动作。

P0 不提供在量化页手工编辑或删除信号。信号冻结入口仍遵守 Evidence/Relation 人工确认链，候选、驳回或解除关系不得进入信号集。

### FR-05 新建组合验证

表单字段分组如下：

| 分组 | 字段 |
| --- | --- |
| 基础信息 | 运行名称、行情数据集、信号集、开始日期、结束日期 |
| 研究对象 | 基于数据集和信号集交集的证券多选，不使用逗号文本作为主交互 |
| 样本外验证 | 滚动窗口、测试窗口、再平衡周期 |
| 交易假设 | 初始资金、成本 bps、滑点 bps、容量参与率、容量约束 |
| 组合约束 | 个股上限、行业上限、行业中性、市值中性、做空开关 |

默认值与当前后端 `PortfolioConfigIn` 一致。高级参数可折叠，但折叠前后值必须保持。

运行前校验：

- 数据集、信号集和至少一只证券必填；
- 开始日期不得晚于结束日期，且必须落在数据集覆盖范围内；
- 证券必须同时存在于数据集和信号集；
- 信号生成时间不得晚于可用于验证的行情截止时点；
- 市值中性需要能力声明和所选区间逐行完整；纯 A 股可用，A/H 混合禁用并解释原因；
- 当前真实两证券信号不满足至少三证券的有效横截面时，市值中性应禁用或由后端 422 明确阻断；
- 混币种组合显示高可见警告，FX 未冻结时不得标记为 Alpha 结论；
- 涨跌停能力关闭时明确说明成交模拟限制；
- 后端 404、422 和网络错误映射到具体区域，用户修正参数后可重试。

### FR-06 运行提交与幂等

- 运行中禁用重复提交并显示明确进度；
- 相同数据集 Manifest、信号内容、方法版本和参数产生相同 `QPF-*`，前端应说明复用的是不可变运行；
- 成功后跳转 `/quant/runs/{runId}`；
- 失败不得在历史列表生成伪运行；
- 离开页面再返回时，尚未提交的参数可在当前会话恢复，但不得跨账号共享；
- 退出登录时清除量化 React Query 缓存和会话草稿。

### FR-07 运行结果与解释

运行详情分为六个区域：

1. **摘要**：组合收益、基准收益、超额收益、最大回撤、跟踪误差、信息比率、Beta；
2. **净值路径**：组合与基准曲线，支持时间悬停；图表只渲染后端结果，不在 AI 或浏览器重新定义业务口径；
3. **Walk-forward**：训练区间、测试区间、样本数、组合/基准/超额收益；
4. **信号研究**：观测数、IC、Rank IC、分层收益；无数据时显示原因，不显示 0 冒充有效结果；
5. **风险归因**：证券、行业和因子暴露；保留 `market_beta`、`size_exposure`、`net_exposure` 等方法字段的中文解释；
6. **诊断与复现**：接收/输入信号数、跳过信号、被阻断交易、警告、完整参数、数据集/信号集/方法版本与生成时间。

详情顶部固定展示“研究验证，不构成投资建议；不生成订单或调仓指令”。收益颜色不使用“买入/卖出”文案，不给出策略评级。

### FR-08 历史运行

- 默认只展示当前用户最近 50 次运行，与后端现有所有者隔离一致；
- 支持按运行名称、运行 ID、数据版本、信号集和生成时间在当前结果内筛选；
- 行点击使用可访问链接进入稳定详情路由，不使用只有鼠标 `onClick` 的表格行；
- 显示运行编号、名称、数据集、信号集、方法版本、生成时间、评测轨和关键诊断状态；
- 列表刷新不改变当前筛选和滚动上下文；
- 非本人运行保持 404，不通过错误文案泄漏对象存在。

### FR-09 跨模块联动

- 工作台顶部“模型与因子”进入 `/quant`；
- 数据中心数据集详情进入 `/quant/new?marketDatasetId=...`；
- 量化页数据集进入对应数据中心详情；
- 信号详情可进入有权限的证据、逻辑变化或投资逻辑页面；
- 运行结果不自动修改投资逻辑、复盘、证据关系或状态建议；
- 全局搜索和知识问答 P0 不索引运行收益，避免把个人研究结果当作正式团队结论。

### FR-10 页面状态与响应式

每个页面必须有 Loading、Empty、Error、Ready 四态；新建验证另有 Validating、Running、Success 状态。

- 1280px 及以上：复用工作台内容宽度和卡片网格；
- 1050px：参数表单两列，结果卡片不横向溢出；
- 760px：单列内容，标签页可横向滚动；
- 390px：关键数字、选择器、表格替代卡片和诊断信息可完整读取；
- 支持键盘遍历、可见焦点、表单 label、错误 `role=alert`、运行状态 `role=status`；
- 图表必须提供文本摘要或表格替代，不用颜色作为唯一信息载体。

## 9. API 与数据契约改动

### 9.1 P0 复用接口

| 页面能力 | 复用接口 |
| --- | --- |
| 概览/数据集/信号集摘要 | `GET /api/quant/catalog` |
| 数据集能力和资产深链 | `GET /api/quant/market-datasets/{dataset_id}` |
| 创建组合验证 | `POST /api/quant/portfolio-backtests` |
| 本人历史 | `GET /api/quant/portfolio-backtests` |
| 运行详情 | `GET /api/quant/portfolio-backtests/{run_id}` |
| 因子发布目录 | `GET /api/quant/factors` |
| 模型模板发布目录 | `GET /api/quant/model-templates` |

### 9.2 P0 建议新增

1. `GET /api/quant/signal-sets/{signal_set_id}`：返回信号集元数据和受权限裁剪的信号明细；
2. 认证配置增加 `quant_research_enabled`，前后端共同控制模块入口和路由；
3. 如运行列表在真实环境超过 50 条，再增加 `limit/cursor`，P0 可先沿用最近 50 条；
4. OpenAPI 重新导出并生成前端类型，不手工拼接与生成契约冲突的重复类型。

`POST /api/quant/market-datasets/register-default` 不作为普通前端流程使用。若保留该 API，应增加明确的治理权限，避免任一登录用户触发登记动作。

### 9.3 契约原则

- 金额、收益、IC 和风险值继续保持后端确定性计算；
- 前端只做格式化和可视化，不更改方法含义；
- 数据集、信号集和运行均不可变；
- 日期统一按 `Asia/Shanghai` 业务时区解释；
- 后端错误返回稳定错误语义，前端不得通过字符串猜测业务状态；
- 信号详情中的 Evidence/Relation 在返回前重新鉴权，不直接暴露无权对象 ID。

## 10. 设计与交互规范

本模块以当前工作台为设计基线：

- 复用全局顶部栏、左侧导航、工作区、底部声明、字体、颜色变量、按钮、状态徽标和卡片边界；
- 复用数据中心的数据集状态和能力矩阵表达，避免同一数据集在两处出现不同状态；
- 页面内增加轻量二级标签，不增加第二套永久侧栏；
- 核心操作使用工作台现有主按钮样式，次要跳转使用文本链接；
- 大段原始限制默认按严重级别折叠，阻断项始终展开；
- 证券选择器展示公司名、证券代码、市场和行业，不要求用户记住代码；
- 参数旁提供简短口径说明，高级参数默认折叠；
- 正负收益可使用颜色，但必须同时显示正负号和文字；
- 图表建议使用轻量、可按路由拆包的库；若引入第三方库，需评估许可证和 bundle 体积。

## 11. 权限、安全与治理

- 所有量化接口需要登录；
- 行情和信号集目录按团队已授权范围展示；
- 历史运行默认只对创建人可见；
- 前端缓存 key 必须包含登录身份或在账号切换时完整清理；
- 不在浏览器日志、埋点或错误上报中记录完整信号内容、原文片段、Token 或本地资产路径；
- 正式数据登记、默认切换和候选发布继续使用审批哈希与受控命令；
- AI 不参与数值计算，不自动生成待运行信号，不根据收益回写证据方向；
- 页面固定展示来源授权和研究用途限制；
- 不提供删除冻结数据集、冻结信号集或历史运行的前端动作。

## 13. 验收场景

### 13.1 正向场景

1. 从工作台顶部进入模型与因子概览；
2. 看到旧版为显式默认，V3 为已登记候选/非默认；
3. 从数据中心选择 V3，进入新建验证且数据集已预选；
4. 选择真实两信号集、关闭市值中性，成功得到并恢复 V3 历史运行；
5. 打开运行详情，核对指标、walk-forward、归因、诊断、方法和版本；
6. 刷新、复制详情链接后仍打开同一运行；
7. 从结果返回数据集详情，从信号进入有权限的证据来源。

### 13.2 阻断与降级场景

1. V3 + A/H 混合证券 + 市值中性：阻断并说明港股点时市值缺口；
2. V3 + 当前真实两证券 + 市值中性：阻断或禁用，并说明横截面样本不足；
3. 信号生成时间晚于 2026-08-28：不允许交给 V3，提示选择更新数据版本；
4. 混币种但关闭市值中性：允许受控研究时必须持续展示 FX 缺口，不把结果标记为 Alpha；
5. 数据集 Manifest 校验失败：阻断运行并引导前往数据中心，不允许静态兜底；
6. 无权打开他人运行：返回统一 404，不泄漏所有者和运行元数据；
7. 接口超时或网络失败：保留表单参数，用户可重试；
8. 功能开关关闭：入口隐藏，直接 URL 显示产品内 404，其他模块正常。

## 14. 明确不做

- 券商连接、订单、实盘组合、自动调仓、买卖建议或策略评级；
- 把回测收益写回投资逻辑、证据方向或复盘结论；
- 为凑够三只证券而伪造或倒签信号；
- 用当前市值回填历史点时市值；
- 修改或覆盖 V3、已有信号集和已有 `QPF-*` 运行；
- 把语义金标、检索标签或 AI 置信度直接作为 Alpha 信号；
- P0 中建设自由公式、代码执行、在线训练、自动调参和通用因子市场；
- 在量化页面提供正式数据发布、默认切换或资产删除按钮；
- 重做已完成的工作台主体 UI。

## 16. P0 完成定义

只有同时满足以下条件，才能将模型与因子 P0 标记为完成：

1. 命名、入口、路由和工作台设计语言统一，投资逻辑与模型因子不再混用；
2. 概览、信号、验证、结果和历史五段流程接入真实 API；
3. V3 的候选状态、真实覆盖、能力和限制展示与 Manifest 一致；
4. 信号详情可追溯到人工确认来源，越权对象不会泄漏；
5. 运行参数、结果、诊断和版本可以通过稳定 URL 复看；
6. 市值、混币种、时点、样本数和数据完整性门禁均有自动化测试；
7. 普通前端不暴露正式数据发布与默认切换动作；
8. 工作台、投资逻辑、数据中心、复盘、搜索和知识问答无回归；
9. 前后端门禁、共享环境真实账户验收、响应式和缓存隔离通过；
10. 实施记录明确标注真实样本限制，不宣称产品已经验证出可交易 Alpha。
