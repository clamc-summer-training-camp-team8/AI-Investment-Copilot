# 量化功能可行性与行动计划

更新日期：2026-09-01
结论：**研究验证型量化功能可行；实盘交易、自动调仓与组合优化不在当前产品边界内。**

## 1. 为什么可行

项目已经具备四项可复用基础：

1. 变化处理链能够生成带披露时间、生成时间、方向、强度和置信度的事件信号。
2. `analytics` 已有复权行情读取、行业基准和 20 日事件收益实验。
3. `app/core/timeutil.py` 已统一 Asia/Shanghai 时间语义并提供未来数据泄漏检查。
4. `app/calc` 已坚持 Decimal、确定性计算和零 IO，适合承载可复算回测。

因此量化能力应定位为投研闭环的“历史验证层”，而不是交易执行层：

```text
公开资料 → AI/Graph RAG 候选 → 人工确认信号 → 量化回测 → 风险与有效性判断
                                              ↘ 不生成订单或调仓指令
```

## 2. 两条评测线必须分开

专业人类研究员准备的独立金标用于评估“系统是否正确理解事实、假设和影响方向”；
量化回测用于评估“冻结后的信号规则在历史价格上表现如何”。两者不能混成一个分数。

| 评测线 | 主要问题 | 数据 | 防偏差要求 |
| --- | --- | --- | --- |
| 独立金标 | 事件抽取、关联和方向是否正确 | 人类独立标注 | 评测前冻结模型与 Prompt；不把金标回灌为提示示例 |
| 量化回测 | 信号是否有收益/风险区分度 | 复权行情、基准、交易状态 | T+1、成本、样本外、无未来函数 |

金标正式进入仓库后，应使用现有 `analytics/evaluation` 管线生成独立报告；不得用金标集同时调参和报最终成绩。建议固定开发集、验证集、一次性盲测集三个版本，并记录研究员、裁决规则和数据哈希。

## 4. MVP 计算口径

- 信号只能在 `generated_at` 所在业务日之后的第一个可交易行情点执行。
- `disclosed_at > generated_at` 的信号标记为疑似未来数据泄漏，不进入策略。
- 多条信号落在同一执行日时只采用最后生成的一条，其余信号在诊断中记录为被覆盖。
- 支持信号映射为正仓位；冲突信号在长仓模式下只平仓，开启研究性做空后才映射为负仓位。
- 旧的单证券兼容接口 `event-backtest-v1` 仍按 `方向 × 强度权重 × 置信度` 复算历史运行；主产品组合方法 `portfolio-research-v3` 只使用人工确认的方向与强度，AI 判断置信度仅作诊断元数据。
- 每次仓位变化按换手扣除 `transaction_cost_bps + slippage_bps`。
- 持有期结束在可交易行情点退出；回测期结束强制平仓。
- 输出总收益、基准收益、超额收益、年化收益、年化波动、夏普、最大回撤、胜率、换手、平均暴露、净值曲线和逐笔交易。

相同输入与 `event-backtest-v1` 方法版本产生相同 `QBT-*` 运行编号，便于复算和审计。

## 5. 产品入口与接口

前端入口：主导航“量化实验”。页面读取版本化行情目录和人工确认信号集，支持组合参数、
walk-forward 分段、风险归因、诊断限制与本人历史运行；浏览器内固定 80 日样例已经移除。

后端接口：

```http
GET  /api/quant/catalog
POST /api/quant/market-datasets/register-default
POST /api/quant/signal-sets
POST /api/quant/portfolio-backtests
GET  /api/quant/portfolio-backtests
```

行情清单、信号集、参数、方法版本和运行结果均已持久化；相同输入产生稳定 `QPF-*` 编号。
旧的 `POST /api/quant/backtests` 仅作为单证券兼容接口保留，主产品链路不再使用浏览器提交行情。

## 6. 当前不能声称什么

- 不能声称 AI 或 Graph RAG 已证明可以稳定创造 Alpha。
- 不能把只有两条信号的内部链路验证当作策略有效性或稳定 Alpha 证据。
- 不能把现金期较长、样本稀疏的组合收益直接外推为可投资组合业绩。
- 不能生成买卖、评级、调仓或自动执行指令。
- 点时市值、涨跌停、结构化公司行动、汇率与历史证券池未全量准入前，不能用于生产投资判断。

### P0：回测口径可信化

已完成：

1. 行业单例时禁止行业中性，不再把单证券信号静默归零。
2. 超额收益、跟踪误差、信息比率和 Beta 与策略实际暴露期匹配。
3. 样本不足时只报告覆盖和不足原因，不授予 Alpha 宣称权限。
4. 自动质量状态为工程测试、样本不足、研究候选；“内部验证通过”和“已失效”由后续独立评审生命周期管理，不由回测自动授予。
5. AI 置信度与 Alpha 权重分离，组合只使用人工确认的方向和强度。
6. 运行不可变保存参数、模板、因子版本和数据版本；后续仍需补充实验族/参数搜索审计视图，避免只展示表现最好的一次回测。

当前小样本阶段继续禁止自由公式、自动调参和在线训练，防止反复试参造成回测过拟合。

#### P2.3：研究评价（当前受前瞻样本门槛阻断）

点时市值、涨跌停日频状态与其他市场数据能力已通过；只有前瞻样本门槛再通过后，才允许：

- 保存无中性、仅行业中性、仅市值中性、双中性四组消融；
- 使用每个训练窗真正重新拟合的 walk-forward，而不是固定参数分段报告；
- 报告交易费用敏感性以及行业、时间、来源和市场环境稳定性；
- 对盲态和时间外结果形成独立研究意见。

达到 P2 工程门槛不等于证明 Alpha，也不允许启动 P3 纸面组合。

### P3：内部模拟组合试点

只有 P2 数据、样本、时间外测试和独立评审稳定后，才建设模型目录审批、开发/验证职责分离、纸面组合、数据中断与性能漂移监控、模型暂停/回滚/退役。P3 不连接券商，不产生订单。

## 8. 后续数据准入清单

1. 独立金标文件包含稳定样本 ID、原文 locator、双人标注、裁决结论与数据版本。
2. 行情明确复权方式、币种、时区、交易日历、停牌和涨跌停语义。
3. 基准按证券市场与行业匹配，港股/人民币资产的汇率处理有固定口径。
4. 训练/开发、验证、盲测和样本外回测区间在看结果前冻结。
5. 每次报告同时给出覆盖率、失败案例、成本敏感性和不支持的结论。
