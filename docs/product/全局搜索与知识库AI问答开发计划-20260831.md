## 1. 交付目标

本计划在不改动人工闸门和既有业务状态的前提下，完成：

1. 顶部静态输入框升级为权限感知的全局搜索；
2. 右下角新增基于知识库、带引用的 AI 研究助手；
3. 搜索与问答的 OpenAPI、AI Schema、测试、审计和共享环境灰度；
4. 模型不可用、只有标题索引或引用校验失败时的可解释降级；
5. 可独立关闭问答而不影响搜索及现有页面的回退机制。

## 2. 开发原则

- **契约先行**：先提交 OpenAPI、错误码和 AI JSON Schema，再并行实现前后端。
- **权限先于排序**：数据库/仓储层先缩小可见候选，禁止 API 层拉全量后过滤。
- **搜索与问答分离**：搜索不调用模型；问答失败不能拖垮搜索。
- **原文引用优先**：Graph 只增强召回与解释，最终引用必须是可打开的原文 locator。
- **标题不是正文**：3,784 份标题索引可以被搜索发现，但不能进入事实回答上下文。
- **无业务写回**：第一版不新增“采纳回答”或自动确认入口，避免改变正式研究状态。
- **无持久会话迁移**：会话仅保存在浏览器当前标签页，本阶段不新增聊天记录表。
- **小步提交**：契约、搜索后端、搜索前端、问答后端、问答前端、测试/发布分别提交，便于评审和回退。

   - 调用 Gateway，校验 Schema 和引用白名单；
   - 使用服务端候选补全来源信息；
   - 写入不含问答明文的模型调用审计。
3. 新增 `app/api/routers/assistant.py`，处理 404/422/503/504 映射和取消传播。
4. 实现反馈接口，仅记录 answer ID、枚举反馈和可选原因，不保存问答正文。
5. 对 provider 不可用、30 秒超时、一次修复、候选池外引用和提示注入编写测试。

#### 实现顺序

1. local provider + Schema 校验；
2. 无 Graph 的混合检索回答；
3. 指定逻辑上下文的 Graph RAG 增强；
4. HTTP provider；
5. 审计、指标和反馈。

这样可以在 Graph 集成出现问题时保留可工作的文本/向量问答路径。

#### 关键边界

- `app.ai` 不读取数据库和 Actor；所有候选由 service 传入。
- history 只改善语义连续性，不能作为本轮引用来源。
- 只有 `完整正文` 和明确可引用的合成样例可支撑事实回答；标题索引仅进入“资料待解析”提示。
- 回答 locator 必须属于本次候选白名单；不接受模型生成 URL。
- 问答不调用量化计算、不写入 Thesis/Evidence/SignalSet。
- 服务端不记录问题、历史、提示词、回答或片段正文。

### 阶段 6：测试、安全与质量评测（1.5–2 人日）

#### 后端测试

- 搜索请求校验、组内排序、精确匹配、分组上限和错误映射；
- 证券别名/行业、逻辑权限、事件来源权限、文档标签权限；
- PostgreSQL + pgvector 权限过滤发生在排名前；
- `asOf` 未来信息过滤覆盖文本、Graph 路径和最终引用；
- 标题索引不能进入事实上下文；
- local/http provider、超时、取消、有限修复和不可重试错误；
- 候选池外引用、重复引用、错误 locator、无引用事实；
- 审计记录版本/耗时/状态，但不含问题和正文。

#### 前端测试

- 防抖与过期响应；
- 快捷键、方向键、Esc、焦点恢复和 ARIA 状态；
- 各结果类型跳转；
- 标题索引标签和无结果/失败态；
- 助手上下文、发送锁、取消、重试、3 轮历史上限和清空；
- 引用点击、复制、反馈和退出登录清理；
- 1280px、1050px、760px 三个关键宽度的布局检查。

若仓库仍无前端测试框架，本阶段加入 Vitest + Testing Library，只覆盖新增交互，不一次性迁移旧页面。

#### 安全对抗

- 低权限账户搜索高权限文档标题/ID；
- 枚举 thesis/document/event ID；
- 带未来日期的资料与 Graph 节点；
- 文档中包含“忽略规则/输出密钥/伪造引用”；
- 用户问题要求展示系统提示词或其他团队资料；
- AI 返回候选池外 locator、外部 URL 或 HTML/script；
- 同一浏览器先后登录两个账户后的缓存隔离。

#### 质量门禁

- 搜索冻结集满足 Top-1 指标；
- `supported` 可核验事实引用覆盖率 ≥ 95%；
- 引用可打开率 100%，越权/未来信息/池外引用为 0；
- 仅标题和无正文样例 100% 返回证据不足或待解析提示；
- P95 搜索 ≤ 2 秒，问答端到端 P95 ≤ 20 秒，硬超时 30 秒。

### 阶段 7：共享环境发布与灰度（1 人日 + 3 个工作日观察）

#### 发布前

- 合并前执行完整工程门禁并确认工作树干净；
- 生成新的 OpenAPI，确认契约与应用一致；
- 检查数据库唯一 migration head；若阶段 2 未新增索引，则本功能不应新增迁移；
- 从目标提交 SHA 构建镜像，不使用带未提交文件的工作树镜像；
- 发布前执行成套备份并记录上一镜像标签。

#### 灰度顺序

1. `GLOBAL_SEARCH_ENABLED=true`，`KNOWLEDGE_QA_ENABLED=false`，三个账户验收搜索；
2. 对测试账户开启问答，先使用 local provider 验证降级和引用链；
3. 配置获准的 HTTP provider 后完成 20 条问答集，不记录问题/正文日志；
4. 扩大到三个团队账户，观察 3 个工作日；
5. 指标满足门禁后默认开放问答。

#### 回退

- 问答异常：关闭 `KNOWLEDGE_QA_ENABLED`，保留全局搜索；
- Graph 异常：关闭 `KNOWLEDGE_QA_GRAPH_ENABLED`，回退混合检索问答；
- 搜索异常：关闭 `GLOBAL_SEARCH_ENABLED`，恢复原页面但不改数据库；
- 代码回退使用上一不可变镜像；数据库不执行自动 downgrade；
- 权限、未来信息或引用泄漏不等待观察窗口，立即关闭问答并保留审计证据。

## 8. 完成定义（Definition of Done）

满足以下条件才视为功能完成：

1. 顶部搜索和右下角问答均连接真实 API，非 Mock 模式可完整使用；
2. 搜索、问答、引用、权限、时点和错误降级满足需求文档验收项；
3. 搜索准确性、引用覆盖、安全和性能门禁全部达标；
4. 所有工程检查通过，OpenAPI 与 AI Schema 和实现一致；
5. 共享环境完成三账户灰度、关闭开关和镜像回退演练；
6. 发布工作日志记录提交 SHA、镜像、配置开关、验收证据、已知限制和后续正文解析清单；
7. 没有权限/未来信息泄漏、候选池外引用、自动业务写回或问答明文日志。
