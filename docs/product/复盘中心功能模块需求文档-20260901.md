# 复盘中心功能模块需求文档

> 文档版本：v1.0
> 日期：2026-09-01
> 状态：待评审
> 适用代码基线：`phase3-database-auth-reconciliation` / `f3d889d`，并以当前工作区中的全局搜索、知识库 AI 问答和数据中心首版成果完成独立提交后的集成版本为开发起点
> 目标路由：`/retrospective` 及其子路由
> 关联入口：`/reviews`、`/theses/{thesisId}`、`/assets/documents/{documentId}`、全局搜索和知识库 AI 助手
> 产品边界：还原并沉淀“当时基于什么信息作出什么判断”；不自动修改投资逻辑、证据关系、状态、评级、仓位或交易指令

## 1. 需求摘要

AI Investment Copilot 已完成 Phase 2 三分支集成、共享集成环境、数据资产治理、量化能力产品化，
并在当前工作区继续完成了全局搜索、知识库 AI 问答和数据中心首版开发。产品已能管理投资逻辑、
关键假设、指标、事件、证据、版本和审计记录，也已有复核队列与阶段复盘草稿 Agent。

当前“复盘”仍未形成可交付的业务闭环：

- `/reviews` 是真实 API 驱动的异常与人工任务队列，承担的是“现在要处理什么”；
- `/retrospective` 是完整产品快照中的静态页面，展示的是“未来希望如何复盘”；
- `POST /api/reviews/theses/{thesis_id}/drafts` 可以临时生成 AI 复盘候选，但候选不能保存、编辑、
  提交、发布、修订或导出；
- 当前复盘输入只汇总区间内的已确认关系和部分审计动作，尚未形成逻辑版本、假设变化、指标结果、
  状态处置和原始证据的冻结快照；
- 页面中的逻辑变更、假设验证、强反证处理和记录完整度目前是演示数值，没有后端口径；
- 尚无“已发布复盘”和“可复用研究经验”的正式业务对象、权限模型和审计链。

本次开发将静态 `/retrospective` 升级为真实的“复盘中心”，围绕一条公司级投资逻辑建立
“选择区间与时点 → 冻结当时可得记录 → 还原逻辑演变 → 评估假设 → 生成 AI 候选 → 人工编辑与
发布 → 形成不可变版本 → 可选沉淀经验”的完整闭环。

## 2. 建设依据与当前基线

### 2.1 已有能力

| 能力 | 当前状态 | 复盘中心可复用内容 |
| --- | --- | --- |
| Phase 2 集成 | Graph RAG、Agent Runtime、排序先验和完整产品页已统一 | 复用 Agent 网关、图路径解释和静态复盘页面的交互表达 |
| 共享集成环境 | Web、API、Worker、PostgreSQL/pgvector、Redis、MinIO 在同一真实链路运行 | 复盘中心必须连接真实 API、数据库、对象与独立账号 |
| 身份与审计 | 产品内 JWT、首次改密、独立用户和团队身份已落地 | 所有聚合、详情、发布、导出和来源打开均按 Actor 鉴权并审计 |
| 投资逻辑生命周期 | 一家公司一条当前逻辑；发布、修订、状态变更和关闭受人工闸门控制 | 可按 Thesis、Hypothesis、Version 和状态决定还原演变过程 |
| 证据与指标 | 已确认关系、原文 locator、指标观测、阈值判断和人工处置已持久化 | 可构造复盘时间线、假设依据与强反证处理记录 |
| 版本与审计 | `thesis_version` 不可变快照、`audit_log` 追加留痕 | 可冻结起点/终点版本并说明谁在何时因何修改 |
| 复核工作台 | `review_task`、`ingestion_review`、任务重放和在线裁决已有真实 API | `/reviews` 继续处理进行中的任务，并可发起或跳转到复盘 |
| 复盘 Agent | `review-draft` Skill、Local/Mock/HTTP Provider 和 `review_draft` Schema 已存在 | 可迁移为持久化复盘对象的 AI 候选生成能力 |
| 数据资产治理 | 文档原件、不可变 revision、内容状态、授权和谱系已治理 | 所有复盘引用可跳转数据中心并再次鉴权打开原文 |
| 数据中心首版 | 文档目录、详情、原件、Revision、运行和量化数据目录已在工作区完成 | 复用文档详情、locator 抽屉和冻结量化版本说明 |
| 全局搜索/问答 | 权限感知搜索和带引用问答已在工作区开发 | 已发布复盘可进入搜索；问答可接受复盘上下文但不得写回 |
| 量化产品化 | 冻结行情、人工确认信号集和持久化组合运行已落地 | 可作为独立的量化验证附录，不得替代研究假设或语义评测结论 |

### 2.2 当前工程事实

- 当前开发分支为 `phase3-database-auth-reconciliation`，本地 HEAD 为 `f3d889d`；
- 当前分支相对远端存在本地提交，同时工作区还有搜索/问答、数据中心等未提交开发内容；
- Alembic 当前唯一 head 为 `0017_user_accounts`；
- 当前 OpenAPI 为 87 条路径；
- `/reviews` 已有真实任务、摄取复核、失败恢复和复盘候选入口；
- `/retrospective` 仍全部使用静态数组和本地交互状态；
- `review_task` 只保存任务和处置文本，不等同于复盘报告；
- AI 复盘候选主要是摘要、支持变化、冲突变化、待确认问题和 locator 列表，尚不足以承载正式报告。

### 2.3 必须保留的产品红线

1. AI 生成的内容始终是候选；只有研究员人工发布后才成为正式复盘。
2. 复盘不会反向自动修改 Thesis、Hypothesis、Evidence、Status、SignalSet 或量化运行。
3. 历史复盘只能使用 `data_cutoff_at` 之前已披露、已入库且当时有权访问的信息。
4. 候选、驳回、解除和未确认关系不能被改写为“当时已知的正式证据”。
5. 标题索引只证明资料存在，不得作为事实性复盘结论的正文依据。
6. 管理员权限与研究内容权限分离；管理员不能因管理系统而看到全部复盘正文。
7. 量化附录只报告冻结数据和确定性运行事实，不把小样本工程测试宣传为 Alpha 或交易结论。

## 3. 术语与模块分工

### 3.1 核心术语

| 术语 | 定义 |
| --- | --- |
| 复核 | 对候选关系、资料归属、失败任务、状态建议或到期事项作当下人工处置 |
| 复盘 | 在指定历史区间和数据截止时点下，还原判断、证据、版本和结果，并总结误差与改进 |
| 复盘报告 | 有明确 Thesis、区间、截止时点、冻结来源、状态和版本的正式业务对象 |
| 复盘草稿 | 可编辑但未发布的复盘内容；可能由人工创建，也可能包含 AI 候选 |
| 来源快照 | 本次复盘允许使用的版本、证据、指标、状态处置和原文 locator 白名单 |
| 假设结论 | 研究员在复盘中对单条假设作出的“成立/部分成立/不成立/证据不足/尚未到期”判断 |
| 研究经验 | 从已发布复盘中人工确认的可复用规则、反例、适用条件和例外，不是模型自动生成的事实 |

### 3.2 `/reviews` 与 `/retrospective` 的边界

| 模块 | 回答的问题 | 典型对象 | 主要动作 |
| --- | --- | --- | --- |
| 复核中心 `/reviews` | 现在有哪些事项需要人处理？ | 候选关系、资料归属、失败任务、逻辑复核任务、裁决项 | 确认、修改、拒绝、重放、完成任务 |
| 复盘中心 `/retrospective` | 过去的判断如何演变，哪些成立，为什么偏差？ | 复盘报告、来源快照、假设结论、研究经验 | 还原、编辑、提交、发布、修订、导出 |

完成复核任务可以成为发起复盘的入口，但两类对象不能共用一张表或同一状态字段。

## 4. 产品目标、成功标准与非目标

### 4.1 产品目标

1. 研究员可按公司、逻辑和区间快速还原当时的逻辑版本、假设、指标、证据与人工动作。
2. 每项事实判断都能回到当时可见的原文 locator、版本或确定性计算记录。
3. AI 可以帮助整理材料和提出候选总结，但研究员拥有编辑、结论和发布权。
4. 正式复盘具备不可变版本、来源指纹、操作者、截止时点和修订原因，可长期审计。
5. 复核中心、逻辑详情、数据中心、全局搜索、知识问答和量化实验之间使用稳定深链。
6. 从已发布复盘沉淀的研究经验保留适用范围和反例，避免只积累“成功故事”。

### 4.2 首版成功指标

| 指标 | 目标 |
| --- | ---: |
| 复盘列表/筛选请求 P95 | ≤ 2 秒 |
| 单份复盘详情请求 P95 | ≤ 3 秒 |
| AI 草稿端到端 P95 / 硬超时 | ≤ 20 秒 / 30 秒 |
| 已发布复盘引用可打开率 | 100% |
| 已发布复盘来源指纹和截止时点覆盖率 | 100% |
| 无权限对象标题、数量、正文或引用泄漏 | 0 |
| 截止时点之后的版本、证据、指标或 Graph 节点泄漏 | 0 |
| AI 草稿直接改变正式业务状态 | 0 |
| 已发布假设结论具备人工判断与依据的比例 | 100% |
| 草稿或退回内容进入全局搜索/经验库 | 0 |
| 发布、修订、导出和经验沉淀的审计覆盖率 | 100% |

### 4.3 非目标

首版不包含：

- 自动给出买卖、评级、目标价、仓位或调仓建议；
- 根据复盘结论自动关闭逻辑、修改状态、更新假设或确认证据；
- 使用互联网新资料补写历史复盘；
- 把候选关系、未发布草稿或标题索引当作正式事实；
- 自动评价研究员绩效、进行团队排名或生成薪酬考核；
- 用复盘中心替代质量中心的语义金标、RAG 排序或模型放量门禁；
- 用单次组合回测决定假设是否成立或宣称策略有效；
- 物理删除已发布复盘版本、来源快照、审计或研究经验历史；
- 第一版建设复杂 BI 大屏、自由拖拽报告设计器或实时多人协同编辑；
- 自动把所有历史逻辑批量生成正式复盘；没有人工确认的历史只保留为空缺。

## 5. 目标用户与权限边界

### 5.1 目标用户

| 用户 | 核心诉求 | 首版权限 |
| --- | --- | --- |
| 逻辑负责人/研究员 | 还原自己的判断、编辑假设结论、发布复盘和沉淀经验 | 对有权且本人负责的当前/历史逻辑创建、编辑和发布；查看被授权复盘 |
| 研究主管/复核人 | 查看团队复盘质量、提出退回意见、发现共性问题 | 查看团队授权范围；可评审和退回，不默认代替负责人发布 |
| 基金经理/只读成员 | 理解历史观点和演变，查看已发布结论与依据 | 只读查看被授权的已发布复盘和引用 |
| 数据/资产管理员 | 诊断引用、对象、内容状态和处理运行问题 | 管理数据运行，不因此获得复盘正文权限 |
| 系统管理员 | 配置功能开关、角色和运行状态 | 不因系统角色自动扩大研究内容可见范围 |

### 5.2 权限原则

- 列表、聚合、筛选选项、详情、导出和引用均在服务/仓储层按 Actor 过滤。
- 无权限与不存在统一返回 404，禁止通过 ID、数量或搜索建议枚举对象。
- 草稿默认仅创建人、逻辑负责人和显式评审人可见；团队可见不等于草稿可见。
- 发布复盘的可见性不能高于 Thesis，也不能高于其引用来源中最严格的可见性。
- 前端只根据 API 返回的 `allowed_actions` 展示按钮，不自行通过团队名推断权限。
- 首版只有逻辑负责人可执行最终发布；主管可退回并给意见，但不能静默代发。
- 逻辑关闭后仍允许创建结项复盘；历史 Thesis 和历史复盘只读，修正必须新增版本。

### 6.2 与现有模块的协作

| 模块 | 向复盘中心提供 | 从复盘中心接收 |
| --- | --- | --- |
| 投资逻辑 | 当前逻辑、历史版本、假设、指标映射、状态变更 | 已发布复盘入口和最新复盘摘要；不接收自动状态写回 |
| 复核中心 | 已完成任务、处置原因、发起复盘入口 | 复盘链接；不把复盘发布等同于复核任务完成 |
| 变化雷达 | 已确认/修改/驳回的关系与强反证处置 | 查看相关复盘的深链 |
| 数据中心 | 文档、Revision、授权、内容状态、原件和 locator | 从来源卡片跳转；不接收复盘正文写入资产 |
| 全局搜索 | 公司、逻辑、事件和文档发现 | 仅索引已发布复盘与已发布经验 |
| 知识库 AI 助手 | 带引用问答、当前 Thesis 上下文 | 可读取已发布复盘作为带标签的二级研究材料；不读取草稿 |
| 量化实验 | 冻结行情、信号集、运行和限制 | 可从复盘附录跳转；不接收复盘结论作为新信号 |
| 质量中心 | 评测状态与模型门禁 | 不因个别复盘结果改变模型 READY/BLOCKED |

## 7. 核心业务流程与状态

### 7.1 周期复盘

```text
选择公司级投资逻辑和复盘区间
  → 系统按 data_cutoff_at 汇总可见记录并计算完整度
  → 研究员确认来源范围并创建草稿
  → 系统冻结来源白名单和 source_fingerprint
  → 人工编写或生成 AI 候选
  → 研究员逐项评估假设、补充局限和引用
  → 提交评审（可选）
  → 负责人发布
  → 生成不可变复盘版本和审计
  → 可选沉淀研究经验
```

### 7.2 结项复盘

逻辑关闭时可以创建“结项复盘”草稿或复盘任务，但关闭动作本身不得自动发布复盘。结项复盘必须
冻结关闭前最后一个正式 Thesis 版本、关闭原因、状态处置、关键证据和未完成验证事项。

### 7.3 状态机

```text
草稿 ──提交评审──► 待评审 ──退回──► 草稿
  │                    │
  └────负责人发布──────┴────► 已发布 ──新增修订──► 草稿（新版本）

已发布 ──归档展示──► 已归档
```

- AI 运行状态（生成中、候选、低置信、失败）与复盘业务状态分开保存。
- “已发布”和“已归档”的历史版本均不可修改或物理删除。
- 同一 Thesis、复盘类型和区间只能存在一份未归档的主复盘，重复创建返回 409 并引导打开原对象。

## 8. 功能需求

### 8.1 总览、搜索与列表

#### FR-RC-001 真实概览指标

总览至少展示以下后端聚合指标，并返回 `as_of`、分子、分母和口径说明：

- **逻辑变更**：筛选区间内当前 Actor 可见 Thesis 的正式版本新增次数，不统计草稿保存；
- **已验证假设**：已发布复盘中结论为“成立、部分成立、不成立”的假设数；
- **待验证判断**：可见逻辑中状态为待验证，或已发布复盘结论为“证据不足/尚未到期”的假设数；
- **强反证处理**：已完成人工处置的高强度冲突关系数 / 区间内全部可见高强度冲突关系数；
- **记录完整度**：可用必需记录项 / 当前对象适用必需记录项。必需项包括基线版本、截止版本、
  证据 locator、披露时间、确认人/确认时间、状态变更原因和假设结论依据；
- **待完成复盘**：待评审、被退回和已到期但尚未形成复盘的逻辑数。

指标点击后进入带相应筛选的列表。前端不得用当前页数组长度、静态常量或 Mock 数值冒充全量聚合。

#### FR-RC-002 搜索、筛选与 URL 状态

支持以下条件，并全部写入 URL 查询参数：

- `q`：公司名、证券代码、逻辑标题、假设、报告标题和已发布摘要；
- 时间范围：复盘区间或发布时间；
- 行业、公司/证券、逻辑负责人、评审人；
- 复盘类型：周期、结项、专题、人工；
- 业务状态：草稿、待评审、已发布、已归档；
- 假设结果：成立、部分成立、不成立、证据不足、尚未到期；
- 是否存在强反证、是否有量化附录、记录完整度区间；
- 排序：最近更新、最近发布、区间结束日、完整度。

搜索使用防抖和过期响应保护；改变筛选回到第 1 页；刷新和复制 URL 可以恢复相同视图。筛选选项
和数量也必须按 Actor 可见范围计算。

#### FR-RC-003 服务端分页列表

默认每页 20 条，最大 100 条。每行至少显示：公司/证券、逻辑标题、复盘类型、区间、截止时点、
负责人、状态、假设结论分布、强反证处理、记录完整度、最新版本和更新时间。

列表必须区分：

- 从未创建复盘；
- 已创建但仍是草稿；
- AI 生成失败但人工仍可编辑；
- 待评审或被退回；
- 已发布；
- 已归档。

### 8.2 创建、冻结与回溯

#### FR-RC-010 创建复盘

创建时必须选择：

- 一条当前 Actor 可见的 Thesis；
- 复盘类型：周期、结项、专题或人工；
- `period_start`、`period_end`；
- `data_cutoff_at`，默认使用复盘结束日的团队时区日终，不得晚于实际创建时点；
- 报告标题，可由系统建议但可编辑。

系统在正式创建前展示来源预检：起点/终点正式版本、已确认支持/冲突证据、指标观测、状态处置、
已完成复核任务、缺 locator、标题索引、无权限或时点越界数量。研究员确认后才创建草稿。

#### FR-RC-011 冻结来源快照

创建时生成不可变来源白名单和 `source_fingerprint`。允许进入来源快照的记录包括：

- 区间起点之前最近的正式 Thesis 版本和区间内/截止时点前的正式版本；
- 截止时点前已确认或经人工修改确认的证据关系；
- 对应 Evidence、Event、Document Revision 和可打开 locator；
- 截止时点前已披露且已入库的指标观测、阈值计算结果和数据版本；
- 状态建议及人工接受、拒绝或修改记录；
- 与该逻辑有关的已完成复核任务及处置原因；
- 关闭原因、负责人动作和相关审计元数据。

以下内容必须排除或只作为“当时未知/不可用”的缺口显示：

- 待确认、已驳回、已解除或无目标假设的候选关系；
- 截止时点之后披露、入库、确认或生成的记录；
- 当前 Actor 无权查看的文档、片段和版本；
- 标题索引正文、解析失败内容和缺失对象；
- 未发布的其他复盘草稿或 AI 问答内容；
- 未冻结、不可复算或跨币种能力受限的量化结果。

来源快照不复制整份原文，只保存稳定 ID、revision/version、locator、内容哈希、披露/确认时间、
可见性口径和必要摘要。原文打开时仍需再次鉴权。

#### FR-RC-012 研究时间线

详情页按发生/披露/确认顺序展示：

- 逻辑建立和正式版本发布；
- 假设、指标映射、预期和失效条件变化；
- 支持、冲突、中性证据及人工处置；
- 指标观测与确定性阈值结果；
- 状态建议和负责人决策；
- 复核任务创建、完成与退回；
- 逻辑关闭和复盘发布。

每个节点必须标记“事实发生、信息披露、系统入库、人工确认、版本发布”中的实际时间类型，禁止把
入库时间当成事实发生时间。节点可跳转到对应版本、证据、数据中心原文或审计详情。

#### FR-RC-013 逻辑版本演变

系统基于不可变 `thesis_version` 展示起点版本、区间内版本和终点版本，至少比较：核心观点、方向、
状态、期限、假设、指标映射、预期、失效条件和变更原因。

差异由后端根据冻结快照生成；前端不读取当前 Thesis 后自行猜测历史差异。若区间内没有正式版本
变化，明确显示“本区间无正式逻辑变更”，不能生成虚构 v1/v2。

#### FR-RC-014 假设验证

每条假设在复盘草稿中包含：

- 期初表述、期末表述和是否发生正式修改；
- 验证期限、预期方向、阈值和适用数据口径；
- 支持证据、冲突证据、指标结果和未决缺口；
- 人工结论：成立、部分成立、不成立、证据不足、尚未到期；
- 结论说明、关键依据 ID、主要反证和局限；
- 判断人和判断时间。

“成立/部分成立/不成立”至少引用一项有效依据；存在高强度冲突但未解释时不得发布。AI 可以建议
结论，但默认不得替用户选中正式结果。

#### FR-RC-015 量化验证附录（P1）

研究员可选择关联已登记的冻结行情版本、人工确认信号集和持久化量化运行。附录展示数据版本、
覆盖期、证券范围、能力限制、运行参数和结果链接，并固定显示：

“该结果属于独立量化验证轨道，不替代语义准确率、检索门禁、人工证据确认或投资建议。”

复盘中心不重新计算回测，不允许用候选信号集或未来确认时间倒签结果。

### 8.3 AI 草稿、编辑与发布

#### FR-RC-020 AI 复盘候选

研究员可在已创建的复盘草稿中触发 AI 生成。模型只接收本报告来源快照中的结构化记录和引用
白名单，不直接查询数据库、互联网或任意历史资料。

候选至少包含：

- 区间摘要；
- 原判断与关键变化；
- 成立/部分成立/不成立的候选总结；
- 正确判断、错误假设、遗漏风险和领先信号；
- 支持与冲突证据的平衡呈现；
- 仍待确认的问题；
- 方法与数据局限；
- 后续研究改进建议；
- 逐项引用和模型/Prompt/Schema 版本。

生成结果必须标记 `requires_human_review=true`。模型不可用、超时、Schema 失败、引用越界或记录不
完整时保留人工编辑能力，不得用 Mock 或静态文案伪装真实成功。

#### FR-RC-021 结构化编辑与保存

编辑页支持研究员修改摘要、假设结论、误差来源、局限、改进建议和引用。要求：

- 采用纯文本或受控 Markdown，不渲染模型返回 HTML；
- 引用只能从本报告来源快照选择，不能手输任意 URL；
- 自动保存和手动保存均使用版本号/ETag 乐观锁；
- 发生并发修改返回 409，展示差异并要求用户选择，不静默覆盖；
- AI 重新生成前提示会覆盖哪些候选字段，人工已编辑内容默认保留；
- 保存失败时保留本地未提交内容并给出明确重试状态。

#### FR-RC-022 提交评审与发布

首版允许研究员直接发布，也允许先提交给指定评审人。发布前后端逐项校验：

- Thesis、区间、截止时点和来源指纹存在；
- 起点/终点版本或缺失原因明确；
- 每条已下正式结论的假设都有人工结论、理由和有效依据；
- 高强度冲突已处理或明确记录为未决局限；
- 所有事实性引用属于来源白名单且当前仍可鉴权打开；
- 摘要、误差来源、局限和后续建议非空；
- 草稿不存在未解决的并发冲突或 AI 生成中状态；
- 发布者是逻辑负责人且填写发布说明。

发布在同一事务中写入不可变复盘版本、业务状态和审计。任何下游索引或通知失败不得造成“状态已
发布但版本不存在”；异步副作用可以重试。

#### FR-RC-023 修订与更正

已发布内容不可直接修改。发现错误时从最新已发布版本创建修订草稿，必须填写更正原因和受影响
字段；发布后形成新的顺序版本，旧版本继续可见并显示“已被 vN 替代”。来源快照若有变化，必须
生成新的指纹并明确是“新增资料后的修订”，不能覆盖当时版本。

#### FR-RC-024 导出

P0 支持导出已发布复盘的受控 Markdown 和结构化 JSON；P1 增加 PDF。导出内容包含报告版本、
区间、截止时点、来源列表、引用、局限、发布人和生成时间，不包含永久对象地址、内部密钥、模型
提示词或用户不可见来源。

草稿导出默认关闭；如后续开放，必须带明显“未发布草稿”水印。每次导出记录审计。

### 8.4 研究经验与跨模块集成

#### FR-RC-030 研究经验沉淀（P1）

已发布复盘可以生成经验候选，但必须由研究员逐条确认。经验字段至少包括：

- 经验标题和规则/反模式描述；
- 适用行业、公司阶段、假设类型和时间范围；
- 不适用条件与反例；
- 来源复盘 ID、版本和原始引用；
- 提出人、确认人、状态和版本。

只有已确认经验可以进入经验库、全局搜索和知识库问答。复盘被修订时，相关经验标记“来源已更新”
并等待人工复核，不自动改写。

#### FR-RC-031 全局搜索和 AI 助手

- 全局搜索新增“复盘/经验”结果组，只返回当前 Actor 可见且已发布的对象；
- 从搜索进入详情时保留查询词并定位匹配段落；
- AI 助手在复盘详情中接受 `retrospectiveId` 上下文，只能引用已发布版本和当前可见原始来源；
- 复盘文本属于研究员解释材料，必须标为二级来源，不能替代原始公告/财报；
- 问答不写回复盘、不创建经验、不修改假设结论。

#### FR-RC-032 复核与逻辑详情联动

- `/reviews` 的逻辑任务和已完成处置可以“发起复盘”，预填 Thesis、类型和建议区间；
- 复盘创建后只写关联 ID，不自动把复核任务标记完成；
- Thesis 详情展示最近一次已发布复盘和待完成复盘，不展示其他用户私有草稿；
- 关闭逻辑时可选择创建结项复盘任务，但关闭事务不依赖 AI 生成成功。

### 8.5 状态、空态与可访问性

#### FR-RC-040 页面状态

列表、详情、编辑和来源抽屉必须覆盖：首次加载、局部刷新、空数据、无匹配、权限失效、来源缺失、
对象已修订、AI 生成中、AI 失败、保存冲突、发布校验失败和导出失败。

不得在真实 API 失败时退回静态吉利汽车演示内容。演示模式必须由显式 Mock 开关隔离并标记。

#### FR-RC-041 键盘与响应式

- 主要流程可通过键盘完成，焦点顺序清晰，弹窗关闭后焦点回到触发按钮；
- 标签、状态和假设结论不只依赖颜色；
- AI 状态、保存结果和发布校验使用可读的 `aria-live`；
- 1280px、1050px、760px 和 390px 宽度无不可控水平溢出；
- 移动端优先保留报告标题、状态、假设结论和关键来源，复杂版本差异可折叠。

## 9. 数据模型与完整性约束

### 9.1 建议业务对象

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| `retrospective` | `retrospective_id`、`thesis_id`、类型、区间、`data_cutoff_at`、状态、负责人、评审人、当前版本、`source_fingerprint`、可见性、锁版本 | 可编辑主对象，不保存已发布版本的可变正文 |
| `retrospective_source` | 来源类型、对象 ID、对象版本/revision、locator、内容哈希、披露/确认时间、可见性、摘要、排序 | 创建时冻结的来源白名单；禁止 UPDATE |
| `retrospective_version` | 顺序版本、结构化内容、来源指纹、AI run/model/prompt/schema 版本、发布人、发布说明、发布时间 | 已发布版本不可变 |
| `research_experience` | 标题、正文、适用范围、反例、来源复盘版本、状态、版本、确认人 | P1；只允许来自已发布复盘 |

草稿正文可以保存在 `retrospective.draft_content` JSONB 中，并使用 `lock_version` 做乐观并发控制；
发布时复制到不可变 `retrospective_version.content`。不得把整份原始文档或问答对话复制进复盘表。

### 9.2 关键约束

- `period_end >= period_start`；`data_cutoff_at` 不晚于实际创建/修订时点；
- 同一 Thesis、类型和区间只有一份未归档主对象；
- 来源行引用的对象必须在创建时对 Actor 可见且不越过截止时点；
- 已发布版本号按主对象单调递增，由服务端分配；
- `retrospective_source` 和 `retrospective_version` 只追加，不执行更新和物理删除；
- 发布版本中的 citation 必须引用同一 `source_fingerprint` 下的来源行；
- 研究经验必须引用已发布复盘版本，来源撤销或修订时保留历史并进入复核状态；
- 审计和业务写入同一事务；失败时整体回滚。

### 9.3 记录完整度口径

完整度由后端返回 `completed_items`、`applicable_items`、`score` 和 `missing_items`。不同 Thesis 的
适用项可能不同，不能把“没有量化附录”统一视为缺失。首版必需维度：

1. 期初正式版本或明确无期初版本；
2. 截止时点正式版本；
3. 每条引用具备稳定 locator/revision；
4. 每条正式证据具备披露时间、确认人和确认时间；
5. 每次正式状态变化具备操作者、原因和时间；
6. 每条正式假设结论具备理由与至少一项依据，或选择“证据不足/尚未到期”；
7. 报告具备局限和截止时点；
8. 已发布报告具备发布人、版本和来源指纹。

## 10. 建议 API 契约

### 10.1 查询与创建

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/retrospectives/overview` | 权限过滤后的概览指标与口径 |
| `GET` | `/api/retrospectives` | 服务端分页、搜索和筛选 |
| `POST` | `/api/retrospectives/source-preview` | 创建前预览来源范围、缺口和完整度 |
| `POST` | `/api/retrospectives` | 创建主对象并冻结来源快照 |
| `GET` | `/api/retrospectives/{id}` | 详情、允许动作和当前草稿/已发布摘要 |
| `GET` | `/api/retrospectives/{id}/timeline` | 研究时间线 |
| `GET` | `/api/retrospectives/{id}/sources` | 来源白名单与可打开状态 |
| `GET` | `/api/retrospectives/{id}/versions` | 已发布版本列表 |
| `GET` | `/api/retrospectives/{id}/versions/{version}` | 指定不可变版本 |

### 10.2 编辑、AI 与生命周期

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `PATCH` | `/api/retrospectives/{id}/draft` | 使用 `lock_version` 保存结构化草稿 |
| `POST` | `/api/retrospectives/{id}/ai-drafts` | 基于冻结来源生成 AI 候选 |
| `POST` | `/api/retrospectives/{id}/submit` | 提交评审 |
| `POST` | `/api/retrospectives/{id}/return` | 评审人退回并填写原因 |
| `POST` | `/api/retrospectives/{id}/publish` | 负责人发布并生成不可变版本 |
| `POST` | `/api/retrospectives/{id}/revisions` | 从最新发布版本创建修订草稿 |
| `POST` | `/api/retrospectives/{id}/archive` | 归档展示，不删除历史 |
| `GET` | `/api/retrospectives/{id}/exports/{format}` | 导出已发布版本 |

### 10.3 研究经验（P1）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/research-experiences` | 权限过滤后的经验列表 |
| `POST` | `/api/retrospectives/{id}/experience-candidates` | 生成经验候选，不自动发布 |
| `POST` | `/api/research-experiences` | 人工确认并创建经验 |
| `POST` | `/api/research-experiences/{id}/revisions` | 修订经验并保留旧版本 |

现有 `POST /api/reviews/theses/{thesis_id}/drafts` 在首版迁移期保持兼容，但新前端切换后标记弃用；
不得在同一版本中无提示删除旧路径。

### 10.4 错误语义

至少区分：

- `400/422`：区间、截止时点、字段或发布校验失败；
- `403`：当前用户有对象可见性但无发布/评审动作权限；
- `404`：对象不存在或不可见；
- `409`：重复区间、乐观锁冲突、状态冲突或已有修订草稿；
- `410`：来源对象已撤销且不能再打开，但历史引用仍保留；
- `503`：AI Provider、对象存储或必要后台服务不可用；
- `504`：AI 草稿超时。

错误响应使用现有统一错误结构，并携带不含敏感内容的 `request_id`。

## 11. 后端、AI 与前端边界

### 11.1 后端服务层

后端负责：

- Actor 权限、来源可见性和截止时点过滤；
- 来源快照、指纹、完整度、版本差异和假设依据聚合；
- 状态机、乐观锁、发布门禁、不可变版本和审计；
- 把允许的结构化记录和引用白名单交给 AI；
- 校验 AI Schema、引用白名单和输出大小；
- 导出内容的二次权限检查。

Router 不直接写 SQL，前端不直接读取 PostgreSQL、MinIO 对象键、服务器文件或仓库冻结报告。

### 11.2 AI 能力层

新增版本化 `retrospective-draft` Skill/Schema，保留旧 `review-draft` 兼容。AI 层：

- 只消费服务层传入的来源快照；
- 不读取数据库、Actor、互联网、量化文件或未传入资料；
- 不重新计算指标、收益、风险或状态；
- 不把候选、推断和事实混写；
- 每项事实引用来源白名单中的 `source_id/locator`；
- 输出模型、Prompt、Schema 版本和 `requires_human_review=true`；
- 引用越界、无依据事实或结构错误时最多受控修复一次，仍失败则降级。

建议新 Schema 使用结构化数组而不是只有字符串列表，以支持 `claim`、`assessment`、`source_ids`、
`limitations` 和 `human_review_required` 等字段。旧 `review_draft.schema.json` 不做破坏性覆盖。

### 11.3 前端

前端负责：

- URL 状态、加载/空态/错误态、结构化编辑和可访问交互；
- 展示后端返回的指标、差异、完整度、允许动作和引用；
- 通过数据中心的共享原文抽屉打开 locator；
- 对 AI 候选、人工内容、已发布版本和二级来源作清晰视觉区分。

前端不得重新计算完整度、权限、版本差异、来源指纹或假设结论，也不得把静态演示数组作为 API
失败兜底。

## 12. 权限、安全、隐私与审计

### 12.1 权限与时点安全

- 仓储查询先过滤可见 Thesis 和来源，再聚合、排序和计数；
- 来源打开再次执行对象级鉴权，短期预览响应使用 `no-store`；
- `data_cutoff_at` 同时约束文本、Graph 路径、指标、版本、审计和最终引用；
- Graph 只提供来源快照内部的路径解释，不得扩展到白名单外节点；
- 缓存键包含 Actor、团队/权限版本、复盘 ID、版本和来源指纹；退出登录清理用户级缓存；
- 导出文件名和内容不泄漏不可见公司、对象键、内部路径或凭证。

### 12.2 输入与输出安全

- 文档片段、旧复盘和模型输出都作为不可信文本处理；
- 禁止渲染模型 HTML、脚本、外链图片和任意 URL；
- 请求字段、Markdown、数组长度、单段长度、来源数和导出大小均设上限；
- Prompt injection 内容不能改变系统指令、引用白名单或截止时点；
- 审计与应用日志不记录复盘正文、原文片段、问题、回答、JWT 或模型密钥。

### 12.3 审计事件

至少记录：创建、来源冻结、AI 生成、AI 失败、保存、提交、退回、发布、创建修订、归档、导出、
打开引用、生成经验候选、确认经验和经验修订。元数据包括 Actor、对象、版本、来源指纹、模型/
Prompt/Schema 版本、耗时、状态、错误码和时间，不保存完整正文。

## 13. 非功能需求与可观测性

| 维度 | 要求 |
| --- | --- |
| 性能 | 3,792+ 文档和现有 Thesis 规模下列表 P95 ≤ 2 秒、详情 P95 ≤ 3 秒；聚合不得 N+1 |
| AI 时延 | P95 ≤ 20 秒，30 秒硬超时；取消后不遗留发布态或锁死草稿 |
| 一致性 | 发布状态、不可变版本和审计同事务；搜索索引异步失败可重放 |
| 幂等性 | 创建、AI 生成和发布使用稳定幂等键；重复请求不产生重复版本 |
| 可恢复性 | 新表纳入 PostgreSQL 备份；引用继续由 MinIO/Revision 成套恢复门禁覆盖 |
| 可访问性 | 键盘主流程、焦点可见、状态文本、ARIA 通知和响应式布局 |
| 可关闭性 | 复盘中心、AI 草稿和经验库使用独立功能开关；关闭 AI 不影响人工复盘 |
| 架构 | API 不直连 DB；AI 不依赖 services/db；确定性聚合不放入 AI Provider |

建议观测指标：

- 列表/详情/来源预览 P50/P95、错误率和权限拒绝数；
- 草稿创建、提交、退回、发布和修订数量；
- 从创建到发布耗时、来源缺口率和完整度分布；
- AI 生成成功率、超时率、Schema/引用失败率、token 和成本；
- AI 候选字段保留/修改比例，但不记录正文差异；
- 引用打开成功率、撤销率和越权拦截数；
- 已发布复盘进入搜索后的点击率和经验确认率；
- 强反证未解释导致的发布阻断次数。

## 14. 验收标准

### 14.1 核心闭环

- [ ] 可从真实 Thesis 创建周期或结项复盘并冻结来源快照。
- [ ] 复盘列表、详情、时间线、版本演变和假设验证均来自真实 API。
- [ ] 复盘区间、截止时点、来源指纹、完整度和缺口清晰可见。
- [ ] AI 草稿只使用来源白名单，失败时人工编辑仍可工作。
- [ ] 研究员可以保存、提交、退回、发布和创建修订。
- [ ] 已发布版本不可修改，旧版本和修订原因可追溯。
- [ ] 所有引用可进入数据中心并由当前 Actor 再次鉴权打开。
- [ ] `/reviews`、Thesis 详情和复盘中心可用稳定 ID 双向跳转。

### 14.2 数据、权限与时点

- [ ] 待确认、驳回、解除关系不会进入正式来源快照。
- [ ] 标题索引不会支撑事实性结论。
- [ ] 截止时点之后的版本、证据、指标、审计和 Graph 节点均被排除。
- [ ] 低权限账户无法通过列表、聚合、搜索、ID、导出或缓存发现高权限对象。
- [ ] 草稿、待评审和退回内容不会进入全局搜索或知识库问答。
- [ ] 管理员管理能力不会自动扩大复盘正文可见范围。

### 14.3 人工闸门与研究边界

- [ ] AI 候选不会自动选择正式假设结论或发布复盘。
- [ ] 发布不会自动修改 Thesis/Hypothesis/Evidence/Status/SignalSet。
- [ ] 高强度冲突未解释时发布被后端阻断。
- [ ] 量化附录持续展示独立评测和非交易边界。
- [ ] 经验候选只有经人工确认后才可搜索和问答。

### 14.4 工程门禁

- [ ] Alembic 保持唯一 head，新迁移从实施时的集成 head 串行派生。
- [ ] OpenAPI、错误码和新 AI Schema 与实现一致。
- [ ] Ruff、format、mypy、Import Linter、受治理资产校验全部通过。
- [ ] 单元、契约、PostgreSQL 集成和前端交互测试通过。
- [ ] 前端 lint、TypeScript 和 production build 通过。
- [ ] 3,792+ 文档规模性能、三账户权限和时点对抗验收通过。
- [ ] 共享环境完成备份、迁移、开关、回退和三工作日观察。

## 15. 发布范围与第一版取舍

### 15.1 P0 必须交付

- 真实总览、列表、搜索筛选和复盘详情；
- 来源预览与不可变来源快照；
- 时间线、逻辑版本演变和结构化假设验证；
- 持久化人工草稿、AI 候选、保存和乐观锁；
- 提交/退回（如启用评审）、负责人发布和不可变版本；
- 数据中心引用回查、基础 Markdown/JSON 导出；
- 权限、时点、审计、测试、功能开关和共享环境灰度。

### 15.2 P1 可在 P0 稳定后交付

- 研究经验候选、人工确认、经验库和搜索/问答集成；
- 冻结量化运行附录；
- PDF 导出；

- 已发布复盘的二级来源检索与 AI 助手上下文。

### 15.3 后续增强

- 周期性复盘提醒和自动创建空草稿；
- 多人实时协同编辑与字段级评论；

## 16. 待评审决策

以下问题需要在进入契约开发前由产品、研究负责人和技术负责人共同确认：

1. 首版是否启用“提交评审 → 主管退回”，还是仅负责人直接发布；本文建议保留接口和状态，UI 首版
   可按角色开关启用。
2. 复盘区间重复时是否强制唯一；本文建议同 Thesis、类型、区间只有一个主对象，通过版本修订而
   不是重复建多份。
3. P0 导出是否只做 Markdown/JSON；本文建议 PDF 放 P1，避免它阻塞真实业务闭环。
4. 研究经验是否与 P0 同期；本文建议先完成“可追溯的正式复盘”，经验库作为 P1。
5. 逻辑关闭时是否自动创建结项复盘任务；本文建议创建任务可选，但绝不自动生成或发布正文。
