# P2.1 量化数据源计划

日期：2026-08-30  
决策：AKShare 作为内部研究主源；Tushare 作为显式 Token 下的降级与补充源

## 目标与边界

目标是让研究回测拥有低成本、可持续更新、可审计的数据入口。供应商 SDK 只参与离线构建，在线
API 和回测不得联网；任何结果都必须绑定冻结源快照、provenance、能力矩阵和 SHA-256 清单。

AKShare 官方定位为研究用途，因此当前授权边界仅为项目内部研究、复算和审计，不对外再分发、
不用于实盘交易。Tushare 只有在 Token、积分和具体接口权限均有效时才启用；未配置必须正常降级，
不能让免费主链路失败，也不能把缺失字段标记为可用。

## 120 积分账号实测权限

2026-08-30 使用单证券、单交易日最小查询探测。积分表是名义准入依据，实际调用结果和频控才是
构建依据；每次账号权限或 SDK 变化后必须重新探测。

| 接口 | 实测 | 当前产品用法 |
| --- | --- | --- |
| `daily` | 可用 | 7 只 A 股未复权收盘价、成交量、成交额逐日对账 |
| `pro_bar` | 可用 | AKShare A 股抓取失败时的显式降级；正常构建不调用 |
| `daily_basic` | 单日可用；实测 5 次/天且 1 次/分钟 | 独立任务按目标交易日整市场最多调用一次；当前仍无成功缓存，能力门禁关闭 |
| `stk_limit` | 明确无权限 | 涨跌停状态和交易阻断保持关闭 |
| `trade_cal` | 年度查询可用，但每小时仅一次 | 已缓存 2026 年 SSE 日历；截至 8 月 28 日与 AKShare 的 159 个开市日完全一致 |

当前无需充值。只有在产品确需完整历史市值、涨跌停或官方日历缓存，且独立低频任务仍不能满足时，
才评估提升到 2,000 积分；充值后仍必须重新探测，不能仅凭积分值开启能力。权限依据见
[Tushare 权限说明](https://tushare.pro/document/1?doc_id=108)，主源接口说明见
[AKShare 官方文档](https://akshare.akfamily.xyz/index.html)。

## 10k 兼容端点升级（2026-08-31）

用户新配置包含 10k Token 和独立 HTTPS API Origin。连接器最初只读取 Token 并请求官方地址，五个
接口均返回 Token 无效；在把 Token 与 Origin 作为同一凭证配置、并让 `pro_bar` 复用相同 API
客户端后重新探测，`daily`、`pro_bar`、`daily_basic`、`stk_limit`、`trade_cal` 均真实返回数据。

该 Origin 作为“Tushare 兼容补充接口”独立登记，不标记为 Tushare 官方服务。Token 仍不持久化；
API Origin 会写入权限快照、缓存身份和 provenance，防止不同端点的数据静默混用。

历史回填及候选结果：

- 7 只 A 股点时市值 4,649/4,649，覆盖率 100%；
- 涨跌停状态 4,646/4,649；`603259`、`603986`、`688981` 均在 2026-07-24 缺一条，逐证券单日
  复查仍返回空，因此能力保持关闭；
- 2026 年截至 8 月 28 日交易日历 159/159，双源差异 0；
- 新候选 `MDS-akshare-qfq-tuaremax10000-20260831-v3` 已冻结但未自动发布；纯 A 股所选区间可使用
  市值中性，包含缺市值港股时后端继续硬失败。

## 完成定义

- 连续 20 个交易日自动构建无静默缺口，失败可定位到证券、接口和字段；
- 所有启用能力都有真实覆盖率证据，缺失时前后端共同硬失败；
- 至少一个含退市样本和点时行业分类的冻结证券池完成复算；
- 信号样本数和时间跨度达到研究评审预先规定的门槛后，再提交 Alpha 有效性评审；
- 产品边界仍为内部研究验证，不连接券商、不生成订单或自动调仓指令。
