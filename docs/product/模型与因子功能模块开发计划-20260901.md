# 模型与因子（量化研究）功能模块开发计划

> 计划日期：2026-09-01  
> 对应需求：`docs/product/模型与因子功能模块需求文档-20260901.md`  
> 开发分支：`feature/knowledge-answer-intent-routing`  
> 目标：在不重做工作台、不改写冻结资产的前提下，完成模型与因子 P0 产品化，并滚动交付 P1.1 模型模板与版本治理

## 1. 交付策略

本轮采用“契约补齐—模块拆分—主链实现—门禁验证—共享环境灰度”的顺序。量化引擎和数据库主对象已经存在，开发重心放在前端信息架构、真实数据呈现、可解释门禁和稳定详情路由。

开发遵循四条约束：

1. 以当前分支为基线，不重做第三阶段已经完成的工作台主体；
2. V3 只作为已登记候选供用户显式选择，不自动改成默认；
3. 先复用现有 `catalog/dataset/backtest` 契约，只为信号详情和独立开关补最小接口；
4. 前端模块从 `web/src/pages.tsx` 拆出并路由级懒加载，避免继续扩大主 chunk。

## 2. 交付范围与优先级

### P0 必须完成

- 顶部和侧栏命名、链接、激活态统一；
- `quant_research_enabled` 前后端独立功能开关；
- 模型与因子概览；
- 研究信号集列表和详情；
- 结构化新建组合验证表单；
- V3 候选状态、能力和限制展示；
- 运行结果可视化、诊断和稳定详情 URL；
- 本人历史运行；
- 数据中心、证据/逻辑与模型因子的双向深链；
- 单元、契约、前端交互、响应式、安全和共享环境验收。

### P1 滚动交付状态

- 通用因子定义与当前发布版本：已完成；历史多版本查询继续预留；
- 模型模板与运行不可变绑定：P1.1 已完成；运行对比、消融和导出继续预留；
- 团队共享运行与评审；
- 新行情版本、信号集 V2、FX、港股市值和完整涨跌停；
- 训练/选参式 walk-forward。

P1.1 交付包括 `GET /api/quant/model-templates`、`/quant/models`、模板参数预设、发布/门禁/规划状态、
因子版本、运行模板与因子版本溯源、投资逻辑研究深链以及工作台入口修正。规划模板不得运行，
已有运行不回填虚假模板版本。

## 3. 阶段计划

### 阶段 0：基线冻结与产品口径确认（0.5 人日）

任务：

1. 记录当前分支 HEAD、集成基线和未提交状态；
2. 运行现有量化 API、前端 lint/test/build 基线，保存失败项；
3. 冻结路由决策：`/quant` 为正式入口，`/theses` 保持投资逻辑；
4. 冻结 P0 术语：模型=确定性研究方法，因子=受治理信号/风险暴露；
5. 记录 V3 Manifest SHA、默认数据集 ID、真实信号集 ID 和已知限制；
6. 明确不执行线上默认切换、不发布新数据集、不伪造新信号。

产出：基线检查记录、评审通过的 PRD、V3 验收夹具。

完成门：产品、前端、后端共同确认入口、P0/P1 边界和 V3 非默认语义。

### 阶段 1：后端契约和功能开关（1–1.5 人日）

任务：

1. 在配置、认证配置响应和前端 `AuthConfig` 中增加 `quant_research_enabled`；
2. 量化 Router 在开关关闭时统一返回 404；

4. 信号详情返回冻结元数据、信号明细和可访问来源定位，权限过滤在返回前完成；
5. 复核 `POST /market-datasets/register-default` 权限；普通研究员不具备发布权限，前端不调用；
6. 为运行 404、数据能力 422、时点和市值中性错误建立稳定错误码或结构化字段；
7. 更新 OpenAPI 和生成的前端类型。

建议测试：

- 开关开/关；
- 信号集存在/不存在；
- Evidence/Relation 有权和无权；
- 他人运行继续返回 404；
- V3 A 股市值中性正向、A/H 混合、两证券样本不足；
- 普通研究员不能执行正式数据登记。

完成门：契约检查无漂移，OpenAPI 含信号详情和开关，权限测试通过。

### 阶段 4：新建组合验证主链（2–2.5 人日）

任务：

1. 将逗号代码输入改为证券多选器，显示名称、代码、市场和行业；
2. 证券候选取数据集与信号集交集；
3. 将参数分为基础、样本外、交易假设、组合约束，高级参数可折叠；
4. 默认值与 `PortfolioConfigIn` 对齐，避免前后端默认漂移；
5. 日期选择受数据集覆盖约束；
6. 实现运行前客户端即时校验，并保留后端硬门；
7. 实现市值中性状态：可用、仅 A 股、样本不足、数据缺口、混合市场阻断；
8. 实现混币种、涨跌停和公司行动能力警告；
9. 提交中防重复，成功跳转稳定运行详情；
10. 网络/422/404 失败保留表单值和可重试入口；
11. 会话草稿不跨账号，退出登录清理。

关键验收组合：

| 数据/信号 | 配置 | 预期 |
| --- | --- | --- |
| V3 + 真实两证券 | 市值中性关闭 | 可运行并显示样本限制 |
| V3 + 真实两证券 | 市值中性开启 | 禁用或 422，说明横截面不足 |
| V3 + A/H 混合 | 市值中性开启 | 阻断，说明港股无点时市值 |
| V3 + 晚于 2026-08-28 的信号 | 任意 | 阻断，要求更新数据版本 |
| Manifest 校验失败 | 任意 | 阻断，不产生历史运行 |

完成门：真实 V3 两信号运行闭环通过，所有阻断场景文案可操作、无伪结果。

### 阶段 8：共享环境灰度与验收（1 人日 + 2 个工作日观察）

发布前：

1. 从干净提交 SHA 构建不可变镜像；
2. 备份 PostgreSQL 与 MinIO，记录当前默认数据集和上一镜像；
3. 确认 V3 仍为已登记候选，默认版本未被开发流程修改；
4. 使用研究员、研究负责人/管理员和普通只读账户验证权限；
5. 运行旧默认和 V3 已有历史运行复看；
6. 验证开关关闭、开启和上一镜像回退。

灰度顺序：

1. 部署后先关闭 `QUANT_RESEARCH_ENABLED`，回归工作台、数据中心和投资逻辑；
2. 对测试账户或共享环境开启模块，验证目录和只读信号；
3. 用 V3 + 真实两信号、关闭市值中性执行一次受控运行；
4. 验证 A/H 市值中性、晚信号和 Manifest 异常阻断；
5. 观察 2 个工作日的错误率、性能、缓存隔离和用户理解问题；
6. 无高风险问题后扩大入口可见范围。

回退：

- 前端或交互异常：关闭量化功能开关，保留数据集、信号集和运行；
- API 异常：回到上一镜像，不删除新运行；
- 权限泄漏或错误默认切换：立即关闭模块，恢复部署配置并保留审计；
- 数据异常：停止新运行，保持 V3/旧版本不可变，使用新的修订版本处理，不覆盖原资产。

完成门：真实账户、开关、回退、性能和关键门禁均有验收记录。

## 11. 风险与应对

| 风险 | 概率/影响 | 应对 |
| --- | --- | --- |
| 当前分支名称与量化内容不一致 | 中/中 | 量化提交独立、PR 清楚列出基线和提交范围 |
| 顶部改链导致投资逻辑入口难找 | 低/中 | 左侧“投资逻辑”和工作台逻辑卡继续保留 `/theses` |
| V3 被误解为默认或已上线 | 高/高 | 默认只读 `default_market_dataset_id`，候选徽标和文案验收 |
| 当前信号过少导致结果被过度解读 | 高/高 | 显示样本数和工程验证声明，阻断虚假市值中性 |
| 图表增加 bundle 体积 | 中/中 | 路由懒加载、依赖评估、构建体积门禁 |
| 前后端默认参数漂移 | 中/高 | 从 OpenAPI/共享常量生成类型，契约测试锁默认值 |
| 普通用户触发数据登记 | 中/高 | 移除 UI 动作，后端增加治理权限 |
| 信号详情泄漏受限证据 | 低/高 | 服务端裁剪、404、权限对抗测试 |
| 混币种收益被宣传为 Alpha | 中/高 | 高可见限制、报告声明、不生成评级 |
| 量化页继续成为巨型单文件 | 高/中 | 阶段 2 强制模块拆分，代码评审检查边界 |

## 12. 完成定义

P0 完成需要同时满足：

1. 需求文档中 FR-01 至 FR-10 全部通过验收；

8. 未完成的通用因子库、模型模板和新信号样本明确留在 P1，不用静态页面替代。
