## 1. 交付目标

首版完成以下闭环：

1. 把现有 `/assets`“资产治理”单页升级为“数据中心”模块；
2. 交付数据总览、研究资料目录、文档详情/原件/谱系、已登记量化数据目录和数据源/运行视图；
3. 补齐分页文档目录、文档详情、revision、处理运行、来源和量化数据详情的只读契约；
4. 复用现有重处理、可见性、软删除、索引重建和量化目录能力，不重写底层数据治理；
5. 接通全局搜索、AI 引用、任务中心和量化实验的深链；
6. 在共享集成环境完成多账号权限、性能、原件访问和回退验收。

增强版再交付量化刷新运行持久化、候选待发布视图和受控发布检查清单，避免首版前端直接依赖
CI artifact 或服务器 `.runtime` 文件。

## 2. 范围与优先级

### 2.1 首版 P0

- 数据中心二级导航、路由、加载/空/错状态和响应式外壳；
- 数据总览及需要关注项；
- 研究资料服务端分页、搜索、筛选和排序；
- 文档详情、活动原件、locator、来源授权、revision 和处理运行；
- 标题索引/完整正文的产品边界；
- 已登记冻结行情版本、信号集、能力矩阵和限制；
- 文档归档/解析运行和来源目录；
- 与全局搜索、知识问答引用、任务中心、量化实验的深链；
- 权限、审计、缓存隔离、性能和共享环境验收。

### 2.2 首版 P1（时间允许时合入）

- 文档批量重处理和批量可见性调整；
- 文档状态/来源/运行摘要导出为不含正文的 CSV；
- 总览聚合短时缓存和查询性能索引；
- 资料详情中的关联事件/证据只读入口；
- 更完整的键盘操作和移动端筛选抽屉。

### 2.3 增强版

- 将量化行情刷新、低频参考缓存和候选报告登记为产品运行记录；
- 展示 `noop`、`candidate_built`、`candidate_reused`、`failed` 和待发布状态；
- 候选发布检查清单、审批记录及默认版本切换；
- 全文解析优先级队列和批次进度；
- 数据新鲜度告警与连续 20 个交易日稳定性视图。

## 3. 开发原则

- **契约先行**：先确定分页、状态枚举、错误码和 `allowed_actions`，再并行开发前后端。
- **权限先于聚合和分页**：所有数量、选项、列表和详情均按 Actor 缩小范围。
- **只读目录优先**：先解决可见、可找、可追溯，再开放少量已有受控写操作。
- **状态正交**：归档、授权、解析、索引和可见性分别展示；候选、冻结、默认和能力准入分别展示。
- **后端口径唯一**：前端不计算质量、覆盖率、能力、哈希或数据新鲜度结论。
- **历史不可覆盖**：失败与成功运行、旧 revision 和旧冻结版本均保留。
- **不直读运行目录**：浏览器和在线 API 不读取 `analytics`、CI artifact、服务器 `.runtime` 或部署文件。
- **小步提交**：契约、查询、页面外壳、资料目录、详情、量化目录、测试和发布分别提交。
- **共享组件先解耦**：与全局搜索共同使用的原文抽屉、API 映射和样式先确定接口，减少合并冲突。

## 4. 开发前置检查

开始编码前完成以下检查：

1. 确认全局搜索与知识库问答功能是否已提交，并选择共同基线；当前工作区的
   `web/src/App.tsx`、`api.ts`、`types.ts`、`design-system.css` 和 OpenAPI 已存在并行改动，不能直接
   覆盖。
2. 执行 `git status` 并记录现有用户改动；数据中心使用独立短期分支或干净 worktree。
3. 确认 Alembic 唯一 head、OpenAPI 当前路径数、Python/前端测试基线和共享环境当前镜像。
4. 从真实数据库记录 3,792 份文档规模下的现有 inventory 与 hybrid-search P95，作为性能对照。
5. 明确三个验收账户：资产管理员、研究员、只读成员；文档不记录密码。
6. 固定验收样例：完整正文、标题索引、失败后成功重试、受限文档、多 revision、默认量化版本、
   历史量化版本、A/H 混合能力限制各至少 1 个。

## 5. 工作分解

### 阶段 0：产品/交互收口与验收集冻结（0.5–1 人日）

#### 任务

- 评审需求文档，确认首版 P0、二级入口和与其他模块的职责边界。
- 绘制低保真流程：总览 → 资料列表 → 文档详情 → 原件/locator → revision/运行；量化列表 → 详情
  → 量化实验。
- 冻结状态文案和颜色语义，重点确认“标题索引”“原件已归档”“完整正文”“candidate”与
  “default”。
- 固定 20 条目录/筛选验收查询和 10 个详情对象，记录当前 Actor 可见范围和期望状态。
- 冻结 1280px、1024px、760px、390px 四个关键宽度的页面验收清单。

#### 产出

- 评审后的需求文档；
- 页面流程/线框和状态字典；
- 数据中心验收数据集及账号矩阵；
- 首版范围与增强版 backlog。

#### 完成标准

- 任何状态都能由明确后端字段推导，不依赖前端猜测；
- 数据中心、任务中心、质量中心和量化实验没有重复主操作；
- 验收样例不包含未授权正文或凭证。

### 阶段 1：OpenAPI、错误码与查询模型（1 人日）

#### 任务

1. 在 `contracts/api/openapi.yaml` 定义：
   - `GET /api/assets/overview`
   - `GET /api/assets/documents`
   - `GET /api/assets/documents/{document_id}`
   - `GET /api/assets/documents/{document_id}/revisions`
   - `GET /api/assets/documents/{document_id}/ingestion-runs`
   - `GET /api/assets/sources`
   - `GET /api/assets/ingestion-runs`
   - `GET /api/assets/documents/{document_id}/content`
   - `POST /api/assets/documents/{document_id}/restore`
   - `GET /api/quant/market-datasets/{dataset_id}`
2. 定义统一分页、排序、筛选、状态枚举、`as_of` 和 `allowed_actions`。
3. 在 `contracts/api/errors.yaml` 增加无效筛选、无效 cursor、原件不可预览、revision 不可用、运行
   冲突和数据清单失配等错误。
4. 补充 Pydantic Schema；文档列表摘要和详情分开，避免列表携带大 JSON/正文。
5. 增加 OpenAPI 解析、请求边界、枚举和实现漂移测试。

#### 主要文件

- `contracts/api/openapi.yaml`
- `contracts/api/errors.yaml`
- `app/schemas/assets.py`
- `app/schemas/quant.py`
- `tests/contract/`

#### 设计决策

- 列表默认 offset/page 分页即可；若 `ILIKE + 多筛选 + 总数` 实测慢，再改 cursor，不在契约中同时
  支持两套不必要的分页模型。
- `allowed_actions` 是后端决策结果，前端只渲染，不硬编码 `asset-admin`。
- 详情只返回脱敏来源与对象状态；原件字节通过独立接口返回。
- 量化 catalog 可继续作为列表来源，详情接口补充子资产校验和关联计数。

#### 完成标准

- 前端可以仅依赖契约和受控 mock 开始开发；
- OpenAPI 3.1 校验通过，代码导出与契约一致；
- 分页上限、日期范围、排序白名单和非法枚举均有契约测试。

### 阶段 2：后端文档目录、详情与总览（2.5–3 人日）

#### 任务

1. 扩展 `AssetRepository` Protocol 与 SQL 实现：
   - Actor 可见范围内文档分页查询；
   - 文档详情、关联证券/行业、活动 revision 和最新运行；
   - revision/运行分页；
   - 来源目录与可见资产计数；
   - 总览聚合和需要关注项。
2. 在数据库查询层实现筛选、排序和分页，禁止 API 拉全量后过滤。
3. 为 `content_status`、来源、披露时间、最新运行等组合查询执行 `EXPLAIN ANALYZE`；只有实测需要
   时才增加迁移和索引。
4. 扩展 `app/services/assets.py`：
   - 权限、状态和 `allowed_actions` 组装；
   - 标题索引/正文边界；
   - 原件访问鉴权与安全响应元数据；
   - 软删除恢复的冲突检查；
   - 治理操作审计。
5. 在 assets Router 增加薄路由和统一错误映射。
6. 总览的“最近运行”先覆盖数据库中已有归档/解析运行；量化刷新运行放增强版。

#### 主要文件

- `app/core/domain.py`
- `app/db/repositories/assets.py`
- `app/db/models/core.py`（仅实测需要索引时）
- `app/services/assets.py`
- `app/api/routers/assets.py`
- `app/schemas/assets.py`
- `alembic/versions/`（仅必要索引）
- `tests/unit/services/`
- `tests/unit/api/`
- `tests/integration/`

#### 测试重点

- 权限过滤发生在计数、筛选选项、排序和分页之前；
- 标题索引不会返回正文片段能力；
- 失败运行和后续成功运行同时存在；
- 无权限文档、revision、原件和 locator 统一不可枚举；
- 原件响应的 MIME、Content-Disposition、安全头和审计；
- 3,792 份文档下组合筛选 P95。

#### 完成标准

- 20 条冻结目录查询和 10 个详情对象响应符合预期；
- 列表 P95 ≤ 2 秒，详情 P95 ≤ 3 秒；
- 不新增不必要迁移；若新增索引，base→head 和 downgrade/upgrade 往返通过；
- Repository、service、router 分层契约通过。

#### 前端任务

- 实现详情的子资产、证券/市场/币种、能力、限制和信号集区域；
- “使用此版本”跳转 `/quant?marketDatasetId=...`，量化页校验版本存在且已冻结；
- 实现来源与运行列表、筛选、运行详情和跳转任务中心；
- 不在数据中心展示回测收益或把内部验证运行描述为 Alpha。

#### 主要文件

- `app/services/quant.py`
- `app/api/routers/quant.py`
- `app/schemas/quant.py`
- `web/src/data-center/MarketDatasetsPage.tsx`
- `web/src/data-center/MarketDatasetDetailPage.tsx`

- `web/src/pages.tsx`（仅为 `/quant` 接收数据版本参数做小范围调整）

#### 完成标准

- 默认版本由后端确认，历史版本仍可查看和复算；
- 纯 A 股点时市值能力与 A/H 混合限制显示准确；

### 阶段 6：联调、测试、安全与性能（2–2.5 人日，开发中持续执行）

#### 后端测试

- 列表参数、分页、排序白名单、日期范围和错误映射；
- 文档/来源/运行聚合权限和不可见总数；
- revision、运行、原件、locator 的对象级鉴权；
- title_index、archive、full_text 状态组合；
- allowed_actions 与直接接口授权一致；
- 量化清单哈希失配、blocked 版本和能力范围；
- PostgreSQL + pgvector 真实集成测试，不允许缺库跳过。

#### 前端测试

- URL 与筛选双向同步、刷新恢复、分页和过期响应；
- 加载、空、错误、权限过期和重试；
- locator 深链、前后片段、标题索引提示和安全渲染；
- allowed_actions、确认对话框、409/422/503 错误；
- 量化默认/历史版本、能力限制和跳转参数；
- 键盘、ARIA、焦点恢复和四个关键宽度。

若前端测试框架已由全局搜索工作引入，直接复用 Vitest + Testing Library；若尚未引入，本阶段只为
数据中心新增最小测试配置，不一次性迁移旧页面。

#### 安全对抗

- 低权限用户枚举文档 ID、revision ID、locator、来源和原件；
- 通过分页总数、筛选选项和聚合卡片推断受限资产；
- 文件名/标题包含 HTML、脚本、双向控制字符或超长文本；
- 伪造 MIME、外部重定向和不安全内联预览；
- 先后登录不同账户后的 React Query 缓存串线；
- 操作按钮隐藏但直接 API 调用越权；
- 量化 manifest 或子资产哈希漂移仍被标记可用。

#### 性能门禁

- 文档列表组合筛选 P95 ≤ 2 秒；
- 文档详情 P95 ≤ 3 秒；
- 总览 P95 ≤ 2 秒；
- 首屏不请求所有 revision、运行或片段，详情区域按需加载；
- 共享 2C4G 环境下搜索、问答和数据中心同时使用不产生持续队列积压或 OOM。

### 阶段 7：共享环境发布与验收（1 人日 + 3 个工作日观察）

#### 发布前

- 从已提交目标 SHA 构建，不发布带未提交改动的工作树；
- 运行 Python、架构、Schema、OpenAPI、受治理资产和前端全部门禁；
- 如果有迁移，确认唯一 head 并在临时 PostgreSQL 执行 base→head→base→head；
- 执行发布前数据库、MinIO 对象版本、镜像清单和哈希成套备份；
- 记录上一镜像标签和功能关闭/代码回退路径。

#### 发布顺序

1. 部署只读目录接口和数据中心页面，治理写操作保持关闭或仅管理员可见；
2. 使用资产管理员验收总览、资料、原件、revision、运行和量化版本；
3. 使用研究员和只读成员验收权限范围、深链和按钮；
4. 开放重处理、可见性和索引重建，验证审计及任务跳转；
5. 与全局搜索/AI 引用和量化实验完成双向跳转；
6. 观察 3 个工作日的 API P95、错误率、对象存储失败和 Worker 队列。

#### 回退

- 前端严重异常：回退上一 Web 镜像；新增只读 API 可保留但不暴露入口；
- 新查询导致数据库压力：关闭数据中心新入口或回退 API 镜像，保留旧 `/assets` 页面；
- 原件访问/权限异常：立即关闭原件内容接口，不等待观察期；
- 新增索引迁移通常不需要紧急 downgrade，先回退代码并评估锁与容量；
- 不自动删除新审计、运行或不可变资产记录。

## 10. 增强版计划（首版稳定后 3–4 个工作日）

### 阶段 A：量化刷新运行持久化（1.5 人日）

- 为行情刷新、低频参考缓存和候选构建增加不可变运行记录；
- 调度报告只保存脱敏摘要、报告哈希和 artifact 标识；
- 增加 `GET /api/quant/refresh-runs` 及详情接口；
- 从 `noop` 到 `candidate_built` 的状态转换具备契约和集成测试。

### 阶段 B：候选发布检查清单（1–1.5 人日）

- 展示候选清单哈希、授权、能力覆盖、跨源质检和人工审批状态；
- 发布人必须提供审批后的 dataset ID 和 manifest SHA-256；
- 发布动作调用已有受控脚本/服务能力，不让前端写冻结目录；
- 默认切换保留审计，旧版本继续可复算。

### 阶段 C：稳定性与告警（1 人日）

- 展示连续 20 个交易日成功率、延迟、重试、跨源差异和失败类型；
- 接入磁盘、队列、对象存储和默认行情新鲜度告警；
- 达不到门禁时保持候选隔离，不自动降级或静默切源。

## 11. 完成定义（Definition of Done）

首版满足以下条件才可关闭开发任务：

1. 需求文档中的 P0 功能与 AC-01 至 AC-08 全部通过；
2. 数据总览、资料目录、文档详情/原件/谱系、已登记量化数据和来源/运行连接真实 API；
3. 全局搜索、AI 引用、任务中心和量化实验深链稳定；
4. 权限、状态边界、审计、缓存隔离和原件安全没有已知高风险问题；
5. 工程、性能和共享环境多账号门禁全部通过；
6. 共享环境观察期没有持续错误率、数据库压力、对象存储访问或队列积压异常；
7. 发布工作日志记录提交 SHA、镜像、迁移、备份、验收、回退和增强版未完成项。
