## 1. 交付目标

本计划把现有静态 `/retrospective` 和临时 AI 复盘候选升级为真实、持久化、可审计的复盘中心，
同时保持 `/reviews` 作为进行中人工复核工作台。P0 交付以下闭环：

1. 复盘总览、服务端分页列表、搜索筛选和真实指标；
2. 创建周期/结项复盘，并按截止时点冻结来源白名单和来源指纹；
3. 展示研究时间线、逻辑版本演变、结构化假设验证和来源缺口；
4. 保存人工草稿，基于冻结来源生成 AI 候选，并支持乐观锁编辑；
5. 提交/退回、负责人发布、不可变版本和修订；
6. 复用数据中心原文抽屉，完成 `/reviews`、Thesis 详情和复盘中心深链；
7. 完成权限、时点、审计、契约、测试、性能、备份、灰度和回退。

P0 完成后再交付研究经验库、量化附录和 PDF 导出，不让增强功能阻塞真实复盘主链路。

- 结构化假设结论及高强度冲突发布门禁；
- 持久草稿、乐观锁、AI 候选和人工编辑；
- 提交/退回接口、负责人发布、修订和归档；
- Markdown/JSON 导出；
- `/retrospective` 真实页面及子路由；
- 数据中心 locator 回查、`/reviews` 和 Thesis 详情联动；
- OpenAPI、AI Schema、错误码、功能开关、审计与观测；
- 单元、契约、数据库集成、前端交互、安全与性能测试；
- 共享环境三账户灰度和回退演练。

### 2.2 P1：P0 稳定后完成

## 3. 开发原则

1. **先清理集成基线**：当前未提交的搜索/问答和数据中心成果必须先按模块独立提交、验证和记录，
   复盘中心不与这些改动混成一个提交。
2. **契约与数据模型先行**：先评审状态机、OpenAPI、错误码、数据库表和 AI Schema，再并行开发。
3. **复核与复盘分离**：复用稳定 ID 和跳转，不复用 `review_task` 表承载复盘正文或版本。
4. **时点先于生成**：先冻结来源白名单和 `data_cutoff_at`，再生成 AI 候选；不能生成后再裁剪未来信息。
5. **权限先于聚合**：仓储层先过滤可见 Thesis、版本和来源，再统计、排序和计算指标。
6. **人工闸门唯一**：AI 只写候选；发布、假设结论、经验沉淀均由服务层人工动作完成。
7. **不可变发布**：已发布复盘、来源快照和版本只追加；错误通过修订纠正，不覆盖历史。
8. **确定性逻辑不进模型**：完整度、版本差异、时点裁剪、状态机和发布门禁全部由后端确定性实现。
9. **功能独立关闭**：人工复盘、AI 草稿、经验库分别使用开关；AI 失败不影响人工主链路。
10. **小步提交与可回退**：迁移、后端读链、生命周期、AI、前端和集成分别提交。

## 4. 开发前置检查

阶段 0 完成前不创建复盘中心业务迁移或修改共享环境。

### 4.1 工作区与 Git

1. 保存当前 `git status --short` 和改动归属清单，确认哪些属于：
   - 登录/共享环境；
   - 全局搜索与知识库问答；
   - 数据中心；
   - 量化/数据治理；
   - 第三只 A 股复核材料；
   - 临时输出与不应提交文件。
2. 将搜索/问答、数据中心和必要修复拆成独立提交，避免把 `outputs/**/_work`、凭证、运行正文或
   临时检查文件纳入 Git。
3. 确认目标远端分支和下一次团队合并策略；从验证通过的集成提交创建
   `feat/retrospective-center`。
4. 不对现有用户改动执行 `reset --hard`、`checkout --` 或批量删除。

### 4.2 工程基线

在功能分支创建前记录：

- `git rev-parse HEAD`、远端跟踪状态和工作树是否干净；
- `alembic heads` 必须只有一个 head；当前记录为 `0017_user_accounts`，若前置合并新增迁移，复盘
  中心从合并后的唯一 head 派生，不硬编码旧 head；
- OpenAPI 路径数和契约校验结果；当前记录为 87 条；
- Python 单元/契约、PostgreSQL 集成、Ruff、mypy、Import Linter 和受治理资产结果；
- 前端 ESLint、TypeScript 和生产构建结果；
- 共享环境当前镜像、数据库迁移版本和功能开关，只记录标识，不记录凭证。

### 4.3 评测与验收样例

冻结至少 15 个复盘场景：

| 场景 | 最低数量 | 目的 |
| --- | ---: | --- |
| 正常周期复盘 | 3 | 有起止版本、支持/冲突证据和指标 |
| 无正式版本变化 | 1 | 不得虚构逻辑演变 |
| 结项复盘 | 2 | 关闭原因、最后版本和未决事项 |
| 只有标题索引 | 1 | 只能显示资料缺口，不能支撑事实 |
| 来源对象缺失/撤销 | 1 | 历史引用保留但打开状态明确 |
| 高强度冲突未解释 | 1 | 发布必须阻断 |
| 截止时点之后有新资料 | 2 | 文本、Graph、指标和版本均不泄漏 |
| 跨权限账户 | 2 | 列表、聚合、详情和导出均不泄漏 |
| AI 超时/Schema/引用失败 | 2 | 人工编辑继续可用 |

每个样例记录 Thesis、区间、允许来源 ID、禁止来源 ID、预期完整度缺口、预期假设结论范围和
允许动作。验收数据只使用已获授权的仓库样例或隔离测试数据。

#### 数据模型注意

- `retrospective` 保存可变草稿、状态、当前版本号和 `lock_version`；

- 同一 Thesis、类型和区间的主对象唯一性优先由数据库约束保护；
- JSONB 内容仍需 Pydantic/Schema 校验，不能把任意字典直接写入数据库。

2. 新增 `app/services/retrospective_sources.py`：
   - 校验 Actor、Thesis、区间和截止时点；
   - 找到期初/期末正式版本；
   - 只汇总已确认或人工修改确认的关系；
   - 裁剪披露、入库、确认、Graph 和指标时点；

### 阶段 3：复盘生命周期、发布门禁与 API（2–2.5 人日）

#### 任务

1. 新增 `app/services/retrospective.py`，实现：
   - 创建并冻结来源；
   - 使用 `lock_version` 保存草稿；
   - 提交评审、退回；
   - 发布校验和不可变版本；
   - 从已发布版本创建修订草稿；
   - 归档；
   - Markdown/JSON 导出。
2. 发布门禁覆盖：来源指纹、版本、假设结论、引用、高强度冲突、局限、发布说明和发布人。
3. 在同一事务中写业务状态、不可变 version 和 audit；搜索索引等副作用使用可重试异步任务。
4. 新增薄 Router `app/api/routers/retrospectives.py` 并注册到应用。
5. 实现稳定幂等键：
   - 创建：Actor + Thesis + 类型 + 区间；
   - 发布：retrospective ID + `lock_version` + source fingerprint；
   - 导出：对象 + 发布版本 + 格式。
6. 保持旧 `/api/reviews/theses/{thesis_id}/drafts` 可用并标记弃用，不在本阶段删除。
7. 增加对象不存在/无权限统一 404、动作无权 403、重复/并发/状态冲突 409 的一致映射。

#### 事务边界

```text
发布复盘
  → permission 与 owner 校验
  → 草稿 Schema、来源、引用、冲突和完整度门禁
  → 锁定主对象并校验 lock_version
  → 追加 retrospective_version
  → 更新主对象 current_version/state
  → 写 audit
  → commit
  → 提交可重试索引/通知副作用
```

不得让 AI 调用、PDF 生成、搜索索引或外部通知参与核心数据库事务。

### 阶段 4：AI 复盘候选产品化（1.5–2 人日）

#### 任务

1. 新增版本化 Skill：`app/ai/skills/retrospective-draft/SKILL.md`。
2. 注册新的 `retrospective_draft` 任务和 Schema；Local/Mock/HTTP Provider 保持同一契约。
3. 扩展 Gateway/Runtime：
   - 接收规范化来源快照；
   - 使用稳定幂等键；
   - 记录模型、Prompt、Schema、token、耗时和运行状态；
   - Schema 或引用失败时最多修复一次。
4. 新增 `app/services/retrospective_ai.py`：
   - 读取已冻结来源，不重新搜索数据库；
   - 生成编号化候选和 locator 白名单；
   - 调用 Gateway；
   - 校验每个事实 claim 的来源 ID；
   - 把结果保存为草稿中的 AI 候选区，不覆盖人工字段；
   - 记录不含正文的审计。
5. `RETROSPECTIVE_AI_DRAFT_ENABLED=false` 时，人工创建/编辑/发布完整可用。
6. 对 Provider 不可用、30 秒超时、取消、Schema 失败、引用越界、Prompt injection 和空来源编写测试。

#### AI 输入边界

- 只传来源快照中的必要结构化字段和短摘要；
- 标题索引、无权来源、未来资料和未确认关系不进入上下文；

#### 灰度顺序

1. 部署迁移和代码，三个复盘开关均关闭，执行健康检查与旧功能回归；
2. 开启 `RETROSPECTIVE_CENTER_ENABLED=true`、AI 关闭，使用研究员账户验证人工创建/发布；

- AI 异常：关闭 `RETROSPECTIVE_AI_DRAFT_ENABLED`，人工复盘继续可用；

- 数据库使用追加式表和迁移，不自动 downgrade；关闭功能后保留已写数据和审计；
- 权限或未来信息泄漏不等待观察窗口，立即关闭相关开关并保留审计证据。

#### 完成标准

- 三种真实账户完成创建、发布、只读、无权、导出和原文回查验收；
- 15+ 冻结样例、安全对抗和性能门禁通过；

- 发布实施记录包含提交 SHA、镜像、迁移、开关、性能、验收证据、已知限制和回退结果。

- `/reviews` 路由和 `ReviewTaskRecord` 语义保持不变；
- 新前端只调用 `/api/retrospectives/**`；
- 后续删除旧 API 前先确认访问日志为零并发布迁移说明。

### 10.3 备份与恢复

- 新主对象、来源和版本表纳入 PostgreSQL 备份；
- 原文对象仍由现有 MinIO 备份和引用覆盖率报告保护；
- 隔离恢复验证复盘表行数、版本连续性、来源指纹、引用对象可用率和 Alembic 版本；
- 已发布版本与来源快照发现错误时通过新版本修正，不直接更新恢复后的历史行。

## 11. 风险与应对

| 风险 | 概率/影响 | 应对 |

## 13. 完成定义（Definition of Done）

满足以下条件才可将 P0 标记为“复盘中心首版完成”：

1. 当前已有模块先形成干净集成基线，复盘中心改动可独立审查和回退；
2. 研究员可基于真实 Thesis 和真实来源，从创建一直完成到人工发布与修订；
3. 总览、时间线、版本、假设、完整度和来源均由后端真实数据生成；
4. 来源快照严格满足权限、内容状态和截止时点规则，所有发布引用可回查；
5. AI 只生成候选且失败不影响人工主链路，不发生自动业务写回；
6. 已发布复盘具备不可变版本、来源指纹、发布人、截止时点、修订和审计；
7. `/reviews`、Thesis 详情和数据中心深链贯通，旧复核流程无回归；
8. 自动化、安全、性能、备份恢复和三账户共享环境验收全部通过；
9. 发布实施记录清楚标记已完成、未完成、已知限制、开关和回退方式；
10. P1 经验库、量化附录和 PDF 未完成时明确显示为后续范围，不以静态页面冒充交付。
