# AI Investment Copilot RAG 与量化模块详细技术报告

> 报告版本：2026-09-02
> 工程基线：`feature/models-factors-workbench-integration` / `2818d5a`
> 适用场景：最终产品答辩、技术评审、研发交接
> 产品边界：研究辅助与研究验证；不构成投资建议，不生成订单、评级或调仓指令

## 0. 摘要

AI Investment Copilot 是一个以“投资逻辑”为核心对象的主动权益研究协作平台。它解决的不是
“让大模型替研究员做投资决定”，而是两个更具体、也更适合工程化的问题：

1. 当资料、事实、指标和研究假设不断增加时，如何让研究员优先看到真正相关、可追溯且在权限和
   历史时点上可见的证据；
2. 当研究员已经确认某个事件对投资假设的方向和强度后，如何把判断放入一个数据、方法、参数和
   结果都可冻结、可复算、可审计的量化实验。

本项目用 RAG/Graph RAG 解决第一个问题，用“模型与因子”量化模块解决第二个问题：

```text
公开原文与结构化事实
        ↓
RAG：按文本相关性和研究关系检索、排序、给出原文路径
        ↓
研究员人工确认“证据—假设”关系及方向、强度
        ↓
量化：冻结信号 + 冻结行情 + 模型模板 + 因子版本
        ↓
确定性回测、风险归因、样本门禁、不可变运行
```

截至本报告基线，两个模块的结论必须分层理解：

| 模块 | 工程与产品化结论 | 效果或研究结论 | 当前成熟度 |
| --- | --- | --- | --- |
| Graph RAG | 已进入变化链、投资逻辑证据、质量中心等主链；默认参与正式证据排序 | v6 盲测 14/14 门禁通过，Top-1、MRR、NDCG@5 均优于文本基线，四类泄漏为 0 | 已达到受控内部产品/试点级；尚未达到大规模、高 SLA 生产级 |
| 量化模块 | 已形成行情、信号、模板、因子、回测、持久化和前端工作台闭环 | 当前真实信号样本仍太少，只能证明链路可运行、结果可复算，不能证明稳定 Alpha | 工程产品化基本完成；研究有效性与生产运营成熟度尚未达标 |

一句话概括：**RAG 负责把证据排对顺序，量化负责把确认后的判断放进可复算实验；二者都不越过
人工决策闸门。**

## 1. 产品背景与共同约束

### 1.1 什么是“投资逻辑”

投资逻辑（Investment Thesis）是研究员对一家公司的核心判断，例如“产能释放和产品升级将推动
利润率改善”。一个投资逻辑通常继续拆成：

- **假设（Hypothesis）**：需要被事实持续验证的具体判断；
- **业务变量（Business Variable）**：影响假设成立与否的经营变量；
- **指标（Metric）**：可以观察和计算的量；
- **事实/观测（Fact/Observation）**：从公告、财报或其他资料中取得的当前证据；
- **证据关系（Evidence Relation）**：某条事实是支持、冲突还是中性，以及影响强度。

产品要求每家公司只维护一条当前投资逻辑，观点变化通过修订和不可变版本演进，而不是为同一公司
反复创建互相矛盾的平行卡片。

### 1.2 两个模块共享的六条硬约束

| 约束 | 在 RAG 中的含义 | 在量化中对应的含义 |
| --- | --- | --- |
| 不出交易指令 | 返回证据候选和解释路径，不改变持仓或状态 | 只做研究回测，不生成订单、评级或调仓指令 |
| 人工闸门 | 图关系和模型输出不能自动成为正式研究结论 | 只有人工确认关系才能冻结为正式量化信号 |
| 数值由程序计算 | RAG 负责检索和排序，不计算财务结论 | 收益、风险、成本、权重全部由 `app/calc` 确定性计算 |
| 结论可追溯 | 每个结果回到文档、切片 locator 和关系路径 | 每次运行绑定数据、信号、模板、因子、参数和方法版本 |
| 禁止未来信息 | 检索受 `as_of` 和披露时间约束 | 信号最早在生成后的下一可交易日生效，泄漏输入被拒绝 |
| 历史不可改写 | 图是关系事实源的只读快照 | 冻结数据与 QPF 运行只新增版本，不覆盖旧版本 |

### 1.3 零背景读者需要先理解的术语

| 术语 | 本项目中的含义 |
| --- | --- |
| RAG | Retrieval-Augmented Generation，先检索资料，再让模型基于可见证据解释或作答 |
| Graph RAG | 在文本相关性之外，用“逻辑—假设—变量—指标—事实—原文”的关系路径辅助排序 |
| locator | 原文定位符，可指向文档页、段落或切片，保证结论能回到原文 |
| 因子 | 把某类研究信息映射为可比较的数值特征；本项目当前 Alpha 输入是人工确认事件方向与强度 |
| Alpha | 相对基准的、可重复的超额收益能力；小样本正收益不等于已经证明 Alpha |
| 回测 | 在冻结历史数据上按固定规则重放信号，观察收益、风险和成本 |
| T+1 | 信号在生成时点之后的下一可交易日才可进入组合，避免使用当时不可得的信息 |
| Point-in-time | 某历史时点真实可得的数据，不能用今天知道的值倒填历史 |
| 中性化 | 从信号中剥离行业或市值等共同暴露，观察剩余部分；前提是截面和点时数据完整 |
| IC / Rank IC | 因子分数与未来收益的线性/排序相关性，用于判断区分度，不等于可交易收益 |
| Walk-forward | 按时间滚动训练和测试；当前系统输出固定模型的时间分段，尚不等于每窗重新拟合 |

# 第一部分：RAG 与 Graph RAG

## 2. RAG 要解决什么问题

### 2.1 仅靠关键词为什么不够

投资研究问题通常不是“文档里是否出现同一个词”，而是“这条事实是否能验证某个假设”。例如，
研究员查询“动力电池外供能否成为第二增长曲线”，真正相关的财报可能只写“外部客户收入、储能
业务增速、产能利用率”，与问题的字面重合有限；相反，标题里包含“电池”的治理公告可能字面匹配
很高，却不能验证该假设。

因此检索要同时处理四件事：

1. **覆盖**：不能因为图关系不完整而漏掉文本相关证据；
2. **排序**：与当前投资假设有明确关系的证据应更早出现；
3. **权限和时点**：用户无权查看或在历史时点尚未披露的资料不能进入候选；
4. **解释**：系统需要说明“为什么这条原文与当前假设相关”。

### 2.2 本项目的 RAG 边界

本项目的 Graph RAG 是**研究证据排序系统**，不是：

- 对全互联网开放的通用问答；
- 自动修改投资逻辑的自治 Agent；
- 用图数据库替代全部业务数据库；
- 自动确认事实和假设关系的裁决器；
- 对收益或价格作保证的预测模型。

关系型数据库仍是事实源。Graph RAG 在请求或评测时构建只读图投影，读取已经存在的文档、事实、
逻辑、假设和人工关系，用于受控检索与排序。

## 3. 从原文到可检索证据

### 3.1 数据进入

资料经过 `app/ingest` 进入系统，保留：

- 文档编号、证券编号、来源、标题和披露时间；
- 文档切片及 locator；
- 内容哈希、数据版本和可见性标签；
- 解析、去重和入库审计信息。

结构化事实、观测、财务指标和研究关系进入业务表。正式关系包含证券、投资逻辑、假设、原文证据、
方向、状态和人工确认信息。这样，检索结果不只是“一段相似文本”，而是可以回到业务语义与原文的
研究证据。

### 3.2 基础文本检索

项目保留多种文本召回器：

| 召回器 | 作用 | 当前特点 |
| --- | --- | --- |
| Keyword | 基础词元重合召回 | 简单、确定、可解释 |
| BM25 | 根据词频和文档频率排序 | 使用中文 n-gram，版本 `bm25-zh-ngram-v1[k1=1.2,b=0.75]` |
| ChineseVector | 本地字符哈希向量 | 无外部模型依赖，适合离线和降级 |
| Hybrid | 融合关键词、向量、公告先验和多样性 | 为全局搜索等路径提供稳健覆盖 |

保留文本召回非常重要：知识图不可能从第一天起就覆盖所有新文档和新关系。Graph RAG 的设计是
在文本候选池内改善排序和解释，而不是让图覆盖不足变成系统性漏召。

## 4. 五层投资知识图

### 4.1 分层模型

当前图 Schema 版本为 `investment-knowledge-layers-v2`，Graph RAG 算法版本为
`investment-graph-rag-v2-layered`。节点被组织为五个知识层：

| 层级 | 典型节点 | 回答的问题 |
| --- | --- | --- |
| 原始证据层 | Document、Segment | 原文在哪里、具体写了什么 |
| 事实观测层 | Observation、Fact、Evidence、Event | 当前发生了什么、测量值是什么 |
| 领域语义层 | Security、BusinessVariable、Metric | 事实属于哪家公司、哪个经营变量或指标 |
| 投资研究层 | Thesis、Hypothesis | 它验证了哪条投资逻辑和假设 |
| 聚合摘要层 | Summary | 如何聚合多个有来源的事实，便于概览 |

典型可追溯链路是：

```text
Thesis 投资逻辑
  → Hypothesis 假设
  → BusinessVariable 业务变量
  → Metric 指标
  → Observation / Fact 观测或事实
  → Document 文档
  → Segment / locator 原文位置
```

### 4.2 为什么强制“层级单调”

图遍历默认要求路径按知识层有序推进，避免从一个文本切片无边界地扩展到另一个不相关研究结论。
这是一项精度和安全约束：图可以从研究问题走向事实和原文，也可以从文本命中回溯受控关系，但不会
把任意同词节点当作等价关系。

### 4.3 图快照的构建和治理

`app/services/graph_rag.py` 从关系型业务数据构建只读投影。构建时保留：

- 图 Schema、构建时间和快照元数据；
- 节点的证券范围、披露时间和可见性；
- 边的关系类型、权重、确认状态与来源；
- 文档与切片 locator；
- 逻辑、假设、变量、指标、事实之间的业务编号。

默认只扩展已确认关系，`include_unconfirmed_edges=false`。候选关系可以被展示给研究员，但在人工
确认前不会以正式边参与主排序。

## 5. 查询、图遍历与 Evidence Fusion

### 5.1 查询种子

Graph Retriever 从三类种子开始：

1. 请求显式给出的 Thesis、Hypothesis、Security 等节点；
2. 查询词元与节点标签/内容的重合；
3. 文本召回已经命中的 Segment 节点。

这让查询既能从研究上下文出发，也能从新文档文本出发。

### 5.2 受限图遍历

当前默认参数：

| 参数 | 默认值 | 目的 |
| --- | ---: | --- |
| 最大跳数 | 5 | 覆盖典型“逻辑到原文”路径，防止无限扩散 |
| 跳数衰减 | 0.82 | 路径越长，贡献越小 |
| 每切片最多路径 | 3 | 防止一个结果用大量相似路径重复加分 |
| 最大扩展数 | 5,000 | 控制最坏情况下的计算量 |
| 层级单调 | 开启 | 阻止不合理跨层游走 |
| 未确认边 | 关闭 | 人工确认前不进入正式排序 |

单步路径分数按以下方式衰减：

```text
next_score = current_score × edge_weight × hop_decay
```

遍历同时应用四类硬过滤：

- `security_id`：不能从一家公司的逻辑跳到另一家公司的文档；
- `allowed_document_ids`：只能使用调用方已经获准访问的文档；
- `allowed_visibility`：遵守可见性标签；
- `as_of`：不能使用查询时点之后披露的事实或文档。

### 5.3 Evidence Fusion

正式发布策略为：

```text
graph-evidence-fusion-v1[
  rrf_k=1,
  text=0.25,
  bm25=0.5,
  graph=1,
  report_prior=1
]
```

它使用类似 Reciprocal Rank Fusion（倒数排名融合）的方式，将文本、BM25、图路径和高证据等级报告
的排名合并。简化表达为：

```text
fusion_score(document)
  = Σ channel_weight / (rrf_k + rank_in_channel)
    + report_prior
```

Graph 权重最高，但它只能在已授权、同证券、满足历史时点且属于候选池的结果中调整排序。每个结果
都可以保留检索版本、图快照和路径来源，便于解释与复算。

### 5.4 回退策略

如果图为空、关系覆盖不足或 Graph RAG 被关闭，系统保留文本/BM25 结果，不把“图暂不可用”变成
“用户看不到证据”。v6 已允许 Graph 正式参与排序，配置为：

- `rag_graph_enabled=true`；
- `rag_graph_assist_only=false`；
- Graph Retriever 兼容权重：文本 0.35、关系 0.65；
- `rag_graph_max_hops=5`；
- 失败回退：text retrieval。

旧的 `graph-assist-rank-stable-v1` 保序辅助模式仍可用于兼容或排障，但不是当前默认发布策略。

## 6. 知识问答中的 RAG

### 6.1 意图路由

知识助手把问题路由为：

- `thesis_status`：投资逻辑组合状态；
- `thesis`：某条投资逻辑或假设；
- `financial`：财务指标；
- `general`：一般资料问题。

系统根据显式上下文、问题中的证券名称和最近对话确定证券与逻辑范围；只读取用户可见且在
`as_of` 时点存在的内容。最近最多使用 6 条历史消息，避免对话无限污染当前查询。

### 6.2 上下文组合

不同意图按优先级组合上下文：

- 投资逻辑问题：结构化逻辑上下文 → Graph 路径上下文 → 文本命中；
- 财务/一般问题：财务上下文 → 结构化上下文 → 文本命中；
- 每次最多 8 个上下文；
- 只有 Thesis 意图、且同时确定 Thesis 和 Security 时才启用 Graph QA。

当前检索版本以 `intent-routed-hybrid-v2[...]` 记录。当没有可用证据时，服务返回
`insufficient_evidence`，不会让大模型凭空补答案。

### 6.3 引用与输出门禁

知识助手不是“模型说完就展示”。输出必须满足：

- 引用只能来自本次用户可见候选；
- 支持或部分支持的回答必须有 citation；
- 正文中的 `[S#]` 标记必须与返回的 citation 集合精确对应；
- 无证据或引用校验失败时降级；
- 请求编号、答案编号、检索版本、上下文和失败原因进入审计。

需要注意：`knowledge_qa_graph_enabled=true` 表示一旦知识问答启用可以使用 Graph；但全局
`knowledge_qa_enabled=false` 仍是当前默认值。因此知识问答代码链路已经具备，默认产品环境不会
因为模型服务故障影响主研究流程。

## 7. Graph RAG 当前在产品里用到哪里

| 产品位置 | 当前作用 | 当前状态 |
| --- | --- | --- |
| 变化处理链 `app/workers/change_chain.py` | 对变化事件命中的证据进行图增强排序，生成可追溯候选 | Graph 默认开启 |
| 投资逻辑证据/草稿 `app/api/routers/thesis.py` | 在 Thesis 和 Security 范围内补充关系路径和证据顺序 | 已接入，仍需人工确认 |
| 证据详情与检索轨迹 | 展示原文、locator、检索版本、图快照和关系路径 | 已实现可审计信息 |
| 质量中心 `/quality` | 展示 v6 指标、发布门禁和安全结论 | 已进入产品可见质量口径 |
| 知识助手 `/api/assistant/answers` | Thesis 意图下组合结构化、Graph 和文本上下文 | 代码已接入；全局开关默认关闭 |
| 全局搜索/财务搜索 | 仍以混合文本检索或结构化数据为主 | 并非所有检索都强制经过 Graph |

因此，“Graph RAG 已应用到产品”是准确的；“产品里所有搜索和回答都由 Graph RAG 处理”则不准确。

## 8. Graph RAG 当前效果

### 8.1 评测设计

当前正式发布证据是 `graph-relevance-v6-blind`：

- 30 个正例查询；
- 覆盖 9 家证券；
- 300 条已判定候选；
- 独立一次性盲测；
- 文本基线与 Graph RAG 使用同一候选池；
- 未标注结果硬失败；
- 金标不用于图构建；
- 阈值在运行前冻结。

这套设计主要避免两类常见误判：一是 Graph 通过扩大或改变候选池“看起来更好”，二是开发人员
反复查看盲测结果后继续调参。

### 8.2 核心指标

| 指标 | 文本基线 | Graph RAG v6 | 变化 | 应如何解释 |
| --- | ---: | ---: | ---: | --- |
| Recall@5 | 0.8303 | 0.8247 | -0.0056 | 前五覆盖轻微下降，但在允许回退阈值内 |
| MRR | 0.8222 | 0.8983 | +0.0761 | 第一条相关证据平均出现得更早 |
| NDCG@5 | 0.7385 | 0.8076 | +0.0691 | 前五名中高相关证据的顺序更合理 |
| Top-1 正确率 | 0.6667 | 0.8333 | +0.1666 | 首位正确率提高约 16.66 个百分点 |
| 路径来源完整率 | — | 1.0000 | — | 相关命中都能给出合法关系路径 |
| 候选池合规率 | — | 1.0000 | — | Graph 没有越界添加候选 |

Graph RAG 的效果主张应聚焦**排序质量**，不能声称“召回全面提升”。Recall@5 从 83.03% 变为
82.47%，虽然通过“不比文本下降超过 1 个百分点”的门禁，但它不是提升项。真正显著改善的是首位
证据、MRR 和 NDCG@5。

### 8.3 安全门禁

| 门禁 | v6 结果 |
| --- | ---: |
| 权限泄漏 | 0 |
| 跨证券泄漏 | 0 |
| 未来信息泄漏 | 0 |
| Canary 内容泄漏 | 0 |
| 未标注结果 | 0 |
| 官方门禁 | 14/14 通过 |

`outputs/graph-rag-v6-activation-decision.json` 据此给出
`official_rollout_ready=true`，允许 Graph Evidence Fusion 参与默认排序。

### 8.4 历史版本不能做简单纵向比较

| 版本 | Recall@5 | MRR | NDCG@5 | Top-1 | 门禁 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v3 | 0.7832 | 0.8367 | 0.8088 | 0.6667 | 10/12 |
| v4 | 0.5143 | 0.5658 | 0.4383 | 0.3667 | 7/12 |
| v5 | 0.6372 | 0.8062 | 0.6541 | 0.7000 | 12/14 |
| v6 | 0.8247 | 0.8983 | 0.8076 | 0.8333 | 14/14 |

不同版本的候选池、金标、查询和协议发生过变化，因此这张表只能说明研发收敛过程，不能把 v3→v6
直接解释为同一测试集上的单调提升。正式答辩应以 v6 与其同版文本基线的对照为主。

### 8.5 已知错误形态

v6 仍有需要继续优化的失败查询，主要包括：

- 同主题公告和摘要重复，占用 Top-5 位置；
- 某些查询相关候选超过 5 条，Recall@5 理论上无法达到 1；
- 个别查询 Graph 与文本拥有相同错误 Top-1，关系路径没有纠正首位；
- 图关系覆盖仍依赖已有结构化研究数据和人工确认质量。

## 9. Graph RAG 是否达到产品级

“产品级”需要拆成三个维度：

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 功能产品化 | 是 | 已接入主业务链、权限/时点/人工闸门、审计和产品质量中心 |
| 受控效果发布 | 是 | v6 盲测 14/14，通过排序、来源和安全门禁 |
| 大规模生产运营 | 尚未完全达到 | 线上延迟、自动降级、容量、缓存、真实用户效果和 SLA 证据不足 |

因此更准确的结论是：

> 当前 Graph RAG 已达到**受控内部产品/试点级**，可以在保留文本回退和人工复核的条件下默认启用；
> 但尚不能把它定义为已经完成大规模、高并发、高 SLA 生产化的通用知识基础设施。

### 9.1 还需要重点完善什么

按优先级建议：

1. **集成环境复验**：在最终答辩/试点部署版本重跑权限、时点、候选池和降级链路，而不只依赖离线文件；
2. **线上可观测性**：记录 Graph 构建耗时、检索 P50/P95、图空率、回退率、超时率、路径覆盖率；
3. **统一降级协议**：为超时、图构建失败、关系覆盖不足增加明确 `fallback_reason`、熔断和恢复策略；
4. **缓存与增量图**：按证券、逻辑版本和关系变更增量刷新，避免数据规模增长后每次重建；
5. **研究员真实反馈**：统计首位采纳率、找证据耗时、错误证据纠正率和人工接受/拒绝原因；
6. **扩大开放评测**：增加新公司、新行业、新时间段和开放候选池，避免只在当前闭池内表现良好；
7. **重复披露治理**：按主题、正文相似度和正式报告/摘要关系做簇级去重；
8. **知识问答灰度**：在开启全局 QA 前完成模型超时、引用一致性、敏感资料外发和故障演练。

# 第二部分：模型与因子量化模块

## 10. 量化模块要解决什么问题

### 10.1 定位

量化模块在产品中的名称是“模型与因子”，入口为 `/quant`。它不是交易系统，而是**研究验证层**：

```text
AI/规则发现变化
    → 研究员确认事实与假设关系
    → 方向、强度因子化
    → 冻结信号集
    → 与冻结行情和模型模板组合
    → T+1 确定性回测
    → 风险、成本、样本质量与可复算审计
```

它要回答的是“这套经过人工确认的研究规则，在严格时间与数据边界下呈现什么样的历史结果”，
而不是“明天应该买什么”。

### 10.2 为什么不能把 AI 置信度直接当仓位

AI 置信度描述模型对自己判断的确信程度，不代表经济影响的方向和大小。一个非常自信的错误判断反而
会被放大。因此主产品方法 `portfolio-research-v3` 的 Alpha 输入只使用人工确认的方向与强度：

```text
governed_score = direction_sign × strength_weight

支持 = +1     冲突 = -1     中性 = 0
高   = 1.0    中   = 0.7    低   = 0.4
```

例如“支持/高”得到 +1.0，“冲突/低”得到 -0.4，“中性/任意强度”得到 0。AI 置信度继续保存，
用于复核优先级和质量诊断，但 `alpha_weight_uses_ai_confidence=false`。

这些默认值只定义研究实验，不是建议仓位。

### 15.2 时间调度与未来数据防护

对每条信号：

1. 同时检查 `disclosed_at` 与 `generated_at`；
2. 如果生成时间早于披露时间，判定为潜在未来信息泄漏并拒绝；
3. 寻找严格晚于生成时间的第一个可交易行情日；
4. 只有在该日以后，信号才可以影响组合。

这意味着即使研究员在收盘后确认了一条公告，系统也不会把它放回当天开盘成交。

### 15.3 中性化

**行业中性**对每个行业的非零信号减去行业平均值。若一个行业只有一只非零信号，去均值会把它
静默变成 0，因此 v3 改为硬门禁：每个有暴露行业至少需要两只非零信号证券。

**市值中性**先对点时市值做横截面秩，再将信号对中心化市值秩做残差化。它要求：

- 纯 A 股同口径截面；
- 至少 3 只证券；
- 所有证券在该时点都有市值；
- Manifest 明确授权点时市值能力。

V4 不满足全量覆盖，所以服务层会返回 422，而不会用当前市值倒填。

### 15.4 从分数到目标权重

简化流程：

```text
人工确认分数
  → 可选行业/市值中性化
  → 按总绝对分数归一化
  → 单证券上限
  → 单行业上限
  → ADV20 容量上限
  → 停牌/涨跌停可交易性约束
  → 目标权重
```

不能交易时，系统不会假定“可以用收盘价随意成交”：停牌或不可用状态保留原位置；涨停不允许新增
买入，跌停不允许新增卖出。需要再次强调，V4 涨跌停能力当前因覆盖不完整而关闭，因此不能把现有
结果描述为已完成全量涨跌停模拟。

### 15.5 成本、收益与风险

每次仓位变化计算换手，并扣除：

```text
cost = turnover × (transaction_cost_bps + slippage_bps) / 10000
```

系统输出：

- 组合总收益、年化收益、年化波动和最大回撤；
- 有效暴露期基准与超额收益；
- 全区间基准与超额收益，作为现金期审计对照；
- 跟踪误差、信息比率、Beta；
- 换手、毛暴露、净暴露、容量、再平衡次数；
- IC、Rank IC、分层前瞻收益；
- 证券、行业和市场/市值/净暴露风险贡献；
- 滚动时间窗口明细。

有效暴露期口径很重要：信号出现前的长期现金期不能与全区间上涨的基准直接混成策略超额。系统同时
保留两组指标，既给出可比结果，也不丢失全区间审计。

### 15.6 当前 Walk-forward 的准确含义

当前输出按 60 日观察窗和 20 日测试窗分段报告，但模型与参数在各窗之间没有重新训练或重新选参。
因此它是“固定规则的滚动分段验证”，不是严格意义上的“每窗重新拟合模型”。真正的 refit
walk-forward 被协议设置为通过 research-candidate 样本门槛后才能启动，避免在极小样本上不断调参。

### 15.7 中性 0 分不等于清仓

当前正式 v3 的中性事件可把目标分数更新为 0，可能在再平衡时关闭此前位置。但研究语义上，
“本条证据中性”更接近“不改变已有判断”，不一定表示“撤销此前观点”。

答辩演示采用独立策略 `assumed-confirmation-neutral-noop-v1`：

- 中性事件仍留痕，因子贡献仍为 0；
- 不覆盖此前有效方向状态；
- 只有明确撤销、失效或关闭动作才归零。

该修正只用于隔离演示，没有静默改写 v3 历史运行。后续正式方法应增加
`event_action = update | no_op | close`，从契约上明确三种行为。

## 16. 不可变运行与 API

### 16.1 QPF 运行如何产生

每次组合实验把以下输入规范化：

```text
市场数据 Manifest 哈希
+ 信号内容哈希
+ 模型模板 ID/版本
+ 实际因子版本
+ 方法版本
+ 参数
+ 请求用户
        ↓ SHA-256
稳定的 QPF-* 运行 ID
```

相同输入重复请求会复用同一不可变记录，不覆盖历史；任一数据、信号、模板、因子或参数变化都会得到
新运行。数据库分别保存市场数据版本、信号版本和回测运行，并记录审计。

语义正确性、检索排序和 Alpha 验证使用不同评测轨道：

- `gold_semantic_accuracy`；
- `retrieval_ranking_quality`；
- `alpha_validation`。

量化表只接受 `alpha_validation`，避免把“模型抽取正确”误当成“策略有效”。

### 16.2 产品 API

所有路径前缀为 `/api/quant`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /demo-scenario` | 读取隔离的确定性答辩场景，默认关闭 |
| `POST /backtests` | 旧单证券兼容回测，不持久化主产品研究数据 |

新建验证页把完整研究范围分成三组：

1. **可回测**：行情与当前人工确认信号共同覆盖，可以勾选；

3. **信号就绪、待行情**：只读展示，等待受治理数据版本。

- 可回测 3：比亚迪、恒瑞医药、中芯国际；

## 18. 当前量化效果与演示数据

### 18.1 真实数据能证明什么

当前真实人工确认信号只有 3 条，覆盖 3 只可回测证券，远低于“20 只非零证券、100 个独立事件、
60 个有效交易日”的研究候选门槛。因此：

- 可以证明数据、信号、模板、因子和回测链路已经闭环；
- 可以证明相同输入产生相同 QPF 结果；
- 可以验证 T+1、成本、容量、权限、时间和样本门禁；
- 不能用当前收益评价策略稳定性；
- 不能宣称 AI、RAG 或事件因子已经创造 Alpha。

较早的真实 v3 对照只有两条确认信号，其中一条为中性，实际非零证券 1 只、前瞻观测 2 个、有效
暴露 12 日。虽然该区间组合收益为 -2.497787%、同期基准为 -3.803340%、同期超额为 +1.305553%，
质量仍是 `insufficient_sample`。正的同期超额只是对这 12 个交易日的描述，不可外推。

### 18.2 答辩演示为什么单独隔离

`/quant/demo` 使用真实 V4 冻结行情和同一个 `portfolio-research-v3` 计算引擎，但研究确认记录
是确定性构造的“假设全量确认”场景：

| 项目 | 演示值 |
| --- | ---: |
| 证券 | 30 |
| 交易日 | 667 |
| 信号截面 | 11 |
| 假设已确认事件 | 330 |
| 方向性信号 | 264 |
| 中性 no-op | 66 |
| 有效暴露日 | 547 |
| 前瞻收益观测 | 3,170 |
| 非零信号覆盖 | 30 只 |

方向按证券序号和截面序号固定轮换，不读取未来收益，不为了回测结果反向拟合。场景只在内存中计算，
不调用模型、不写数据库，也不与真实 Evidence、Relation、Signal Set 或历史运行混合。

所以答辩时可以说“30 只证券完整展示了工程能力和样本门禁”，不能说“330 条都是真实人工确认”或
“演示收益证明了 Alpha”。

## 19. 量化模块是否达到产品级

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 功能产品化 | 基本达到 | 页面、API、冻结输入、不可变运行、权限和样本门禁完整 |
| 数据工程 | 受控可用但有门禁项 | V4 资产哈希完整；点时市值和涨跌停因少量缺口关闭 |
| 研究有效性 | 未达到 | 真实信号只有 3 条，远低于前瞻协议最低门槛 |
| 生产运营 | 尚未达到 | 缺少长期漂移、数据中断、异常收益和正式试点运行证据 |
| 交易生产 | 不在产品范围 | 不连接券商、不产生订单 |

更准确的产品结论是：

> 量化模块已经达到“受治理研究实验产品”的工程完成度，但没有达到“可证明稳定 Alpha 的量化
> 策略产品”，也没有进入自动交易生产。

### 19.1 还需要重点完善什么

1. **持续积累真实前瞻信号**：达到至少 20 只非零证券、100 个独立事件和 60 个有效交易日；
2. **冻结验证与时间外样本**：严格执行 2027Q1 blind 和 2027-04-01 后 out-of-time 分区；
3. **补齐 V4 数据缓存**：让 19,960 个证券日的市值和涨跌停状态全量对齐后再开启能力；
4. **正式化 event action**：区分更新、无动作和关闭，修复“中性 0 分”语义歧义；
5. **真正 refit walk-forward**：通过样本门槛后，每个训练窗重新拟合，完整记录参数搜索；
6. **因子预注册与消融**：无中性、行业中性、市值中性、双中性四组冻结对照；
7. **加入稳定性分析**：按行业、时间、来源和市场环境报告覆盖、成本敏感性与失败案例；
8. **独立评审**：研究、数据授权和合规分别签署结论，自动门禁不能代替人工研究评审；
9. **试点监控**：只有 P2 通过后才启动纸面组合、数据中断、性能漂移、暂停和回滚机制；
10. **继续保持交易边界**：即使进入 P3，也只做内部模拟组合，不连接券商执行。

# 第三部分：两个模块如何形成完整研究闭环

## 20. 数据与决策流

```text
┌─────────────────────────────────────────────────────────────┐
│ 公开公告、财报、指标、研究资料                              │
└──────────────────────┬──────────────────────────────────────┘
                       ↓ 解析、切片、locator、权限、时间
┌─────────────────────────────────────────────────────────────┐
│ 文本/BM25 召回 + 五层知识图 + Evidence Fusion               │
│ 输出：证据候选、排名、关系路径、检索版本、图快照            │
└──────────────────────┬──────────────────────────────────────┘
                       ↓ 人工阅读与确认
┌─────────────────────────────────────────────────────────────┐
│ 正式 Evidence Relation                                      │
│ 证券、逻辑、假设、证据、方向、强度、披露/复核/生成时间      │
└──────────────────────┬──────────────────────────────────────┘
                       ↓ 冻结为 alpha_validation 信号集
┌─────────────────────────────────────────────────────────────┐
│ V4 行情 + 信号集 + 模型模板 + 因子版本 + 参数               │
└──────────────────────┬──────────────────────────────────────┘
                       ↓ portfolio-research-v3 确定性计算
┌─────────────────────────────────────────────────────────────┐
│ QPF 不可变运行：收益、风险、成本、样本质量、血缘与审计      │
└─────────────────────────────────────────────────────────────┘
```

RAG 与量化的共同设计思想是把不确定的 AI 输出限制在“候选与解释”层，把正式关系交给人，把所有
数值交给确定性程序，并用版本、哈希和审计将每一步串起来。

## 21. 两模块的风险不会互相抵消

RAG 排得更准不等于信号一定有收益；量化小样本结果为正也不等于 RAG 的语义判断正确。项目用三条
评测轨道刻意分离：

| 问题 | 应使用的评测 |
| --- | --- |
| 事件、方向和假设理解是否正确 | 独立语义金标 |
| 相关证据是否排得更早且没有泄漏 | RAG 排序与安全基准 |
| 冻结信号是否有样本外收益/风险区分度 | Alpha 前瞻验证 |

只有三者分别满足门槛，才可能形成可信研究结论。不能用其中一个分数替代另两个。

## 22. 当前总体成熟度判断

| 能力 | 当前阶段 | 可用于 | 不可用于 |
| --- | --- | --- | --- |
| 文本/混合 RAG | 稳定基础能力 | 搜索和 Graph 回退 | 无引用自由生成 |
| Graph RAG v6 | 受控内部产品/试点 | 默认证据排序、路径解释、质量审计 | 大规模 SLA 承诺、自动裁决 |

| 量化数据与引擎 | 受治理研究产品 | 可复算回测、风险/样本诊断 | 声称策略稳定有效 |
| 真实 Alpha 研究 | 前瞻积累初期 | 形成将来的研究样本 | 当前宣称 Alpha |
| 交易执行 | 明确排除 | 无 | 订单、评级、调仓、券商连接 |

## 24. 答辩建议结论

建议用以下四句话收束：

1. **RAG 不是替研究员下结论，而是在权限和历史时点内，把更相关的原文证据排到前面并给出路径。**
2. **Graph RAG v6 的主要收益是排序：Top-1 从 66.67% 提升到 83.33%，同时 14/14 门禁和四类零泄漏通过。**
3. **量化不是交易系统，而是把人工确认判断与冻结行情、模型、因子和参数绑定成可复算 QPF 实验。**
4. **量化工程闭环已经完成，但真实信号只有 3 条，当前不能宣称 Alpha；系统用硬门禁主动阻止越界结论。**

## 25. 常见问答

### Q1：为什么 Graph RAG 的 Recall@5 没有超过文本，还说有效？

因为目标不是无条件扩大召回，而是在基本保持覆盖的同时改善顺序。Recall@5 只下降 0.56 个百分点，
处于预先冻结的容忍范围；MRR、NDCG@5 和 Top-1 同时显著提升，说明正确证据更早出现。

### Q2：为什么没有直接使用图数据库？

当前关系型数据库是唯一事实源，只读内存投影已经满足受控规模的权限、时点和可追溯需求。等到图
容量、增量更新、缓存、P95 延迟和线上采纳率证明有必要后，再评估专用图基础设施更合理。

### Q3：Graph RAG 会不会把错误关系放大？

会，这是图检索的核心风险。因此主排序只使用已确认关系，候选边默认不扩展；还用同证券、权限、
`as_of`、候选池和路径来源门禁限制影响范围。最终研究关系仍由人确认。

### Q4：3 只可回测证券的结果能说明策略有效吗？

不能。它只能证明工程链路、时间规则、计算和版本审计可运行。正式研究候选至少要求 20 只非零证券、
100 个独立事件和 60 个有效交易日，并且达到后仍需独立评审。

### Q5：为什么 AI 置信度不进入量化权重？

置信度是模型对自身判断的把握，不是经济影响强度。将它作为仓位会放大“自信但错误”的模型输出。
产品只使用人工确认的方向和强度，置信度保留用于复核与诊断。

### Q6：为什么 V3 可以市值中性，V4 又关闭了？

V3 截止 2026-08-31，补充缓存与 19,930 个证券日全量对齐；V4 新增 2026-09-01 后达到 19,960
个证券日，市值缓存只有 19,930 条，涨跌停缓存只有 19,922 条。系统按新版本重新判断能力，覆盖
不完整就关闭，避免用旧值填补。

### Q7：答辩演示的 330 条事件是真实的吗？

不是。行情是真实冻结 V4，事件是为稳定演示按固定规则构造的“假设已确认”情景，只在内存中运行，
不写正式研究库。它用来展示完整流程，不能用于 Alpha 结论。

### Q8：产品下一步最重要的工作是什么？

RAG 重点是线上可观测性、自动降级、增量缓存和研究员真实采纳效果；量化重点是持续积累真实前瞻
信号、补齐 V4 数据、执行盲态与时间外测试，以及通过独立研究/数据/合规评审。
