## 1. 报告摘要

AI Investment Copilot 是面向主动权益研究团队的投资逻辑智能协作平台。产品不以“生成一条
买卖建议”为目标，而是把研究员对公司、行业或主题的判断转化为可验证的结构化投资逻辑，
并将后续公告、财报、经营数据和重要事件持续关联到具体假设，形成可追踪、可复核、可复盘
的人机协作过程。

第一阶段已经完成从产品原型到工程化 MVP 的主要建设，形成以下闭环：

```text
证券建档 → 创建投资逻辑草稿 → AI 辅助拆解 → 人工编辑与发布
    → 上传新资料 → 原件归档 → 解析、切片与事件抽取
    → 召回相关逻辑/假设 → 生成候选证据 → 人工确认或驳回
    → 生成状态建议 → 人工决定正式状态 → 版本、引用与审计留痕
```

阶段结论为：**产品核心对象和核心工作流已经成立，工程链路已达到可运行、可测试、可恢复、
可评测的 MVP 水平；尚未达到共享生产试点和效果扩量条件。** 下一阶段不应继续无边界增加
本地功能，而应优先建设正式身份与 RBAC、共享部署、监控告警、跨机器备份，并以真实研究员
小流量使用数据验证产品价值。

## 2. 项目背景与建设动因

### 2.1 业务背景

主动权益研究的核心产物不是资讯摘要，而是“为什么看好、依赖哪些前提、以后用什么事实验证、
什么情况下需要改变判断”。传统研究流程中，这些内容往往散落在研究报告、即时通讯、会议纪要、
个人笔记和表格中，存在以下典型问题：

1. 观点结构不统一，基金经理或研究主管难以快速理解判断依据。
2. 新资料与既有观点之间缺少稳定关联，研究员需要重复阅读和人工回忆。
3. 支持证据、冲突证据、预期和失效条件没有形成同一条证据链。
4. 正式观点变化缺少版本、原因和数据时点，事后难以复盘“当时为什么这样判断”。
5. AI 摘要容易越过业务边界，出现不可复算数值、无引用结论或替用户作投资决策。

### 2.2 产品定位

产品以 Investment Thesis（投资逻辑）为核心业务对象，以结构化逻辑卡片为主要载体，服务于
“创建—确认—跟踪—复核—复盘”的完整生命周期。

一句话定位：**帮助主动权益研究团队把投资观点转化为可验证的结构化投资逻辑，并将后续事实、
事件和指标变化持续关联到具体假设，形成可追踪、可复核、可复盘的研究过程。**

### 2.3 核心用户

| 用户 | 核心任务 | 第一阶段支持程度 |
| --- | --- | --- |
| 行业研究员 | 创建逻辑、维护假设、处理变化、复核证据 | 核心流程已实现 |
| 基金经理 | 快速理解观点、证据和重大变化 | 可查看逻辑、雷达和时间线；协作能力待增强 |
| 研究主管 | 管理覆盖、质量和复核 | 已有复核与裁决入口；团队管理待下一阶段 |
| 投管/风控/合规 | 检查权限、规则、引用和审计 | 基础权限与审计已实现；正式 RBAC 待建设 |

## 3. 项目目标与边界

### 3.1 第一阶段目标

第一阶段围绕五个目标展开：

1. 将投资判断结构化为标准逻辑卡片。
2. 将新增资料和变化关联到具体逻辑与假设。
3. 让 AI 只生成草稿和候选，由人工决定正式内容与状态。
4. 保存证据、引用、数据版本、模型版本、规则版本和人工动作。
5. 建立可以持续评测 AI 与检索效果的工程基础。

### 3.2 产品硬边界

| 边界 | 第一阶段落实方式 |
| --- | --- |
| 不输出交易指令 | 系统只输出候选证据、研究提示和状态建议，不输出买卖、评级或调仓指令 |
| AI 不自动发布 | AI 生成内容停留在草稿、候选或低置信状态 |
| 正式变化必须人工确认 | 发布逻辑、确认关系、处置状态建议均记录操作人和原因 |
| 数值必须可复算 | 同比、环比、预期差、趋势、分位和失效判定由确定性代码计算 |
| 结论必须可追溯 | 保存原文定位、披露时间、处理运行、模型/提示词/规则版本和审计记录 |
| 禁止未来信息 | 发生、披露、入库和生成时间分别保存，历史复算按当时可得信息裁剪 |
| 历史不可覆盖 | 原件、处理运行、逻辑版本和向量版本采用追加或新版本方式保存 |

### 3.3 不在第一阶段范围内的能力

- 自动交易、组合优化、仓位建议和评级生成；
- 全量新闻、行情和机构数据源自动接入；
- 自动因子挖掘、复杂回测或“证明 Alpha”；
- 代替研究员确定正式预期、阈值或投资结论；
- 公网生产部署、多租户计费和完整机构身份系统；
- 个人绩效评价或研究员排名。

## 4. 第一阶段建设过程

### 4.1 阶段一：领域模型与后端闭环

项目首先围绕投资逻辑、假设、指标、事件、证据、状态建议、版本和审计建立领域模型，完成
SQLAlchemy 持久化、Alembic 迁移、业务服务和 FastAPI 接口。此阶段确定了两条主链路：

- 建卡链路：资料或观点输入 → AI 草稿 → 人工编辑 → 发布 V1；
- 变化链路：新资料 → 事件抽取 → 假设匹配 → 候选证据 → 状态建议 → 人工处置。

### 4.2 阶段二：真实公开数据与规则验证

团队先使用阳光电源真实公开案例验证组合失效条件、口径冲突、时间裁剪和人工闸门，随后扩展
到芯片半导体、医药、新能源汽车三个行业的九家公司。该过程发现并修复了多项不会报错、但会
静默扭曲结论的缺陷，包括：

- “冲突/削弱”方向字面量不一致；
- 数值阈值 `0` 被错误当作空值；
- 建议记录对象与主键混用；
- 使用法定披露截止日近似实际披露日导致未来信息泄漏和期序碰撞。

这些问题已经转化为自动回归测试，避免同类错误重新进入主流程。

### 4.3 阶段三：前后端产品化

在后端闭环基础上，完成 React 网页 MVP，与 OpenAPI 契约联通，形成工作台、变化雷达、投资
逻辑、复核与复盘、资产治理五个主要入口，并补齐异步任务、真实数据库、模型网关、权限过滤、
任务重试和失败恢复。

### 4.4 阶段四：知识资产与交付闭环

第一阶段后半段补齐原件归档、文档修订、处理运行、衍生产物、权限索引、版本化逻辑修订、
备份恢复和本地一键环境，解决“功能能演示但资产无法长期维护”的问题。

### 4.5 阶段五：效果基线与受控 RAG 试点

在独立盲标基础上建立事件筛选、证券归属、假设匹配和方向判断四类效果指标，再引入 pgvector
和混合检索。RAG 默认关闭，只作为候选上下文试点，不改变鉴权、去重、计算、失效判断和人工
闸门。

### 4.6 阶段六：三分支集成与固定场景验收

第一阶段收口时，将后端/数据、AI 框架和 React 前端三条开发线合入统一分支。集成不是简单
覆盖文件，而是保留两条远端分支的父提交，并统一以下关键语义：

- 现有 PostgreSQL/pgvector 数据模型和权限优先 RAG 作为事实与检索主线；
- AI 分支的 Agent Runtime、四项版本化 Skill、证据质量校验、结构化修复和模型用量观察接入
  Worker 实际调用链；
- 正式 `web/` 继续作为通用产品前端，`web_demo/` 作为中芯国际 2023 年报重大风险固定场景；
- 状态建议的接受、拒绝和修改全部沿用主线严格人工闸门，三种动作都必须填写理由；
- AI 迁移顺接既有 `0010`，避免多 head；Docker 启动前初始化 WAL 归档卷权限。

固定场景以仓库内年报原件的 SHA-256 白名单校验输入，演示资料上传、预置 AI 候选、确定性
阈值计算、关系复核、状态决策、版本和时间线均走实际 API 与 PostgreSQL，不以 Mock 补造
真实模式结果。

## 5. 产品成果

### 5.1 投资逻辑管理

研究员可以：

- 建立证券主数据并选择研究对象；
- 从观点或资料创建投资逻辑草稿；
- 获取 AI 建议的标题、核心观点、关键假设、指标、风险和失效条件；
- 编辑假设、指标映射、方向、期限、负责人和复核日期；
- 在发布前查看逐项就绪检查；
- 人工发布正式 V1；
- 对已发布逻辑创建修订草稿、查看差异并发布新版本；
- 查看证据、状态建议、趋势、版本和审计时间线。

### 5.2 资料处理与变化雷达

产品支持上传 PDF、DOCX 和 TXT，资料进入持久化异步任务后完成：

1. 原件以 SHA-256 寻址存入版本化对象存储；
2. 创建不可变文档修订和处理运行；
3. 解析正文、扫描页和表格内容；
4. 生成带页码或文本定位的语义切片；
5. 抽取事件、数值、时间、主体和引用；
6. 进行证券归属和相关逻辑/假设匹配；
7. 生成支持、冲突或中性的候选证据；
8. 在变化雷达展示，由研究员确认、驳回、修改或暂不判断。

低置信、无法归属、解析失败和模型失败不会静默消失，而是进入复核、重试或死信流程。

### 5.3 状态复核与人工闸门

系统根据已确认证据、指标阈值、连续期数、组合条件和复核日生成状态建议。建议本身不会直接
修改逻辑状态；负责人必须选择接受、拒绝或修改，填写原因后才能形成正式状态、版本快照和
审计记录。

支持的状态包括：草稿、验证中、出现分歧、重大风险、已关闭。已关闭为终态，历史版本保持
只读。

### 5.4 研究资产治理

第一阶段已形成较完整的研究资产层：

- 原件保存在启用版本控制和 Object Lock 的 MinIO bucket；
- `document_revision` 保存不可变原件修订及内容哈希；
- `ingestion_run` 保存 parser、chunker、extractor 和 embedding 版本；
- `ingestion_artifact` 保存运行级切片、事实和事件产物；
- 权限感知检索索引可以从事实表重建；
- 文档删除采用墓碑并立即移出活动检索，受保留期保护的原件不被直接擦除；
- 已发布逻辑修订采用乐观锁与基线版本保护，旧版本不可覆盖。

### 5.5 页面与交互

| 页面 | 核心作用 | 主要操作 |
| --- | --- | --- |
| 工作台 | 汇总待处理变化、复核任务和风险 | 进入当前研究上下文、快速处理待办 |
| 变化雷达 | 展示候选证据与影响判断 | 筛选、查看原文、确认/驳回/修改关联 |
| 投资逻辑 | 管理逻辑列表和详情 | 建卡、编辑假设、发布、修订、状态处置 |
| 复核与复盘 | 汇总异常和人工队列 | 资料归属、低置信处理、任务重放、导师裁决 |
| 资产治理 | 管理研究资料与索引 | 资产盘点、权限同步、重处理、索引重建 |

除通用产品入口外，新增独立固定场景前端，覆盖“上传中芯国际 2023 年报 → 查看带引用 AI 候选
→ 复核证据关系 → 查看三项假设健康度 → 人工处置重大风险状态建议 → 生成版本与结构化时间线”。
该入口用于演示和验收，不替代通用 `web/`，也不把预置案例结果外推为普遍模型效果。

### 6.2 最新独立金标结果

独立金标版本为 `mentor-blind-gold-v2-20260811`，共 59 条：

| 任务 | 指标 | 结果 | 阶段判断 |
| --- | --- | ---: | --- |
| 事件筛选 | Precision | 96.3%（26/27） | 精度较高 |
| 事件筛选 | Recall | 86.7%（26/30） | 仍有 13.3% 漏检 |
| 证券归属 | Accuracy | 100.0%（59/59） | 当前样本通过 |
| 假设匹配 | Accuracy | 71.2%（42/59） | 需要继续提升 |

否则不能把单一标注人的判断直接视为最终业务真值。

### 6.3 RAG 试点结果

当前基线 embedding 为离线可复现的 `hash-char-2gram-v1`，256 维，不是生产级通用语义模型。
4,275 个活动切片已按处理运行和 embedding 版本建立独立向量。

| 方法 | Recall@5 | Recall@10 | MRR |
| --- | ---: | ---: | ---: |
| 关键词长查询基线 | 0.0% | 0.0% | 0.0000 |
| 关键词 + pgvector 混合召回 | 57.6% | 61.0% | 0.4136 |

Top-1 引用正确率为 30.5%，受限评测身份的越权结果为 0。当前结果只证明混合召回在此评测
口径下优于长查询关键词基线并满足无泄漏门槛，**不满足扩大自动化范围的质量要求**。

### 6.4 运营指标现状

第一阶段已经定义并能计算候选采纳、驳回、复核耗时、重复提醒和模型成本口径，但真实用户
处置数据尚未形成：

- 候选证据 292 条，已复核 0 条；
- 已复核子集的采纳率、驳回率和人工耗时保持 `null`，不能误写为 0；
- 持久化事件 fingerprint 重复提醒为 0/3,790；
- 5 次可计量模型调用包含 3,630 input tokens、1,174 output tokens；
- 未配置模型单价，因此成本保持 `null`。

## 9. 风险、限制与待决策事项

### 9.1 产品效果风险

1. 方向判断准确率仅 30.8%，不能自动决定证据方向或状态。
2. 假设匹配准确率为 71.2%，需要人工纠错和更好的检索/排序。
3. 当前 Top-1 引用正确率 30.5%，RAG 只适合作为候选上下文。
4. 尚无真实研究员处理 292 条候选证据，产品北极星指标尚不能计算。

### 9.2 数据与标注风险

1. 独立金标为单人盲标，缺少复标一致性。
2. 医药事件方向存在业务定义分歧，需要导师或领域专家裁决。
3. 历史 3,790 篇文档主要保留正文/URL，原件和授权不能由系统自动补造。
4. 部分公开数据存在披露时刻缺失、港股制度差异和口径不一致，需要保守处理。

### 9.3 工程与运维风险

1. 本地默认使用受信任请求头，不适合共享或公网部署。
2. 试点环境尚未完成 OIDC/JWT 身份接入、角色配置和多用户越权验证。
3. 本机备份恢复已通过，但跨机器复制、WAL/PITR 和定期演练未落地。
4. 缺少 Prometheus 指标、告警、分布式追踪、集中日志和容量测试。
5. 模型端点、对象存储和数据库密钥仍需接入机构密钥管理系统。

### 9.4 研究结论边界

项目现有信号实验不能支持以下表述：

- “AI 已证明能够稳定创造 Alpha”；
- “某类事件可以直接转化为交易信号”；
- 不考虑交易成本、可交易时点、停牌和基准口径的收益推断；
- 跨公司选股或个人研究能力评价。

## 10. 下一阶段建议

### 10.1 P0：试点部署安全与可观测性

1. 接入正式 OIDC/JWT 身份源和服务端 RBAC，移除共享环境受信任头。
2. 增加多用户、跨团队、文档删除后检索和对象访问的越权测试。
3. 建立 API、Worker、任务积压、重试、死信、模型调用、处理耗时和容量指标。
4. 固化共享试点部署、密钥注入、资源限制、滚动重启和故障恢复流程。
5. 建立跨机器数据库、WAL 和对象存储备份，并定期执行恢复演练。

### 10.2 P1：小流量业务验证

1. 邀请不少于 5 名研究员完成核心任务，记录任务完成率和反馈。
2. 对独立金标至少 20% 进行第二人复标并计算一致性。
3. 收集候选证据采纳率、驳回率、关联修改率、复核耗时和后续行动率。
4. 用正式中文 embedding 替换哈希基线，继续离线评测，不覆盖旧版本。
5. 只有在引用、权限和稳定性门槛通过后，才开启默认 5% 的事件→假设试点。

### 10.3 建议的下一阶段准入门

| 准入项 | 建议标准 |
| --- | --- |
| 身份与权限 | 共享环境使用正式身份；越权检索、摘要、引用和对象访问为 0 |
| 可恢复性 | 跨机器备份可恢复；数据库与对象哈希一致；恢复流程有演练记录 |
| 可观测性 | 关键依赖、积压、失败率和延迟均有指标与告警 |

| 标注可信度 | 至少 20% 双人复标并报告一致性 |
| RAG 安全 | 越权结果为 0，时间过滤无未来信息泄漏 |

## 11. 项目治理与协作建议

- `main` 保持受保护，通过 PR 合并；
- `contracts/`、数据库迁移、架构约束和产品/数据基线变更至少由一个消费方评审；
- 继续执行契约优先：后端接口变化先更新并导出 OpenAPI；
- 规则、提示词、模型、词典和数据集必须版本化，不直接覆盖历史结果；
- 效果报告必须同时给出分母、样本来源、时间切分、限制和不可外推范围；
- 线上代码不依赖离线分析代码，实验通过门槛后再迁移为受控能力；
- 重要业务裁决形成 ADR 或协作文档，避免规则只存在于口头沟通中。

## 12. 结论

第一阶段最重要的成果不是增加了一个资讯摘要页面，而是建立了一个围绕投资逻辑运转的研究
对象、工作流和数据治理基础：研究判断可以结构化，新增事实可以关联到假设，计算可以复算，
正式变化需要人工确认，历史结论可以根据当时可得信息回放。

工程侧已经完成通用网页 MVP、固定场景前端、后端服务、Agent Runtime、异步任务、数据库、
对象存储、版本、权限过滤、审计、备份恢复、独立评测和受控 RAG 试点。效果侧也明确暴露出
方向判断、引用正确率、标注一致性和真实用户数据不足等问题。这些限制不是报告附注，而是
下一阶段设计准入门的依据。

综合判断：**第一阶段达到“可进入安全加固与小规模业务试点准备”的状态，但不应直接视为
生产级投研平台，也不构成任何投资有效性证明。**
