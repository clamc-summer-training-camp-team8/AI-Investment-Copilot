# 排序 RAG 投资逻辑主题排序层执行方案

## 1. 文档目的

本文档用于指导在现有“证据与文档切片排序 RAG”之上，补齐投资逻辑主题排序层。

建设目标不是让 RAG 直接凭空生成投资观点，而是形成以下稳定链路：

```text
公司资料与指标
  → 召回事实和证据
  → 归纳候选投资逻辑主题
  → 聚合核心假设、指标、支持证据与冲突证据
  → 计算主题先验分并生成版本化排名
  → RAG 优先返回主主题及其完整证据包
```

完成后，系统应同时具备两层排序能力：

1. 主题排序：判断一家公司的哪些投资逻辑更适合作为当前主投资逻辑。
2. 主题内排序：判断支撑该逻辑的哪些证据、指标和文档切片应优先返回。

## 2. 当前基础与缺口

### 2.1 已具备能力

- 已覆盖三行业九家公司。
- 已存在投资逻辑、核心假设、证据、指标及文档切片。
- 已实现文档切片的关键词与向量混合召回。
- 已实现证据质量排序先验、时间边界、引用追溯和近似去重。
- 已建立排序快照及排序条目数据结构。
- 当前证据检索排序已通过第一轮 18 条盲测。

### 2.2 当前缺口

- 现有约 45 条投资逻辑尚未全部归一化为可比较的 `logic_topic`。
- 当前数据库构建脚本主要计算 `document_segment` 的排序先验。
- 尚未批量计算投资逻辑主题的八维特征。
- 尚未形成每家公司按方向、期限和时间点区分的主题排名快照。
- 当前 RAG 可以优先返回高质量证据，但不能稳定读取“排名第一的主投资逻辑”。

## 3. 核心设计原则

1. **RAG 负责证据召回，模型负责语义归纳，排序层负责主次选择。**
2. **规则能计算的字段不得完全交给模型主观评分。**
3. **模型评分必须附带理由、置信度和证据引用。**
4. **支持证据和冲突证据必须同时进入主题证据包。**
5. **排序必须具有公司、方向、期限、截止时间和版本语义。**
6. **历史快照不可静默覆盖，新材料只能生成新版本。**
7. **主题排序是决策支持，不自动改变正式投资逻辑状态。**

## 4. 目标数据模型

### 4.1 投资逻辑主题

将现有投资逻辑归一化为 `logic_topic`：

```json
{
  "topic_id": "TOPIC-00175-001",
  "security_id": "00175",
  "name": "新能源车型放量与产品结构升级",
  "normalized_statement": "新能源车型销量和高端车型占比提升，推动收入及盈利能力改善",
  "direction": "看多",
  "horizon": "12M",
  "status": "active",
  "source_thesis_ids": ["THESIS-001"],
  "created_at": "2026-08-24T23:59:59+08:00"
}
```

`topic_id` 必须由证券、标准主题表述及主题版本稳定生成，不得使用随机哈希。

### 4.2 主题关系

每个主题至少维护以下关系：

```text
LogicTopic
├─ source_thesis_ids
├─ hypothesis_ids
├─ metric_ids
├─ supporting_evidence_ids
├─ conflicting_evidence_ids
└─ document_segment_locators
```

关系记录至少包含：

- 关系方向：支持、冲突、中性；
- 关系置信度；
- 关系来源：规则、模型、人工或历史迁移；
- 有效时间范围；
- 引用定位；
- 模型与 Prompt 版本；
- 创建时间和审核状态。

### 4.3 主题排序快照

排序快照唯一作用域：

```text
security_id + direction + horizon + as_of + ranker_version
```

快照示例：

```json
{
  "security_id": "00175",
  "direction": "看多",
  "horizon": "12M",
  "as_of": "2026-08-24T23:59:59+08:00",
  "ranker_version": "logic-topic-prior-v1",
  "feature_version": "logic-topic-features-v1",
  "status": "provisional"
}
```

## 5. 主题标准化

### 5.1 输入范围

第一批直接处理现有九家公司约 45 条投资逻辑。

### 5.2 标准化规则

- 合并语义高度重复、方向和期限一致的逻辑。
- 拆分同时包含多个独立核心因果链的混合逻辑。
- 降级或排除只描述宽泛行业趋势、不能体现公司差异的表述。
- 每个主题必须包含驱动因素、影响对象和预期方向。
- 每家公司建议保留 3～5 个可比较主题。
- 看多、看空和中性主题不得因文本相似而直接合并。
- 不同期限主题分别维护，例如 3M 事件逻辑与 36M 结构性逻辑不直接比较。

### 5.3 标准化输出检查

每个主题必须满足：

- 有明确公司归属；
- 有明确方向；
- 有明确期限；
- 至少关联一个核心假设；
- 能够映射到事实或指标；
- 标准表述不能只是结论性口号。

预计 45 条原始逻辑标准化后形成约 27～40 个主题。

## 6. 主题关系聚合

### 6.1 自动映射

利用现有数据库关系完成第一轮映射：

1. 从原始投资逻辑取得已有核心假设。
2. 从核心假设取得 `HypothesisMetricMap`。
3. 从核心假设取得支持、冲突及中性证据。
4. 从证据取得可追溯文档切片。
5. 按公司、方向和截止时间过滤无效关系。

### 6.2 高级模型复核

高级模型只处理规则难以判断的语义关系：

- 证据是否真正支持该主题；
- 证据属于支持、冲突还是中性；
- 指标是否能够验证主题；
- 主题是否与其他主题重复；
- 因果链是否成立；
- 是否发生跨公司错误关联。

模型输出必须符合结构化 Schema：

```json
{
  "topic_id": "TOPIC-00175-001",
  "relation_decisions": [
    {
      "object_id": "EVD-001",
      "relation": "支持",
      "score": 0.86,
      "confidence": 0.82,
      "reason": "销量及核心利润数据直接支持产品放量和盈利改善",
      "citation_locators": ["DOC-001#paragraph-8"]
    }
  ]
}
```

无有效引用、引用越界或公司不匹配的判断不得进入正式主题关系。

## 7. 八维特征计算

所有特征归一化到 `[0, 1]`。

### 7.1 业务重要性，权重 25%

```text
business_materiality =
  40% × revenue_impact
+ 35% × profit_impact
+ 15% × cashflow_impact
+ 10% × valuation_impact
```

优先使用业务收入占比、利润贡献、盈利敏感性和管理层重点程度。缺少结构化数据时，由高级模型依据引用材料按统一评分锚点补充。

### 7.2 证据强度，权重 15%

```text
evidence_strength =
  35% × source_authority
+ 30% × direct_evidence_ratio
+ 20% × independent_source_consistency
+ 15% × evidence_completeness
```

计算前必须进行来源与内容去重，重复转载不得重复增加证据强度。

### 7.3 持续性，权重 15%

```text
persistence =
  40% × historical_continuity
+ 35% × expected_valid_horizon
+ 25% × structural_nature
```

历史连续性根据季度或月度指标连续同向期数计算；一次性收益和短期事件应降低得分。

### 7.4 可验证性，权重 15%

```text
verifiability =
  35% × metric_mapping_completeness
+ 25% × data_source_availability
+ 20% × validation_horizon_defined
+ 20% × invalidation_threshold_defined
```

无法关联指标、数据源、验证周期和失效条件的主题不得获得高分。

### 7.5 公司特异性，权重 10%

```text
company_specificity = 1 - industry_generality
```

通过同业主题相似度、公司专属实体和业务结构进行判断。只描述行业长期趋势的主题应降权。

### 7.6 因果关系强度，权重 10%

```text
causal_strength =
  30% × driver_clarity
+ 30% × intermediate_metric_completeness
+ 25% × outcome_direction_clarity
+ 15% × temporal_consistency
```

高分主题应能够形成：

```text
业务驱动 → 中间经营指标 → 收入/利润/现金流变化 → 投资结论
```

### 7.7 时效性，权重 5%

采用按资料类型区分半衰期的时间衰减：

```text
recency = exp(-age / half_life)
```

参考半衰期：

- 新闻与短期事件：30～90 天；
- 月度经营数据：3～6 个月；
- 季度财报：6～12 个月；
- 产能和产品周期：1～3 年；
- 长期竞争优势：根据主题版本单独配置。

任何证据的发布时间不得晚于快照 `as_of`。

### 7.8 反证覆盖，权重 5%

反证不能简单作为加分或减分项，应拆为：

1. `counter_evidence_coverage`：系统是否主动找到主要反证，作为基础分加分项。
2. `unresolved_conflict_severity`：反证是否足以削弱或推翻逻辑，作为额外扣分项。

冲突严重度考虑：

- 反证来源权威性；
- 是否直接攻击核心假设；
- 潜在财务影响；
- 是否连续发生；
- 是否已有更新证据解释或化解。

## 8. 主题评分公式

### 8.1 基础分

```text
base_topic_score =
  25% × business_materiality
+ 15% × evidence_strength
+ 15% × persistence
+ 15% × verifiability
+ 10% × company_specificity
+ 10% × causal_strength
+  5% × recency
+  5% × counter_evidence_coverage
```

### 8.2 冲突惩罚

```text
conflict_penalty = 20% × unresolved_conflict_severity
final_topic_score = max(0, base_topic_score - conflict_penalty)
```

第一版将最大冲突惩罚设为 20%，后续只能依据独立评测结果调整。

### 8.3 模型复核融合

规则基础分与高级模型复核分分开保存。建议初始融合方式：

```text
reviewed_topic_score =
  70% × deterministic_feature_score
+ 30% × model_judge_score
```

模型未复核时直接使用规则基础分，不得自动填充虚假模型分数。

## 9. 主投资逻辑准入条件

主题必须同时满足以下硬门槛，才可参与主投资逻辑排序：

```text
business_materiality ≥ 0.60
evidence_strength ≥ 0.50
verifiability ≥ 0.60
直接证据数量 ≥ 1
有效验证指标数量 ≥ 2
未来信息泄漏数量 = 0
无致命且未解决的反证
```

选择规则：

- 合格候选中 `final_topic_score` 最高者为当前主主题。
- 方向或期限明显不同且达到门槛的主题可作为备选主题。
- 页面默认只展示一个主主题，备选主题通过切换入口查看。
- 分数接近且证据冲突显著时，不强行确定唯一主主题，应标记为“存在竞争主题”。

## 10. 排序快照示例

```text
公司：吉利汽车
方向：看多
期限：12M
截止时间：2026-08-24
版本：logic-topic-prior-v1

1. 新能源车型放量与产品结构升级  0.84
2. 品牌整合与规模协同            0.76
3. 海外市场扩张                  0.68
```

每条排名必须保留：

- 基础分；
- 模型复核分；
- 最终分；
- 八维特征；
- 冲突惩罚；
- 排名理由码；
- 证据引用；
- 计算版本和时间边界。

## 11. 接入现有 RAG

查询公司投资逻辑时改为两阶段检索：

```text
第一阶段：按公司、方向、期限和 as_of 检索排名最高的主题
第二阶段：在主主题作用域内检索假设、指标、支持证据和冲突证据
```

建议向后续模型提供以下结构化上下文：

```json
{
  "primary_topic": {},
  "ranking_reason": {},
  "hypotheses": [],
  "supporting_evidence": [],
  "conflicting_evidence": [],
  "metrics": [],
  "invalidation_conditions": [],
  "alternative_topics": []
}
```

默认完整返回第一主题；第二、第三主题只返回摘要，避免多条逻辑抢占生成上下文。

## 12. 新材料增量更新

新公告、新闻、研报或指标入库后执行：

1. 判断所属公司和可见时间。
2. 关联已有主题、核心假设和指标。
3. 无法关联且信息重要时创建候选新主题。
4. 更新支持、冲突及中性证据集合。
5. 重算受影响主题的八维特征。
6. 生成新的排序快照，不覆盖历史快照。
7. 比较新旧主题排名及分数变化。
8. 重大冲突、主主题切换或低置信结果进入研究员确认界面。

新主题不得因单条新闻直接成为主主题，除非达到主逻辑全部准入条件。

## 13. 主题排序评测集

现有 18 条证据检索盲测不能替代主题排序评测，需要新增独立主题金标。

第一版建议：

- 覆盖九家公司；
- 每家公司 3～5 个主题；
- 每家公司至少 3 组主题比较；
- 总计不少于 45 组比较样本；
- 覆盖支持、冲突、短期和中长期场景；
- 增加新证据前后重排样本。

评测指标：

- 主主题 Top-1 一致率；
- Top-3 覆盖率；
- 不同查询措辞下主主题稳定率；
- 支持证据新增后的合理上升率；
- 重大反证新增后的合理下降率；
- 引用可追溯率；
- 未来信息泄漏数量；
- 跨公司错误关联数量。

第一阶段建议门槛：

```text
主主题 Top-1 一致率 ≥ 75%
Top-3 覆盖率 ≥ 90%
引用可追溯率 = 100%
未来信息泄漏数量 = 0
跨公司错误关联数量 = 0
重大反证触发重排率 = 100%
```

## 14. 实施阶段

### 阶段一：数据结构与迁移

1. 增加 `logic_topic` 实体。
2. 增加主题与 Thesis、Hypothesis、Metric、Evidence 的关系表。
3. 扩展排序快照对 `logic_topic` 的持久化支持。
4. 增加稳定主题 ID 和版本规则。
5. 增加时间、方向、期限及公司一致性约束。

交付物：数据库迁移、领域模型、Repository 和基础测试。

### 阶段二：现有主题标准化

1. 导出现有约 45 条投资逻辑。
2. 批量形成标准主题候选。
3. 合并重复主题并拆分混合逻辑。
4. 自动建立主题与现有假设、指标、证据的关系。
5. 生成九家公司主题覆盖报告。

交付物：主题数据集、映射结果、缺失关系清单和覆盖报告。

### 阶段三：特征与排序计算

1. 实现八维确定性特征计算器。
2. 实现反证覆盖和未解决冲突惩罚。
3. 接入高级模型语义复核。
4. 校验模型引用、公司边界和时间边界。
5. 生成首版主题排序快照。

交付物：评分脚本、Schema、排序快照和九家公司排名报告。

### 阶段四：RAG 集成

1. 增加主题检索接口。
2. 增加“主主题 → 假设 → 证据 → 指标”二阶段召回。
3. 输出结构化主题上下文包。
4. 保留当前纯文档检索接口以便回归对比。
5. 增加权限、去重、时间裁剪和引用检查。

交付物：API、服务层实现、契约测试及集成测试。

### 阶段五：评测与调权

1. 建立不少于 45 组的主题排序金标。
2. 对比无主题先验、规则先验和规则加模型复核三种方案。
3. 统计 Top-1、Top-3、稳定率、重排率和泄漏指标。
4. 针对失败案例调整特征生成方式。
5. 权重调整必须升级 `ranker_version`。

交付物：评测集、评测脚本、实验结果和上线门禁结论。

## 15. 推荐执行顺序

1. 建立主题实体及关系表。
2. 标准化现有 45 条投资逻辑。
3. 挂接现有核心假设、证据和指标。
4. 计算规则基础分。
5. 使用高级模型进行语义复核。
6. 生成九家公司首版主题排名快照。
7. 接入主题优先的两阶段 RAG。
8. 建立主题排序金标并运行评测。
9. 根据失败案例调优并冻结正式版本。

## 16. 完成定义

同时满足以下条件，才视为主题排序层完成：

- 九家公司所有有效投资逻辑均已标准化为主题；
- 每个主题至少关联一个假设、两个指标和一条直接证据；
- 每个主题均有支持及冲突检索结果或明确的缺失说明；
- 八维特征、基础分、冲突惩罚和最终分均可复算；
- 排序快照具备公司、方向、期限、截止时间和版本语义；
- RAG 可以返回一个主主题及其结构化证据包；
- 主题排序评测达到既定门槛；
- 引用可追溯率为 100%；
- 未来信息泄漏和跨公司错误关联均为 0；
- 历史快照可以按当时可得信息回放。

完成该层后，排序 RAG 将从“证据有序”升级为“投资逻辑主题有序，主题内部证据也有序”，为后续稳定形成一条主投资逻辑提供可复用的知识库先验。
