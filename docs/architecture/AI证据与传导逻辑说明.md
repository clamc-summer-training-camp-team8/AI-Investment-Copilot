# 证据验证与投资逻辑传导说明

## 1. 核心原则

对新事件进行投资影响分析时，不能直接让模型从检索结果跳到“支持/削弱假设”的结论。应先验证事实证据，再分析事实如何通过业务变量和指标影响投资假设。

```text
检索信息
  -> 事实证据验证
  -> 传导逻辑分析
  -> 假设影响判断
  -> 人工复核
```

## 2. 第一层：事实证据验证

检索到的信息首先要经过以下检查：

### 2.1 准确性

- 来源是否权威，例如巨潮资讯、公司公告、正式财报。
- 原文中是否存在对应表述。
- 内容是否被错误截断、拼接或模型改写。
- 事实和模型推断是否明确分开。

### 2.2 可回溯性

每条事实都应保留：

- `document_id`
- `locator`
- 原文片段
- 来源名称和 URL
- 发布时间
- 解析器版本或内容哈希（数据管道具备后）

引用必须能够定位回原始段落、页码或网页位置。

### 2.3 时效性

- 文档发布时间不能晚于本次分析的 `as_of` 时间。
- 判断资料是否超过有效时间窗口。
- 检查资料是否被后续公告修正、撤回或替代。
- 区分事件发生时间、披露时间和入库时间。

### 2.4 实体匹配和权限

- 信息必须属于目标证券或明确相关的行业/宏观范围。
- 未授权或权限不明确的资料不能进入 Prompt、摘要或正式引用。
- 行业新闻不能未经判断直接当作公司事实。

## 3. 第二层：传导逻辑分析

事实证据通过业务变量和指标影响投资假设，推荐使用以下链路：

```text
事实事件
  -> 业务变量
  -> 财务/经营指标
  -> 投资假设
  -> 支持、削弱、中性或不确定
```

示例：

```text
公司公告新签订单增加
  -> 在手订单增加
  -> 未来收入可能增加
  -> 核心业务收入持续增长假设
  -> 支持
```

传导逻辑需要检查：

- 中间环节是否完整。
- 事实是否只能说明“可能支持”，而不是直接证明假设成立。
- 是否存在相反证据。
- 影响时间范围是否与假设一致。
- 影响强度是否被夸大。
- 事实与假设之间是否只是相关，而不是有充分依据的因果关系。

## 4. 两类结果必须分开

### 4.1 证据质量

字段建议：

```text
evidence_score
```

表示事实是否可靠、可回溯、及时、匹配目标实体。

当前代码中的 `EvidenceAgent` 和 `EvidenceGrade` 主要负责：

- 引用是否存在。
- locator 是否来自检索结果。
- 是否有越界引用。
- 是否存在 `unsupported_claims`。
- 引用数量和来源数量。
- 证据是否过期。

当前这仍是“证据完整性评分”，不等同于事实真实性证明。

### 4.2 影响判断

字段建议：

```text
impact_direction
impact_strength
impact_confidence
transmission_path
```

表示新事件对目标 Hypothesis 的影响：

- 支持
- 削弱/冲突
- 中性
- 不确定

这部分由 `InvestmentLogicChangeAgent` 调用 Gateway/Provider 生成，但仍需人工确认。

## 5. 推荐运行流程

```text
RAG 检索
  -> 来源权威性检查
  -> 原文引用和 locator 校验
  -> 时间、权限、证券匹配
  -> 形成标准化事实
  -> 建立事实到指标的传导路径
  -> 分析对 Hypothesis 的影响
  -> 输出证据质量和影响判断
  -> 低置信度或证据不足时人工复核
```

## 6. 当前项目实现状态

### 已实现

- `KeywordRetriever` 基础检索。
- 证券、时间和可见性过滤。
- Agent 事件影响分析。
- 引用 locator 校验。
- 引用越界检查。
- `unsupported_claims` 检查。
- 证据完整性评分。
- `evidence_score` 与影响判断在概念上分开。
- 统一 Agent Runtime 和人工复核状态。

### 尚未完整实现

- 原文事实与模型摘要的一致性校验。
- 多条证据之间的冲突检测。
- 后续公告对旧事实的修正判断。
- 传导逻辑路径的独立可信度评分。
- 关键词与向量混合检索。
- PostgreSQL + pgvector 的生产化 RAG。

## 7. 汇报时可使用的表述

> 我们的 Agent 不会直接根据检索结果生成投资结论。第一步先验证信息的来源、准确性、可回溯性、时效性和实体匹配；第二步再分析事实如何通过业务变量和指标传导到具体投资假设；最后分别输出证据质量和事件影响判断，并将低置信度、引用异常或逻辑不清的结果交给研究员复核。

## 8. 维护规则

以后修改以下代码时，需要同步维护本文档的“当前项目实现状态”和流程说明：

- `app/ai/retrieval.py`
- `app/ai/agent.py`
- `app/ai/runtime.py`
- `app/ai/gateway.py`
- `app/ai/contracts/`
- `app/ai/providers/`

每次变更至少记录：

1. 新增或改变的证据字段。
2. 事实验证规则是否变化。
3. 传导逻辑判断是否变化。
4. 评分或人工复核条件是否变化。
5. 测试和评测结果。
