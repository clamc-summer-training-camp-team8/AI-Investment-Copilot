## 1. 执行摘要

当前 GraphRAG 已经不是概念验证或静态演示。项目已经实现五层只读知识图、确定性多跳检索、
文本/BM25/Graph Evidence Fusion、权限与历史时点过滤、可验证图快照、检索追踪和离线发布门禁；
代码默认开启 GraphRAG 与 Evidence Fusion，并已经在共享集成环境的资料变化链中真实参与候选
证据排序。

v6 专业研究员一次性盲测 14/14 门禁通过，GraphRAG 的 Top-1、MRR 和 NDCG@5 明显高于同版
文本基线，路径来源和候选池合规率均为 1.0，四类安全泄漏均为 0。GraphRAG 当前最明确的产品
价值是改善首位证据质量、关系解释和审计能力，而不是扩大原始召回覆盖。

当前成熟度应统一表述为：

> GraphRAG 已达到“功能产品化、离线质量门禁通过、共享环境闭环验证”的受控试点阶段；在真实
> 研究员效率、线上确认率、P50/P95 延迟、容量、异常自动回退和长期运行数据完成验证前，不能
> 宣称已经达到规模化生产级。

后续应继续完善，但优先级应从继续堆叠图算法转向线上观测、容错、缓存与容量、开放语料评测和
人工反馈闭环。当前没有充分证据支持立即引入图数据库或 Agentic RAG。

### 1.2 还需要重点完善什么

下一阶段不应把主要资源投入到继续增加图层、无依据地提高 Graph 权重或立即更换图数据库，而应
优先补齐以下六类产品化证据和工程能力。

| 优先级 | 重点完善项 | 要解决的问题 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 最终集成版本再验收 | 现有共享环境成功记录不是在三分支最终合并提交上重跑 | 最新集成版本完成迁移、账号、存储、worker、变化链和 Graph trace 全链路验收 |
| P0 | 自动容错与降级 | Graph 超时或异常时不能依赖人工切开关 | 所有调用点有独立超时、异常捕获、熔断、文本回退和 `fallback_reason` |
| P0 | 性能、容量与可观测性 | 当前缺少全量规模和尾延迟证据 | 有建图/检索 P50、P95、内存、节点/边、扩展状态、降级率和告警基线 |
| P0 | 快照缓存与失效 | 按请求建图可能成为性能瓶颈 | 以快照、证券、时点和权限范围为键的有界缓存通过一致性与失效测试 |
| P1 | 真实研究员效果闭环 | 离线相关性不等于实际节省时间或提高判断质量 | 持续统计采纳率、拒绝原因、改引率、确认耗时、误导率和文本回退行为 |
| P1 | 扩大评测与数据治理 | 9 家公司、30 个问题和封闭候选池不能代表全量业务 | 增加行业、长尾公司、开放语料、双人标注，并建立关系与 locator 覆盖看板 |

最需要优先解决的不是“GraphRAG 能不能检索”，而是：

1. 在最新集成版本和真实部署条件下是否稳定；
2. 出错时是否能自动、可观测地退回文本路径；
3. 数据量和并发增长后是否仍满足延迟与资源预算；
4. 研究员是否真正更快找到、确认并采用高质量证据；
5. 所有线上决策是否能按检索版本、图快照和原文位置复现。

完成 P0 后，GraphRAG 才具备从受控试点进入生产放量评审的基础；完成一段时间的 P1 线上验证后，
才有充分依据讨论规模化生产级和 SLA。更详细的验收任务见第 10 节。

## 2. GraphRAG 的定位与边界

### 2.1 它是什么

当前实现 `investment-graph-rag-v2-layered` 是面向投资研究工作流的确定性检索增强层。它把
关系库中已经存在的证券、投资逻辑、假设、业务变量、指标、指标观测、事件、证据、文档和原文
片段投影为只读内存图，通过可解释关系路径找到能够回到 locator 的原文证据。

产品当前遵循“一家公司维护一条当前投资逻辑”。GraphRAG 的任务不是在同一公司内竞争多条逻辑，
而是围绕唯一逻辑解释：

- 假设依赖哪些业务变量；
- 业务变量由哪些指标衡量；
- 指标和事实来自哪些披露；
- 新证据如何支持、冲突或补充当前假设；
- 最终引用如何回到原始文档片段。

### 2.2 它不是什么

当前 GraphRAG：

- 不是通用知识问答系统；
- 不是模型自行规划、循环检索和创建关系的 Agentic RAG；
- 不是 Neo4j、NebulaGraph 等图数据库架构；
- 不创建新的业务事实源；
- 不自动确认候选证据；
- 不自动改变投资逻辑、假设、证据关系或状态；
- 不承担财务数值计算、预期差计算或投资结论生成。

关系库和不可变原文仍是事实源。Graph 只读投影正式对象，默认只使用已确认的指标映射、证据关系
和引用；待确认关系只有显式设置 `include_pending=true` 才会进入图，并继续携带未确认标记。

## 3. 核心原理

### 3.1 五层投资知识图

GraphRAG 用分层图表达“研究结论如何回到原始披露”，各层职责如下。

| 层级 | 主要对象 | 作用 |
| --- | --- | --- |
| 原始证据层 | 文档、原文片段、locator | 保留不可变原文和可核验引用位置 |
| 事实观测层 | 事件、事实、指标观测 | 表达在特定时间发生或披露的客观变化 |
| 领域语义层 | 业务变量、指标 | 把业务含义和可量化口径连接起来 |
| 投资研究层 | 证券、投资逻辑、假设、证据 | 表达研究员的判断结构及证据关系 |
| 聚合摘要层 | 主题、摘要等预留对象 | 为跨文档聚合预留，目前不是主要检索依赖 |

典型的可解释路径是：

```text
投资逻辑 → 假设 → 业务变量 → 指标 → 指标观测/事实 → 文档 → locator
```

默认检索遵循单调分层遍历，避免路径在高层研究结论与低层原始证据之间无约束往返，从而压缩
搜索空间并减少语义漂移。

### 3.2 只读图投影

`GraphRagCorpus` 按确定顺序把关系库正式对象投影为节点和边：

1. 建立 `Security → Thesis` 主干；
2. 建立 `Thesis → Hypothesis → BusinessVariable` 研究结构；
3. 加入已确认的业务变量—指标映射、指标观测及其来源文档；
4. 加入已确认的证据、事件、引用片段和事实关系；
5. 连接事实、指标和受控词汇；
6. 对节点、边和语料生成稳定哈希，形成可验证图快照。

投影在单次任务或请求内以内存图运行。当前实现没有证明能够在一个进程中长期承载全市场全量图，
也没有增量建图和跨请求共享缓存，因此不能把“完成图投影”理解为已经解决生产容量问题。

### 3.3 种子选择与路径检索

检索种子有三类：请求显式给出的对象 ID、查询词与图节点文本的重合、由文本检索命中的原文片段。
路径扩展综合种子分、边权和跳数衰减，并用层级方向约束允许扩展的边，核心分数可写为：

```text
next_path_score = current_path_score × edge_weight × hop_decay
```

当前默认限制包括：最大 5 跳、跳数衰减 0.82、最多扩展 5,000 个状态、保留 3 条主要路径，
默认不纳入未确认关系并启用单调分层约束。只有最终能够回到 locator 原文片段的路径才作为
Graph 证据候选返回，防止只给关系结论却无法核验来源。

### 3.4 Evidence Fusion

最终排序融合文本召回、BM25 和 Graph 路径三路名次，并加入报告类型先验：

```text
score =
    0.25 / (1 + rank_text)
  + 0.50 / (1 + rank_bm25)
  + 1.00 / (1 + rank_graph)
  + report_prior
```

这是按名次融合的 RRF 变体，不直接比较不同检索器不可比的原始分数。Graph 权重最高，用于把
能沿正式关系回到原文的证据前置；文本和 BM25 继续承担覆盖与自然回退。早期
`graph-assist-rank-stable-v1` 排序仍保留为兼容路径，当前默认发布策略使用
`graph-evidence-fusion-v1`。

### 3.5 权限、时间与审计

建图和检索共同执行以下边界：

- `allowed_document_ids` 限制当前账号可访问的文档；
- `security_id` 防止跨公司混入；
- `allowed_visibility` 执行可见性范围；
- `as_of` 阻止历史时点之后的信息泄漏；
- 已保存 trace 记录候选来源、路径、分数、版本和快照哈希。

因此 GraphRAG 的可解释性不只是一段自然语言说明，而是“检索版本 + 图快照 + 关系路径 +
原文 locator”的可复现证据链。

## 5. 产品中的应用程度

### 5.1 已进入三分支集成基线的能力

| 产品场景 | GraphRAG 的作用 | 当前状态 |
| --- | --- | --- |
| 资料变化链 | 对新资料候选证据进行关系增强排序，生成可核验路径 | 已真实接入，默认启用 |
| 投资逻辑草稿 | 在显式开关下为草稿生成补充相关证据 | 已接入，可选增强 |
| 证据详情 | 展示 Graph 来源、关系路径、原文位置和版本信息 | 已接入 |
| GraphRAG 质量中心 | 展示评测、版本、门禁和检索质量信息 | 已接入 |
| 共享集成环境 | 完成真实 PostgreSQL、对象存储、任务队列下的变化链验证 | 已验证一条闭环 |

GraphRAG 在这些场景中只生成或排序候选，最终仍由研究员确认。它没有绕过“候选证据 → 人工确认
→ 正式证据”的人机协作门禁。

### 5.2 当前扩展分支新增的应用

`feature/knowledge-answer-intent-routing` 在知识助手中增加了问题意图路由。只有问题被判断为公司、
投资逻辑或研究知识类问题时，才尝试使用 GraphRAG；不适合 Graph 的财务结构化查询、报告直取
等问题继续走专用路径。

当前配置中 GraphRAG 主开关和 Graph Evidence Fusion 默认开启；知识问答总开关
`KNOWLEDGE_QA_ENABLED` 默认仍为 `false`，其 Graph 子开关默认开启。因此“代码已具备问答
Graph 路由”不等于“所有部署环境已经对用户开放知识问答”。

### 5.3 不能归入 GraphRAG 的能力

- 全局搜索仍是文本/向量等混合检索，不是所有搜索都经过投资知识图；
- 财务指标、预期差等问题主要依赖结构化数据和专用计算；
- 报告读取优先走报告检索路径；
- 数据中心的数据治理、身份权限和发布审批属于基础产品能力；
- 报告类型先验和其他排序规则是融合排序的一部分，不等同于 Graph 推理；
- GraphRAG 不执行投资结论发布，也不替代人工复核。

因此当前产品不是“全量 GraphRAG 化”，而是在关系解释价值高的关键研究链路上有选择地增强。

## 6. 效果演进

### 6.1 v3 至 v6 门禁结果

| 版本与评测阶段 | Recall@5 | MRR | NDCG@5 | Top-1 | 门禁结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| v3 初始评测 | 0.7832 | 0.8367 | 0.8088 | 0.6667 | 10/12 关闭 |
| v4 正式盲测 | 0.5143 | 0.5658 | 0.4383 | 0.3667 | 7/12 关闭 |
| v5 扩展评测 | 0.6372 | 0.8062 | 0.6541 | 0.7000 | 12/14 关闭 |
| v6 专业研究员一次性盲测 | 0.8247 | 0.8983 | 0.8076 | 0.8333 | 14/14 通过，允许默认启用 |

这些版本使用的数据集规模、查询构成、标注和门禁协议存在变化，不能把数值简单解释为同一测试集
上的单调提升。尤其 v4 暴露的问题推动了后续数据、融合策略和盲测流程改进，它不应被遗漏。

### 6.2 v6 与同版文本基线比较

| 指标 | 文本基线 | GraphRAG | GraphRAG 判定 |
| --- | ---: | ---: | --- |
| Recall@5 | 0.8303 | 0.8247 | 达到门槛，低 0.0056 |
| MRR | 0.8222 | 0.8983 | 提升 0.0761 |
| NDCG@5 | 0.7385 | 0.8076 | 提升 0.0691 |
| Top-1 | 0.6667 | 0.8333 | 提升 16.66 个百分点 |
| 路径来源合规率 | — | 1.0000 | 通过 |
| 候选池合规率 | — | 1.0000 | 通过 |
| 未标注候选率 | — | 0.0000 | 通过 |
| 权限/时点/关系/来源泄漏 | — | 0 | 通过 |

结果支持的结论是：GraphRAG 的主要收益在于把更合适且可解释的证据排到前面，并保持严格来源
约束；它没有显著扩大 Top-5 原始召回，Recall@5 反而比文本基线略低。因此后续效果目标应同时
保留文本覆盖，不宜只优化 Graph 路径分数。

## 7. 工程验证证据

当前验证不是只看单元算法，已经包含：

- Graph 建图、路径、权限、时点、融合和 trace 的自动化测试；
- 固化问题集、冻结候选池、专业研究员一次性盲测及机器校验产物；
- 共享集成环境中的真实数据库迁移、资料导入、异步变化链和证据生成；
- 发布策略与评测产物哈希绑定，避免仅凭人工描述开启功能。

本次文档复核所执行的 GraphRAG 定向测试结果为 `33 passed in 5.67s`。现有共享环境验证日志中，
一条资料变化链的检索 trace 包含 `text=1`、`graph=1`、`final=0.875`，证明 Graph 候选曾在
真实集成链路中参与最终排序，而不是仅存在于评测脚本。

需要保留一个版本边界：最新三分支集成合并完成了代码级与回归级验证，但合并记录明确说明没有
在该最终合并提交上重新执行完整数据库集成和共享环境验收。因此此前共享环境闭环是强证据，
但不能替代最终集成版本的再验收。

## 8. 产品成熟度判断

| 维度 | 当前判断 | 主要依据或缺口 |
| --- | --- | --- |
| 算法与功能完整性 | 较成熟 | 五层图、多跳检索、融合、trace 和版本策略已落地 |
| 权限与安全边界 | 较成熟 | 权限、公司、时点、确认状态过滤已实现，盲测泄漏为 0 |
| 可解释与审计 | 较成熟 | 路径、locator、版本、快照可追踪 |
| 离线质量 | 达到当前门禁 | v6 14/14 通过，但评测范围仍有限 |
| 业务链路集成 | 已形成闭环 | 变化链和草稿已接入，问答路由仍在扩展分支 |
| 真实研究员长期效果 | 证据不足 | 缺少线上确认率、节省时间、误导率和持续反馈数据 |
| 性能与容量 | 未充分验证 | 缺少全量规模、并发和 P50/P95 数据 |
| 异常容错与自动回退 | 不完整 | 缺少统一超时、熔断、错误归因和可观测回退闭环 |
| 最终集成版本部署验收 | 待补 | 三分支最终合并提交尚未重跑完整共享环境验收 |

综合判断：

- 内部功能演示：已经达到；
- 受控内部试点：基本达到；
- 多团队、规模化生产使用：尚未达到；
- 面向商业客户承诺可用性和 SLA：尚未达到。

这里的“尚未达到产品级”不是指算法不可用，而是生产工程和真实用户效果证据还不够完整。

## 9. 当前局限与风险

### 9.1 缺少真实线上反馈闭环

现有 v6 盲测能证明离线排序质量，但尚未持续统计研究员是否采纳 Graph 候选、确认需要多久、
Graph 是否减少漏读、错误路径是否导致误判，以及用户在何时主动退回文本检索。

### 9.2 自动异常回退仍不完整

无图路径时，文本/BM25 候选能够自然保留；也可以通过配置关闭 Graph。但在变化链、草稿生成和
知识问答等调用点，尚未形成统一的 Graph 超时、异常捕获、熔断、降级和 `fallback_reason`
记录规范。生产环境不能只依赖人工切换开关。

### 9.3 内存图的性能边界未证明

当前主要按任务或请求构建只读内存图，没有稳定的快照缓存、增量更新和容量模型。随着证券、
文档、事实和指标观测增长，建图时间、内存占用和路径扩展尾延迟可能成为瓶颈。

### 9.4 图质量受上游数据覆盖制约

GraphRAG 只能使用已经存在并正确映射的业务变量、指标、事实、证据和 locator。关系缺失、
口径不一致或原文引用不完整时，图算法不能自动补成可信事实。聚合摘要层目前也没有成为主要
产品能力。

### 9.5 当前评测规模仍偏小

现有主要基准覆盖 9 家公司、30 个问题和约 300 个冻结候选，且属于封闭候选池评测。它适合
阶段门禁，但不足以代表全行业、长尾公司、开放语料召回、持续新增文档和并发线上流量。

### 9.6 检索表示仍有提升空间

当前轻量文本表示包含字符 2-gram 哈希等确定性实现，便于复现和离线评测，但不能等同于经过
行业语料验证的正式语义嵌入模型。是否替换应通过开放语料 A/B 和成本、延迟评估决定。

### 9.7 个别说明与展示存在版本漂移

仓库中仍有旧阶段说明、中期门禁数据和演示 mock；部分注释把兼容的 RankStable 路径称为默认，
而当前配置实际默认使用 Evidence Fusion。对外演示和验收前应统一文档、配置和展示数据。

## 10. 后续改进路线

### P0：补齐生产工程与最终集成验收

1. 增加统一可观测指标：建图/检索 P50、P95，节点数、边数、扩展状态数、路径命中率、缓存命中率、
   降级率、人工确认率和拒绝原因；
2. 在所有 Graph 调用点增加独立超时、异常捕获、熔断、文本回退和 `fallback_reason`，并执行
   故障注入测试；
3. 以 `snapshot_hash + security_id + as_of + permission_scope` 为键引入有界缓存，验证失效机制；
4. 增加 Graph 专项真实 PostgreSQL 集成测试，覆盖权限、历史时点、待确认关系和跨公司隔离；
5. 在最新三分支集成版本上重新执行迁移、worker、账号、对象存储和资料变化链共享环境验收；
6. 基于目标数据量和并发执行负载测试，建立容量与资源预算。

P0 建议验收条件：连续两周无权限或时点泄漏；所有 Graph 异常均能在预算时间内回退；关键路径
P95 达标；线上候选决策可按 retrieval version 和 snapshot hash 复现。

### P1：扩大效果证据与用户闭环

1. 扩展公司、行业、问题类型和开放候选池，并引入第二标注人和分歧仲裁；
2. 建立关系覆盖率、locator 完整率、孤立节点率和过期关系看板；
3. 在知识问答和证据详情中完整展示 Graph 路径及文本回退原因；
4. 记录采纳、拒绝、改引和手工搜索行为，用真实反馈调优融合权重与报告先验；
5. 清理旧 mock、过期阶段结论和默认策略注释；
6. 评估正式语义嵌入模型，但必须同时满足质量、成本、隐私和延迟门禁。

### P2：由数据证明是否升级架构

只有当内存图的容量、更新频率、查询复杂度或跨公司分析出现可量化瓶颈时，再评估图数据库；
只有当确定性路径无法覆盖明确业务任务、且人工审批边界和可回放机制已经成熟时，再评估
Agentic RAG。二者都不应仅因为技术趋势提前引入。

## 11. 推荐的对内与对外表述

推荐表述：

> 产品已实现面向投资研究的五层 GraphRAG，在资料变化链等关键场景中提供可回溯的多跳证据
> 检索。v6 专业研究员一次性盲测的排序与安全门禁全部通过，并已完成共享环境闭环验证。目前
> 处于受控试点阶段，正在补齐线上效果、性能容量、自动降级和最终集成版本部署验收。

不建议表述：

- “所有研究检索都已经由 GraphRAG 替代”；
- “GraphRAG 已经自动生成并确认正式证据”；
- “v5 就已全部通过产品门禁”；
- “一次离线盲测证明系统已达到规模化生产级”；
- “GraphRAG 可以替代财务计算、研究判断或人工审批”。
