# Graph RAG 系统评测基准

版本：`graph-rag-evidence-fusion-closed-pool-v4`  
揭盲回归：`final-gold-v3-20260826`、`graph-relevance-v4-blind`、`graph-relevance-v5-blind`  
下一权威盲测：`graph-relevance-v6-blind`  
一次性执行入口：`python -m analytics.pipelines.graph_relevance_v4 evaluate-once --evaluator-dir <v6-evaluator-dir> --output <benchmark.json> --quality-report <quality-report.json>`

## 1. 评测对象与边界

本基准评测当前候选实现 `graph-assist-rank-stable-v1`：底层
`investment-graph-rag-v2-layered` 负责生成可解释图路径和候选补位，文本检索负责正式排序。
它不评测 Agentic RAG 的任务规划，也不把回测收益当成检索质量。

历史 v3 冻结金标包含 180 个“查询假设—候选公告”判断，组成 27 个查询、9 个证券；25 个查询至少有
一条“间接相关”或“直接相关”候选。相关性 0/1 级视为非正例，2/3 级视为正例。两个没有正例
的查询不进入 Recall 和 MRR 分母，但进入 Top-1 正确率分母，防止系统在无证据时强行返回结论。

基准建图只读取查询假设、候选标题、候选原文和冻结的受控词表。金标的
相关性等级、路径判断和裁决理由只在排序完成后计分，不参与节点、边、权重或查询扩展。

v3/v4 已揭盲，只能用于回归和错误分析。v5 采用每查询封闭候选池：所有文本与图检索器都必须
遵守 `allowed_document_ids`，排序结果越出候选白名单或出现未判断文档时直接失败，不再默认把
未标注文档当作无关。

## 2. 指标定义

| 指标 | 定义 | 放量门槛 |
| --- | --- | --- |
| Recall@5 | 每个有正例查询的 `命中正例数 / 全部正例数`，再做宏平均 | ≥ 0.80 |
| MRR | 每个有正例查询的首个正例倒数排名，宏平均 | ≥ 0.65 |
| NDCG@5 | 使用 0–3 级相关性增益的宏平均排序质量 | ≥ 0.75 |
| Top-1 正确率 | 27 个查询中首条结果为 2/3 级相关的比例 | ≥ 0.70 |
| 路径来源完整率 | Top-5 相关命中的图路径中包含该结果 locator 的比例 | ≥ 0.95 |
| 排序稳定率 | Graph assist 输出中，与文本共同候选的相对次序保持率 | = 1.00 |
| 未判断返回数 | 排名中不属于当前查询冻结候选池的文档数 | = 0 |
| Graph 回归门禁 | Recall@5 和 MRR 均不得低于同版本文本基线 | 必须通过 |

Recall@1/3/10、Hit@1/3/5/10 和 NDCG@1/3/10 同时记录，用于诊断但不替代主门禁。

## 3. 权限与时间泄漏挑战

每个查询注入三条和查询文本完全匹配的对抗诱饵，共 81 条：

1. 同证券但标记为“机密”的无权限文档；
2. 同时间但属于另一证券的文档；
3. 同证券但发布时间晚于检索截止时间的文档。

检查范围包括返回正文、引用、metadata 和完整图路径。四项计数——权限泄漏、跨证券泄漏、
未来信息泄漏、诱饵内容泄漏——必须全部为 0；任何一项非零都直接阻断放量，不做平均或豁免。

当前合计 14 项门禁：最少正例查询数、四个质量指标、路径来源完整率、排序稳定率、封闭池无
未判断项、Graph Recall/MRR 不劣于文本，以及四项安全泄漏。质量阈值沿用既有绝对门槛；新增
门禁用于约束产品行为和评测契约，不是放宽标准。

## 5. 结果解释

Graph 融合提高了候选集合覆盖和前五位的分级排序质量，且没有扩大数据可见范围。MRR 已较高，
说明多数查询能较早遇到至少一个相关结果；Recall@5 未通过则说明同一假设存在多条相关公告时，
前五位覆盖不足。Top-1 与文本基线相同，说明当前概念路径能改善中段排序，但还没有稳定纠正首位
弱相关或无关公告。

本次结果已经用于正式门禁，后续不得在同一 v3 数据上反复调阈值后宣称盲测通过。算法改进可以
用 v3 做回归和错误分析，最终放量判断必须再使用由研究员冻结的新盲测集。

## 8. 下一候选实现：Graph assist 与封闭候选池（2026-08-27）

v4 失败后的产品策略不是让 Graph 强行重排，而是把 Graph 用在它更可靠的两处：为文本候选附加
可审计的路径、图分与快照，以及在文本结果不足 K 时补位。对文本已经召回的共同候选，Graph
不得改变相对次序。这样保留成熟文本排序的稳定性，同时在产品中实际使用知识图谱的关系解释。

候选池契约同步落实到四条路径：关键词、中文 BM25、中文向量和图遍历都读取同一个查询级文档
白名单；图的种子和路径也不能借共享公司节点越出池外。评测报告把未判断返回数作为硬失败项，
因此 v4 原报告中的 187/186 个未标注结果在新协议下均归零。

## 10. v5 唯一一次盲测协议

`graph-relevance-v5-blind` 已冻结 30 个全新查询、每查询 10 个候选，共 300 个关系判断，覆盖
9 家公司和 90 份唯一文档。每家公司下的所有查询共享同一 10 文档候选池，防止研究员或模型
从候选集合差异反推相关性；v3/v4 查询和候选 URL 复用均为 0。

冻结顺序必须保持：生成无标签题面 → 冻结候选池 → 锁定检索/Graph/评测代码哈希 → 专业研究员
独立标注 → 按关系样本 ID 合并五个标签字段 → 封存金标 → 写入消费预约 → 执行唯一一次评测。
消费预约一旦写入，即使进程异常也不得静默重跑。

v5 只有在 14/14 门禁全部通过时才能让质量中心标记 READY；READY 的含义是允许进入 P1 的
100% shadow。正式环境仍使用 `RAG_GRAPH_ENABLED=false`，不得只改环境变量绕过质量报告。

## 12. v6 候选：Evidence Fusion 与冻结门禁

`graph-evidence-fusion-v1` 在查询级授权候选池内使用确定性 RRF：文本权重 0.25、中文 BM25
权重 0.5、Graph 路径权重 1.0、财报类高证据密度先验 1.0，`rrf_k=1`。最终结果优先使用
Graph 分支的路径、原文定位和快照 metadata，并记录三分支排名与先验，便于逐条审计。

“整榜完全保序”不再作为发布硬门，因为它与 Graph 改善排序的目标冲突。新硬门要求候选池合规率
为 1.0、未判断项为 0；绝对 Recall@5 仍须 ≥0.80，同时允许相对文本基线最多 0.01 的波动。
MRR、NDCG@5、Top-1、路径来源和四类零泄漏门槛不变。该口径在 v6 候选池生成和标签回收前
冻结，不能根据 v6 结果调整。
