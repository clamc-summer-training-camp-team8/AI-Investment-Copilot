# Graph RAG 实现说明

## 1. 结论

当前项目已实现可注入现有 `Retriever` 协议的 `investment-graph-rag-v2-layered`，并以
`graph-assist-rank-stable-v1` 作为下一发布候选模式。关系库正式对象按“来源—观测—语义—研究—
摘要”五层投影为只读内存图；文本检索保持正式排序，Graph 为命中候选附加路径、图分和快照，
只在文本结果不足 K 时补位。它不引入 Neo4j 等第二事实源，也不承担 Agentic RAG 的任务规划、
循环检索和停止决策。

默认图路径为：

```text
证券 → 投资逻辑 → 投资假设 → 业务变量 → 指标 → 事实 → 原文片段
                                      └→ 指标观测 → 来源文档
投资假设 → 已确认证据 → 事件 → 来源文档 → 原文片段
                    └──────────────→ 引用原文
```

## 2. 模块

| 模块 | 职责 |
| --- | --- |
| `app/ai/graph_rag.py` | 图节点/边、确定性遍历、路径解释、文本与图分数融合 |
| `app/services/graph_rag.py` | 从 UnitOfWork 构建指定逻辑的权限外层可控图投影 |
| `app/ai/retrieval.py` | 扩展稳定 Retriever 契约，承载 `seed_node_ids` 与路径元数据 |
| `app/workers/change_chain.py` | 配置开启时把 Graph Retriever 包装到事件影响分析链路 |
| `scripts/run_graph_rag.py` | 对本地数据库执行可复现查询并输出完整路径 |

构建服务内部由 `SourceLayerBuilder`、`ObservationLayerBuilder`、`SemanticLayerBuilder` 和
`ResearchLayerBuilder` 协作；统一图只是一份检索投影，各层仍有独立类型、内容哈希和版本清单。

## 3. 图语义

节点覆盖证券、文档、原文片段、事件、事实、业务变量、指标、指标观测、投资逻辑、投资假设
和证据。边覆盖拥有逻辑、包含假设、依赖变量、由指标衡量、陈述事实、观测指标、支持、冲突、
引用原文和来源关系。

“业务变量”不是新建数据库事实表，而是从已确认假设的名称或类型形成的确定性投影；指标仍
来自版本化指标字典，事实仍来自 `document_fact`，正式证据关系仍来自人工确认后的
`evidence_relation`。

### 3.1 显式知识层

| 层 | 节点 | 职责 |
| --- | --- | --- |
| 原始证据层 | 文档、原文片段 | 保存不可替代的来源、权限、时间和 locator |
| 事实观测层 | 事实、事件、指标观测 | 表达“资料说了什么”，不直接给出投资判断 |
| 领域语义层 | 指标、业务变量 | 统一指标别名并连接事实与可验证变量 |
| 投资研究层 | 证券、逻辑、假设、已确认证据 | 表达研究判断和人工确认关系 |
| 聚合摘要层 | 摘要（扩展位） | 用于公司/行业导航，不作为最终证据 |

节点类型会自动映射到唯一知识层，错误的类型—层组合会在建图时被拒绝。当前聚合摘要层保留
为扩展位，尚未用机器生成摘要填充，避免摘要在缺少独立评测时影响正式召回。

### 3.2 指标受控词表

`MetricVocabulary` 对“营收/营业收入/revenue”“平均售价/ASP”等名称执行确定性标准化，再建立
事实—指标边。词表具有独立版本并进入图快照；它只做受控别名映射，不调用模型创造业务关系。

### 3.3 可复现图快照

每次构建返回 `GraphSnapshot`，包含：

- 图 Schema、构建器和指标词表版本；
- `as_of` 截面、逻辑范围、证券范围以及是否纳入待确认关系；
- 每层节点数和内容哈希；
- 由上述内容确定性生成的 `snapshot_id`。

相同事实源和构建参数会得到相同 `snapshot_id`。后续持久化缓存或增量构建时，可以按每层
`content_hash` 判断需要重建的范围，而不必把内存图升级为新的事实源。

## 4. 检索流程

1. 使用查询文本、显式假设节点和原文本检索结果共同形成种子节点。
2. 对每个节点执行证券、可见标签和 `as_of` 披露时间过滤。
3. 在最大跳数和最大扩展数内执行带权图遍历，默认拒绝未确认边。
4. 一条路径跨层后只能持续上钻或持续下钻，禁止“研究层→语义层→另一研究对象→来源层”这类
   折返捷径；同层关系仍可正常遍历。
5. 只允许原文片段成为最终引用结果，事实、指标和假设不能冒充引用。
6. 发布候选模式保留文本候选的相对次序，为共同候选附加最佳图分、最多三条路径和快照；只有
   文本不足 K 条时才按图结果补位。融合重排实现继续保留给消融和揭盲回归，不作为当前默认。
7. Agent 仍只能引用返回的原文 locator；图路径作为已确认关系上下文，不替代原文。

## 5. 安全边界

- v6 专业研究员一次性盲测 14/14 通过后，默认 `RAG_GRAPH_ENABLED=true`。
- 默认 `RAG_GRAPH_ASSIST_ONLY=false`，使用已授权的 Evidence Fusion；保序 assist 仍作为兼容开关。
- 默认只纳入已确认指标映射和已确认证据关系。
- 权限和时间过滤作用于路径上的每一个节点，而不只检查最终文档。
- 证券过滤阻止通过共享指标节点串到其他公司的研究对象。
- 评测时查询级候选白名单同时约束文本召回、图种子、图遍历和最终引用；越出池外直接失败。
- 被驳回、已解除和待确认关系不会进入默认图。
- 图检索不写数据库、不发布逻辑、不确认关系、不改变正式状态。

## 6. 与 Agentic RAG 的边界

Graph RAG 提供的是一次确定性 `search(query)`：输入查询，输出原文和可解释路径。任务拆解、
多轮查询、证据缺口判断、预算控制、循环和停止条件属于 Agentic RAG。未来 Agentic RAG 可以
把 `GraphRetriever` 当作一个工具调用，但不需要修改本实现的图语义或人工闸门。

## 7. 配置

```dotenv
RAG_GRAPH_ENABLED=true
RAG_GRAPH_ASSIST_ONLY=false
RAG_GRAPH_TEXT_WEIGHT=0.35
RAG_GRAPH_RELATION_WEIGHT=0.65
RAG_GRAPH_MAX_HOPS=5
```

文本和图权重会在图检索及回归消融中归一化；assist 模式不使用融合分改变文本顺序。最大跳数
限制为 1～8；默认 5 跳足以覆盖“假设—变量—指标—事实—原文”。

## 8. 复现

```powershell
python -m scripts.run_graph_rag `
  --thesis-id THS-001 `
  --query "需求与出货假设有哪些原文证据" `
  --as-of 2026-08-22T00:00:00+08:00 `
  --visibility 公开
```

输出同时包含 locator、文本/图分项分数、节点类型、关系方向、路径解释和边的原文定位。
命令行还会输出本次 `GraphSnapshot` 及各知识层的节点数和内容哈希。

## 9. 前端检索追踪

事件影响分析生成候选证据时，会把命中片段的检索模式、文本/图分项分数、最终得分、最多三条
图路径以及不含正文的快照清单冻结到 `evidence.retrieval_trace`。迁移版本为
`0012_evidence_retrieval_trace`。

前端通过 `GET /api/evidence/{evidence_id}/retrieval-trace` 按需读取，不把技术追踪加入证据列表
接口。该接口复用证据详情的逻辑可见性和文档权限检查；无权访问时仍返回 404。旧证据没有追踪
时返回 `available=false`，不影响原文核验和人工处置。

证据核验页以得分条、知识层标签和文本路径展示双路依据，不绘制可拖拽全图；复杂全图既不利于
两分钟内判断，也容易把不可引用的图节点误解为正式证据。

## 10. 单公司单逻辑维护链与运行时复用

数据库和服务层保证每个证券最多维护一条投资逻辑；新观点通过同一逻辑的修订和不可变版本演进，
不再为同一公司创建并行逻辑。维护链按证券和权限取得唯一可见逻辑后，兼容的候选评分追踪仍会
计算：

- 文本分：事件与逻辑标题、核心观点、假设陈述的双字组重合；
- 图分：事件与该逻辑在投资研究层、领域语义层三跳画像的重合；
- 融合分：沿用 Graph RAG 的文本/关系权重。

在单逻辑口径下，该评分不再承担“多个投资逻辑竞争排序”，只用于审计事件与唯一逻辑的匹配
上下文。它不越过证券和权限召回，也不把低分逻辑自动关闭。分项分数、模式和快照 ID 写入事件
审计并随资料处理作业返回；配置未开启时保留 `baseline` 模式。

`build_graph_retriever_from_corpus` 会复用同一图语料，并在包装前剥离已有 GraphRetriever；因此
长生命周期 Runtime 跨批次复用时不会形成 GraphRetriever 套娃，也不会产生无限增长的版本串。

## 11. 验收范围

已覆盖以下自动化测试：

- 文本无词面重合时，通过“假设—变量—指标—事实—原文”召回；
- 整条路径的权限与未来信息过滤；
- 未确认边默认不可遍历；
- 从 UnitOfWork 的正式对象构建图语料；
- 节点类型到知识层的强约束、路径层级元数据和禁止跨层折返；
- 指标受控别名匹配、稳定快照 ID、每层内容哈希及构建期 `as_of` 过滤；
- 证据级追踪冻结、权限受控 API、旧证据降级和前端生产构建；
- 候选逻辑文本/图画像排序、事件审计、作业摘要和 Runtime 重复包装幂等性；
- 已确认事实、指标、证据与原文路径可被 Retriever 返回；
- 原有关键词、混合检索、Agent Runtime 和上传变化链路保持兼容。

最终独立金标系统基准与 P0 回归见 [Graph RAG 系统评测基准](Graph-RAG系统评测基准.md)。
`graph-relevance-v6-blind` 的 300 行专业研究员独立标注与唯一一次评测已完成：Recall@5
0.8247、MRR 0.8983、NDCG@5 0.8076、Top-1 0.8333，路径来源与候选池合规率均为 1.0，
未判断返回和四类泄漏均为 0，14/14 门禁全部通过。质量中心已标记 READY，默认启用 Evidence
Fusion；历史 v4/v5 未通过结论仍保留且不可覆盖。
