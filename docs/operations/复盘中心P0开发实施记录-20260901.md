## 1. 本次交付范围

本次把 `/retrospective` 从静态产品快照升级为真实 API、真实数据库驱动的复盘中心，交付以下 P0 主链：

1. 按 Thesis、复盘类型、区间和 `data_cutoff_at` 预检并冻结来源；
2. 创建复盘草稿，保存结构化内容并通过 `lock_version` 防止并发覆盖；
3. 展示真实总览、服务端分页列表、详情、时间线、来源和不可变版本；
4. 完成草稿、待评审、退回、发布、修订、归档状态流转；
5. 发布前执行假设依据、强反证、来源缺口、局限、引用白名单和原文可访问性门禁；
6. 基于冻结来源生成 AI 候选，由研究员逐字段采用，不覆盖人工正文；
7. 导出已发布版本的 Markdown 或 JSON，并记录导出审计；
8. 从 Thesis 详情和复核任务跳转发起复盘，来源可深链到数据中心；
9. 通过独立功能开关控制人工主链、AI 候选和后续经验库。

P1 的研究经验库、搜索/问答二级来源接入、量化附录和 PDF 导出未在本次实现。

## 2. 数据、权限与时点边界

- 新增 `retrospective`、`retrospective_source`、`retrospective_version` 三张表，迁移版本为 `0018_retrospective_center`，Alembic 保持单一 head。
- 来源快照只接受截止时点前的正式逻辑版本、已确认关系、当时可访问的正文/Revision、指标观测、状态处置、已完成复核任务和审计动作。
- 待确认、驳回、未来记录、标题索引、无正文、无权限和无有效历史 Revision 的资料被排除并计入缺口。
- 文档后续删除或权限收紧时，详情、时间线、来源接口和导出会再次鉴权并动态脱敏。
- 草稿只对负责人和指定评审人可见；团队成员只读取已发布版本。搜索和假设结果筛选不会使用团队成员无权查看的未发布修订正文。
- 管理员身份不扩大研究正文权限；无权限与不存在统一按 404 处理。
- 修订发布后清除主对象上的未发布修订标记，历史版本保持不可变，不能绕过“新建修订”重复发布。

## 3. AI 与事务边界

- 新增 `retrospective_draft-v1` Schema、版本化 Skill、Local/Mock/HTTP Provider 和 Gateway 入口。
- AI 输入只包含冻结且当前仍可见的来源白名单；输出引用必须全部命中白名单，并拒绝脚本、HTML 协议载荷等不安全内容。
- AI 生成按“短读事务 → 事务外模型调用 → 乐观锁短写事务”执行。模型运行期间发生人工保存时，候选不写入并返回并发冲突。
- 解析、Schema、引用或模型失败会保存失败状态与审计，人工创建、编辑和发布主链不受影响。
- AI 结果只存放在候选区，不自动修改 Thesis、Hypothesis、Evidence、状态、评级、仓位或正式复盘正文。

## 4. API 与前端

- `/api/retrospectives` 提供总览、列表、来源预检、创建、详情、时间线、来源、版本、草稿保存、AI 候选、提交、退回、发布、修订、归档和导出接口。
- OpenAPI 当前导出 103 条路径，错误契约补充重复对象、乐观锁、人工闸门、发布校验、AI 不可用和导出限制。
- 前端新增 `/retrospective`、`/retrospective/new`、`/retrospective/:id`、`/retrospective/:id/edit`，总览、列表、创建、详情和编辑均调用真实 API，不使用静态数据兜底。
- 筛选条件写入 URL，支持报告/公司/证券搜索、状态、类型、负责人、评审人、行业、假设结果、强反证、完整度、区间、发布时间、排序和分页。
- 编辑器支持人工字段、逐项假设结论与引用、手动/自动保存、AI 候选逐字段采用、发布清单和生命周期动作；409 时保留本地编辑内容。
- 新增 Vitest + Testing Library，覆盖真实 API 列表渲染、URL 状态和乐观锁失败时本地内容不丢失。

## 7. 尚未执行的发布验收

以下工作依赖干净提交、共享环境、真实账户或观察窗口，本次开发不能据此宣称“已上线”或“生产验收完成”：

- 把当前混合工作区按搜索/问答、数据中心、复盘中心拆成可审查提交并推送；
- 从确定提交 SHA 构建不可变镜像并部署共享集成环境；
- PostgreSQL + MinIO 成套备份和隔离恢复演练；
- 研究员、研究主管、只读成员三账户真实权限验收；
- 15+ 冻结样例、越权/未来信息/Prompt injection 对抗；
- 真实规模列表 P95 ≤ 2 秒、详情 P95 ≤ 3 秒、AI P95 ≤ 20 秒和 30 秒硬超时；
- 主模块、AI 开关和上一镜像回退演练；
- 共享环境连续 3 个工作日观察。

在上述门禁完成前，交付状态应表述为“P0 代码完成、待共享环境发布验收”。

## 8. 推荐发布顺序

1. 先整理并提交当前已有搜索/问答和数据中心成果，再独立提交本次复盘中心代码；
2. 使用干净 SHA 构建镜像，备份并完成隔离恢复；
3. 部署 `0018_retrospective_center`，三个复盘开关保持关闭并回归旧功能；
4. 仅开启人工复盘主链，完成三账户创建、发布、只读、无权、导出和原文回查；
5. 完成样例、安全和性能门禁后，仅对测试账户开启 Local AI；
6. 观察 3 个工作日，再决定是否扩大 AI；P1 开关继续关闭。

## 9. Phase 3 合并版工作台对齐补充

> 补充日期：2026-09-01
> 当前分支：`feature/knowledge-answer-intent-routing`
> 集成依据：`docs/collaboration/20260901-phase3三分支功能集成合并记录.md`

三分支功能集成后，工作台已经形成稳定的全宽顶栏、三栏研究布局和跨模块导航。本次在不修改复盘
后端契约、数据库迁移和生命周期规则的前提下，完成复盘中心与工作台的产品级衔接。

### 9.1 已完成的对齐

1. 复盘目录改为与工作台一致的三栏工作区：左侧报告状态和研究闭环导航、中间真实概览/筛选/目录、
   右侧流程状态和治理口径；顶栏、卡片、色彩、间距和响应式断点复用工作台设计系统。
2. 创建、详情和编辑页继续保留专注画布，并适配复盘全宽 Shell，避免隐藏原侧栏后内容贴边或无限拉伸。
3. 工作台在 `RETROSPECTIVE_CENTER_ENABLED` 开启时独立读取真实复盘概览，展示待完成数、平均完整度和
   草稿/待评审/已发布状态分布；复盘接口失败只降级该卡片，不阻断工作台研究数据。
4. 工作台左侧研究功能增加“复盘中心”；每条现行主投资逻辑增加“发起复盘”，以
   `/retrospective/new?thesisId={thesisId}` 把研究上下文带入创建页并自动预选逻辑。
5. 复盘中心补齐返回工作台、复核任务、投资逻辑和数据中心的稳定深链，明确“定位逻辑 → 冻结来源 →
   人工评审/发布 → 回查原文”的闭环。
6. 功能开关关闭时，工作台不请求复盘概览，也不展示复盘卡片和发起入口，保持灰度与回退边界。
