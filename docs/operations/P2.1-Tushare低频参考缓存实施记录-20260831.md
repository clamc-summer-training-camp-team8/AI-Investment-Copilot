后续状态：本记录描述 120 积分阶段。当天稍后已使用用户提供的 10k 兼容端点完成历史回填，A 股

## 1. 交付结论

新增 `.runtime/quant-reference-cache/` 本地缓存契约和
`scripts/refresh_tushare_reference_cache.py`。任务先验证当前冻结行情清单，再读取冻结的脱敏权限
快照；Token 只从环境变量或本地密钥文件进入进程，不写入缓存、报告或冻结资产。

- `daily_basic`：对当前默认版本最新 A 股交易日执行一次整市场查询，再筛选研究范围内 7 只 A 股；
  同一目标交易日无论成功或失败都不重复请求。
- `trade_cal`：一次获取 SSE 全年日历，任意两次尝试至少间隔一小时，成功文件七天内直接复用。
- 每个数据文件只追加不覆盖；`state.json` 登记相对路径、接口、观测日、状态、字节数和 SHA-256。
- 候选构建验证状态清单及文件哈希，只消费已登记缓存；实际使用的数据再次冻结到候选的
  `tushare_reference_snapshot.json`。
- 主行情构建已明确排除 `daily_basic` 和 `trade_cal` 在线调用，避免按证券放大低频配额。
- 行情新鲜度探测发现新会话后，把候选目标日显式传给缓存任务；即使默认版本尚未人工发布，也能
  对每个新交易日积累一次市值快照。

## 2. 真实接口验收

第一次执行时，`daily_basic` 返回账号级频控：5 次/天、1 次/分钟。原通用重试策略连续产生三次
失败尝试，但没有写入不完整缓存。随后完成以下整改：

1. 两个低频接口都改为单次调用，不自动重试；
2. 两个端点独立捕获失败，一个受限不再阻断另一个；
3. `daily_basic` 把目标交易日写入尝试状态，重复运行直接由本地门禁拦截；
4. 报告保留脱敏错误和状态，但 `capability_switches_changed` 始终为 `false`。

整改后 `trade_cal` 年度调用成功：

- 缓存文件：`trade_cal/SSE-2026-asof-20260831T121736.json`；
- 比较区间：2026-01-01~2026-08-28；
- AKShare 观测开市日：159；Tushare 开市日：159；
- AKShare 独有：0；Tushare 独有：0；状态：`matched`；
- 紧接着复跑：`trade_cal=reused`、`daily_basic=throttled`、重试事件 0，证明未产生重复调用。

`daily_basic` 当天额度已由此前权限探测和验收消耗，当前成功市值缓存仍为 0。任务将在下一个新
A 股交易日按一次整市场调用继续积累；不能为了补齐本日而绕过目标日门禁。

## 3. CI 与产品门禁

工作日 19:30 流程先通过 GitHub Actions cache 恢复 `.runtime/quant-reference-cache`，再刷新低频
参考数据并探测行情候选。日常任务复用冻结权限快照，不再每次运行最小权限探测，避免额外消耗
`trade_cal` 配额。低频任务暂按可降级步骤运行；报告始终上传，旧缓存损坏时后续候选构建仍会因
SHA-256 不匹配而失败。

当前能力结论保持不变：

- 点时市值真实覆盖为 0，`point_in_time_market_cap=false`、市值中性硬门禁关闭；
- 年度官方日历已完成当前覆盖期对账，但默认数据集不会因缓存结果自动替换；
- `stk_limit` 仍无权限，涨跌停交易阻断关闭；
- AKShare 仍是主行情源，Tushare 参考字段不能静默覆盖主源价格。
