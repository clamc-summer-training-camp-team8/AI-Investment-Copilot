# 共享集成环境建设工作日志（2026-08-30）

> 项目：AI Investment Copilot  
> 工作分支：`phase2-integrated`  
> 目标环境：阿里云 ECS，中国香港  
> 环境用途：团队共享集成、真实动态演示、前后端与数据链路验收  
> 文档状态：已完成；不包含任何明文密码、私钥或服务密钥

## 1. 背景与目标

第二阶段 Graph RAG P0 与多分支集成完成后，团队需要一个所有成员可访问、数据状态一致的共享
环境，替代各开发机上的静态页面或彼此隔离的本地数据库。此次工作的目标是：

1. 在低流量交付预算下部署完整产品栈，而不是只部署静态前端；
2. 让前端、API、后台任务、数据库、对象存储与 Graph RAG 使用同一套真实运行链路；
3. 保持数据库与中间件不直接暴露公网，通过统一网关认证进入产品；
4. 建立可回滚发布、健康检查、数据备份和隔离恢复能力；
5. 验证“一家公司一条投资逻辑”、动态文档上传、证据审核和 Graph RAG 正式排序；
6. 为后续团队账号、域名、CI/CD 和共享联调提供可复用的工程基线。

## 2. 环境选择与架构决策

### 2.1 云资源选择

前期评估过华为云共享集成方案和阿里云华北 2（北京）ECS。北京节点若使用自有域名对外提供
Web 服务，会受到备案周期影响，因此最终采用阿里云中国香港实例：

| 项目 | 配置 |
| --- | --- |
| 实例 ID | `i-j6c5wiqvx4t95l0eupxb` |
| 公网 IP | `47.238.244.65` |
| 操作系统 | Ubuntu 22.04 64 位 |
| 规格 | 2 vCPU / 4 GiB |
| 系统盘 | 40 GiB ESSD Entry |
| 当前定位 | 低流量共享集成与交付演示，不作为正式高可用生产环境 |

香港实例不阻塞域名的 ICP 备案流程；如果网站面向中国内地可访问，仍应按实际开放范围评估公安
联网备案要求。正式规则以阿里云和主管部门最新要求为准。

### 2.2 单机 Compose 架构

当前规模下采用单机 Docker Compose，避免过早引入 ACK、RDS、Tair 等额外成本和运维复杂度。

```text
团队浏览器
    │ HTTPS + Basic Auth
    ▼
Caddy 网关
    ├── React / Nginx Web
    └── FastAPI
          ├── PostgreSQL + pgvector
          ├── Redis / ARQ Worker
          ├── MinIO 对象存储
          └── Graph RAG / Evidence Fusion
```

仅 Caddy 发布 80/443。PostgreSQL、Redis、MinIO、API 和 Web 容器只加入内部 Docker 网络，不在
安全组或宿主机上发布业务端口。

### 2.3 身份与权限决策

共享集成环境使用 `AUTH_MODE=trusted_proxy`：

1. Caddy 完成 Basic Auth；
2. Caddy 移除浏览器传入的 `Authorization`；
3. Caddy 将认证账号注入为 `X-User-Id`；
4. Caddy 使用至少 32 字节的内部代理密钥证明请求来自可信网关；
5. API 不接受绕过网关的外部身份头。

这套模式适合受控共享集成环境。正式试点仍应切换带签名和过期时间的 JWT/SSO。每位团队成员
需要独立 ASCII 账号，禁止长期共用 `integration_admin`，否则审计日志无法区分操作人。

### 3.2 发布策略

每次发布使用时间戳和 Git 短提交号生成唯一镜像标签。发布流程会保留服务器现有
`.env.integration` 和 `users.caddy`，避免应用更新时轮换持久化服务密码或覆盖团队账号。

原方案通过 SCP 传输 `docker save` 镜像包。实际测试发现应用镜像归档约数百 MB，而发布工作站
到香港实例的 SCP 上行速度较慢。因此改为：

1. 优先使用 Docker SSH transport；
2. 本机只发送受 `.dockerignore` 过滤的约 6.84 MB 构建上下文；
3. 在 ECS Docker Engine 上构建不可变镜像；
4. 后续发布复用服务器 Docker 层缓存；
5. 远程 Docker 不可用时，再回退到本机构建、gzip 压缩和 SCP 传输。

服务器端发布前保存上一份 `release.env`。若迁移、容器启动或 `/health/ready` 验收失败，脚本会
恢复上一镜像版本。

### 3.3 应用与样例数据适配

共享环境默认开启：

```text
RAG_GRAPH_ENABLED=true
RAG_GRAPH_ASSIST_ONLY=false
```

为保证虚构样例可以通过正式权限检索链路展示，完成两项修正：

- 样例文档可见性由默认 Actor 无权读取的“内部受限”调整为“内部”；
- 导入样例文档时同步创建已确认的 `document_security_relation`，保证证券过滤、文本检索、向量
  检索和图投影都能识别文档归属。

虚构样例仍保持 `is_illustrative=true`，不得用于真实投资结论。

### 4.2 首次发布与认证修复

首次账号密码哈希在 Windows PowerShell 管道中受到换行/编码影响，导致控制台显示密码与实际
哈希字节不一致。修复方式为把临时明文密码通过短生命周期容器环境变量传入
`caddy hash-password`，避免 PowerShell 管道转换，同时避免密码出现在命令参数中。

当前认证验收：

| 场景 | 结果 |
| --- | --- |

| API 直接公网端口 | 未发布 |

明文初始密码没有写入仓库和本文档。

### 4.3 IP HTTPS 与 Host 验收修复

临时入口使用公网 IP。浏览器访问字面 IP 时可能不发送可用于虚拟主机选择的 SNI，因而 Caddy
增加显式 TLS 策略和 `default_sni`。IP 阶段使用 Caddy 内部证书；绑定域名后切换公开 ACME
证书。

服务器本机验收使用 `--resolve 47.238.244.65:443:127.0.0.1` 保持正确 Host。直接以
`https://127.0.0.1` 请求只适合验证 TLS 监听，不适合验证虚拟主机 API 路由。

## 7. 团队协作边界

当前环境已经支持：

- 多名成员通过浏览器访问同一动态前端；
- 共享 API、PostgreSQL、Redis、MinIO 和 Graph RAG 数据状态；
- 使用独立账号区分投资逻辑负责人和审计操作人；
- 在 `phase2-integrated` 合并后执行真实前端—后端—数据库集成验收；
- 对上传材料、后台任务、证据审核和检索结果进行跨成员复核。

当前环境不等同于多人并行分支沙箱：

- 同一时间只有一个已部署版本，不同功能分支不能同时覆盖部署；
- 数据库不开放公网，开发者不能把共享库当作个人调试库；
- schema 修改必须通过 Alembic migration 随合并版本发布；
- 当前不是实时共同编辑，同一对象的并发修改仍需团队协调；
- 阿里云环境尚未接入 GitHub Actions 自动发布，当前由授权发布工作站执行发布脚本。

推荐流程为“个人分支与本地库开发 → PR/CI → 合并 `phase2-integrated` → 发布共享环境 → 多账号
联合验收”。
