# 华为云共享集成环境建设与验收

> 状态：仓库侧建设完成，等待云账号参数与授权后执行 `terraform apply` 和首次发布  
> 目标环境：`integration`，不是生产环境  
> 基线分支：`phase2-integrated`

## 1. 结论

AI Investment Copilot 可以部署到华为云。首版采用一台独立 ECS 承载 Docker Compose，运行
Web、API、Worker、PostgreSQL/pgvector、Redis、MinIO 和 Caddy。ECS 位于独立 VPC；安全组
只开放 80、443 和来自办公网/VPN 的 22，PostgreSQL、Redis、MinIO、API 均无公网端口。

这个选择适合当前“团队共享集成 + 动态演示”阶段：部署面小、与本地技术栈一致、迁移成本低，
并能立即保留 Graph RAG 所需的 pgvector、图扩展查询、异步 Worker 和不可变原文件链路。
它不等同于最终生产架构。达到第 10 节阈值后，再将数据库、缓存和备份分别迁移到
RDS for PostgreSQL、DCS for Redis 和 OBS。

华为云官方能力核验：

- RDS for PostgreSQL 13～17 的受支持小版本可使用 pgvector 0.8.0；RDS 通过
  `control_extension('create', 'vector')` 安装扩展：
  <https://support.huaweicloud.com/intl/en-us/usermanual-rds-pg/rds_09_0045.html>
- DCS 兼容 Redis 协议；ECS 与 DCS 应放在同一 VPC，Redis 4.0 及以上基础版应配置 IP 白名单：
  <https://support.huaweicloud.com/usermanual-dcs/dcs-ug-0312007.html>
- OBS 支持桶级 WORM，开启 WORM 会自动开启且不能暂停版本控制：
  <https://support.huaweicloud.com/intl/en-us/usermanual-obs/obs_03_0716.html>
- ECS 网站安全组可以开放 80/443，SSH 来源应限制为可信地址：
  <https://support.huaweicloud.com/intl/en-us/helppanel-ecs/ecs_help_007.html>
- 华为云官方 Terraform Provider 支持从环境变量读取凭据：
  <https://github.com/huaweicloud/terraform-provider-huaweicloud/blob/master/docs/index.md>

## 2. 架构与数据流

```text
团队浏览器
    │ HTTPS + 独立账号
    ▼
EIP → 安全组 → Caddy 网关
                  ├── /api、/health ──► FastAPI ─┬─► PostgreSQL + pgvector
                  │       注入用户身份           ├─► Redis/ARQ ─► Worker
                  │                              └─► MinIO Object Lock
                  └── 其他路径 ───────► React/Nginx

公网：80/443；受限运维：22；其余服务：仅 Docker 内网
```

Graph RAG 在集成环境默认使用当前正式口径：

- `RAG_GRAPH_ENABLED=true`
- `RAG_GRAPH_ASSIST_ONLY=false`
- 文本权重 0.35、图关系权重 0.65、最大 5 跳沿用应用默认值；
- 图链路和文本链路访问同一套 PostgreSQL 事实、权限和披露时间边界；
- API、Worker 和前端不是静态 mock，所有动态页面均连接共享数据库和队列。

## 4. 云账号和网络前置条件

执行部署前由云账号管理员准备以下内容：

1. 确定区域和可用区。团队主要在中国大陆时优先同区域低延迟节点；如果选择中国大陆节点，
   公网网站在开通前必须完成 ICP 备案或接入备案。华为云说明见：
   <https://support.huaweicloud.com/icp_faq/icp_05_0145.html>。
2. 一个专用于集成环境的华为云项目，及具备 VPC、子网、安全组、ECS、EIP 创建权限的 IAM
   自动化用户。不要使用账号根用户，不要把 AK/SK 写入 `.tfvars` 或 Git。
3. Ubuntu 24.04 LTS 镜像 ID、至少 4 vCPU/16 GiB 的规格 ID、至少 200 GiB 系统盘、已有
   SSH 密钥对名称，以及办公网/VPN 公网出口 CIDR。
4. 一个已备案（大陆节点）或无需备案（非大陆节点）的子域名，并能添加指向 EIP 的 A 记录。
5. SWR 组织/命名空间和专用发布凭据。SWR 官方长期登录指令说明：
   <https://support.huaweicloud.com/usermanual-swr/swr_01_1000.html>。
6. 一个私有 OBS 备份桶。建议开启版本控制；确认合规需求后开启 WORM。生产资料不得使用公共读。

当前 IaC 只创建会产生费用的计算与网络资源，不自动购买域名、备案、创建 IAM 凭据或修改
组织级 DNS。费用按所选区域、ECS 规格、系统盘和公网流量计算，执行 `terraform plan` 后必须由
云账号负责人审核再 apply。

## 5. 创建华为云资源

在安全终端设置短期凭据。华为云 Provider 会读取环境变量，凭据不进入仓库：

```powershell
$env:HW_ACCESS_KEY = "<temporary-ak>"
$env:HW_SECRET_KEY = "<temporary-sk>"
$env:HW_REGION_NAME = "cn-south-1"
```

复制参数模板并填写控制台中的实际 ID：

```powershell
Set-Location E:\product\AI-Investment-Copilot\deploy\huawei-cloud\terraform
Copy-Item terraform.tfvars.example terraform.tfvars
terraform init
terraform fmt -check
terraform validate
terraform plan -out integration.tfplan
terraform apply integration.tfplan
terraform output
```

`terraform.tfvars`、state 和 plan 均已被 Git 忽略。团队正式共管 IaC 前，应把 state 放到带版本和
访问控制的远端后端；在此之前只允许一名基础设施负责人保管 state，避免并发 apply。

资源创建后，将集成子域名 A 记录指向 `terraform output -raw eip_address`。等待 DNS 生效后，
Caddy 会通过 80/443 自动签发并续签 TLS 证书。

## 6. 首次服务器配置

cloud-init 会安装 Docker/Compose，创建 `/opt/ai-investment-copilot` 并把运维用户加入 docker 组。
首次 SSH 登录后确认：

```bash
cloud-init status --wait
docker version
docker compose version
```

先从运维工作站传输模板（发布流水线也会同步这些非密钥文件）：

```bash
scp deploy/integration/.env.integration.example \
  deploy/integration/users.caddy.example \
  deploy/integration/backup.sh \
  deploy/integration/restore-drill.sh \
  ubuntu@<EIP>:/opt/ai-investment-copilot/deploy/integration/
```

然后准备只保存在 ECS 上的运行密钥：

```bash
cd /opt/ai-investment-copilot/deploy
cp integration/.env.integration.example .env.integration
chmod 600 .env.integration

cp integration/users.caddy.example integration/users.caddy
docker run --rm -it caddy:2.10-alpine caddy hash-password
chmod 600 integration/users.caddy
```

`.env.integration` 中所有 `REPLACE_...` 必须替换。每位成员在 `users.caddy` 中使用一个稳定用户
ID 和独立 bcrypt hash，禁止共享账号。`CORS_ORIGINS` 和 `INTEGRATION_SITE_ADDRESS` 必须使用
同一个实际域名。

集成环境使用显式的 `trusted_proxy` 模式：Caddy 完成身份认证并移除浏览器的
`Authorization`，再注入 `X-User-Id` 和至少 32 字节的内部 `X-Proxy-Secret`。API 不暴露公网，
且只有密钥匹配时才接受网关身份；普通 `trusted_headers` 在非本地环境仍会被拒绝。
这满足受控团队集成；对外试点或生产前必须接入企业
OIDC/SSO，并将后端升级为 JWKS/非对称令牌校验。

## 7. 配置发布流水线

在 GitHub 创建受保护 Environment `huawei-integration`，建议启用负责人审批，并配置：

| Secret | 内容 |
|---|---|
| `HWC_SWR_REGISTRY` | 例如 `swr.cn-south-1.myhuaweicloud.com` |
| `HWC_SWR_NAMESPACE` | 私有 SWR 组织/命名空间 |
| `HWC_SWR_USERNAME`、`HWC_SWR_PASSWORD` | 具备推送权限的专用凭据 |
| `HWC_ECS_HOST`、`HWC_ECS_USER` | ECS EIP/DNS 和运维用户 |
| `HWC_ECS_SSH_PRIVATE_KEY` | 与 ECS 密钥对匹配的私钥 |
| `HWC_ECS_KNOWN_HOSTS` | 经线下核验的 ECS SSH host key，不使用自动信任 |

工作流只允许手工触发。它会构建两个 SHA 固定镜像，推送 SWR，传输非密钥配置，并要求 ECS
上已经存在 `.env.integration` 和 `users.caddy`。发布后循环检查 API 的 `/health/ready`；失败会
恢复 `release.env.previous`，不会把失败版本留作当前服务。

## 8. 首次数据上线与动态演示

空环境只完成表结构，不能代表动态演示已就绪。首次上线选择以下一种数据策略：

- 推荐：在本地执行现有完整备份，将数据库 dump 和对象版本归档传到 ECS/OBS，在隔离环境做
  恢复演练后再导入集成环境；
- 备选：在集成环境从已获授权、可再分发的数据源重新运行行业/公司导入脚本，不导入个人本地
  临时数据。

迁移窗口内暂停本地 API/Worker 写入，迁移后以云环境为唯一共享写入端。成员本地数据库仍只作
个人开发，禁止本地和云端双向合并数据库。数据库 Schema 只能通过 Alembic 随应用发布；业务
数据通过 API、任务或版本化导入脚本进入。

动态演示入口使用 `/operations`，不要从静态工作台作为首屏。集成网关已将根路径重定向到
`/operations`。建议演示以下真实链路：

1. 研究雷达读取共享事件和任务；
2. 上传材料，观察 MinIO 归档、Redis 排队和 Worker 状态；
3. 建立/更新公司唯一投资逻辑及假设、变量、指标；
4. 发起检索并展示文本召回、Graph RAG 扩展及证据融合结果；
5. 进行复核/裁决，另一个账号刷新后看到同一变更和审计身份；
6. 执行量化计算并展示输入、公式、结果和可追溯来源。

前端中仍为静态叙事的页面不应作为“已动态实现”验收项；应按页面逐步替换为 API 数据，并在
CI 中保持前端 lint 和 production build 通过。

## 9. 备份、恢复与监控

每日低峰执行：

```bash
sudo -u ubuntu bash /opt/ai-investment-copilot/deploy/integration/backup.sh
```

脚本生成 PostgreSQL 自包含 dump、全部对象版本及内容哈希、镜像清单和 `SHA256SUMS`。配置
`OBS_BACKUP_URI=obs://<private-bucket>/integration` 且安装/授权 `obsutil` 后，会再复制到 OBS。
本机备份不能算灾备，验收必须确认 OBS 中存在副本。

恢复演练只在脚本新建的隔离 PostgreSQL 容器中执行，不触碰运行数据库：

```bash
bash /opt/ai-investment-copilot/deploy/integration/restore-drill.sh \
  /opt/ai-investment-copilot/backups/<UTC-stamp>
```

集成环境目标：每日备份，RPO 24 小时、RTO 4 小时；每月至少一次隔离恢复演练。建议本机保留
7 天，OBS 日备份保留 30 天、周备份保留 12 周。删除策略须在 OBS 生命周期中配置，并与 WORM
保留期一致。

最低监控项：ECS CPU/内存/磁盘、容器重启次数、`/health/ready`、PostgreSQL 连接数、Redis
队列积压、Worker sentinel、MinIO 可用性、备份时间和恢复演练结果。磁盘使用率达到 70% 告警，
80% 暂停大文件导入并扩容。

## 10. 迁移到托管服务的阈值

满足任一条件即进入 RDS/DCS/OBS 迁移评审：

- 日常活跃成员超过 5 人；
- PostgreSQL 或原文件数据超过 50 GiB；
- 要求月可用性高于 99.5%；
- 需要跨可用区高可用、分钟级 RPO、自动补丁或数据库审计；
- 对外部试点开放或处理受监管/强合规数据。

RDS 迁移时选择支持 pgvector 的 PostgreSQL 小版本，先执行：

```sql
SELECT * FROM pg_available_extension_versions WHERE name = 'vector';
SELECT control_extension('create', 'vector');
```

随后恢复 dump、更新 `DATABASE_URL` 并跑完整检索回归。DCS 放在同一 VPC，配置 ECS 私网 IP
白名单后更新 `REDIS_URL`。OBS 不能直接替换当前 MinIO：应用现在调用 S3 的
`ObjectLockEnabledForBucket`、`put_object_lock_configuration` 和版本 API，必须先实现并验证 OBS
适配器，完成 WORM、版本 ID、生命周期、备份恢复和内容哈希回归后才能切换。

## 11. 上线验收清单

以下项目全部通过才算共享集成环境“完成上线”：

- Terraform plan 经负责人审核，实际资源与代码一致；
- 只有 80/443 公网开放，22 仅办公网/VPN，5432/6379/9000/9001/8000 不可公网访问；
- 域名 TLS 有效，未认证返回 401，两个独立账号均可登录；
- `/health/ready` 中 database、queue、worker、object_store 全为 ready；
- 数据库 Alembic 只有一个 head，pgvector 扩展和 Graph RAG 查询通过；
- 完成一次“上传→归档→排队→抽取→检索→复核”的端到端动态链路；
- 不同账号看到共享业务数据，同时操作人身份可区分；
- 发布失败回滚演练通过；
- OBS 异地备份存在且 `restore-drill.sh` 通过；
- 没有真实密钥、用户 hash、Terraform state 或投研受限原件进入 Git/SWR 镜像。

## 12. 当前尚需云管理员提供的执行参数

仓库中没有华为云 AK/SK、区域、规格/镜像 ID、SSH 密钥对、办公网 CIDR、域名/备案状态、SWR
命名空间和账单授权，因此当前不能安全地代表团队购买资源或执行线上 apply。拿到这些参数后，
按第 5～7 节即可完成真实资源创建和线上验收；不需要再修改部署架构。
