# P2.1 量化行情增量生产实施记录

日期：2026-08-31  
范围：新交易日探测、有限重试、候选冻结、可观测报告与 CI 调度  
发布边界：任务只生成候选，不自动登记数据库、不修改默认清单

## 1. 交付结论

量化行情从“人工执行全量构建脚本”升级为两阶段生产链路：

```text
当前冻结清单哈希校验
  → 9 只证券 + 3 个行业基准最近会话探测
  → 无新会话：noop + 报告
  → 有新会话：按接口/证券有限重试
  → 全量前复权重建 + Tushare 双源门禁
  → 不可变候选 + 报告
  → 人工复核后另行发布
```

前复权历史值会随复权锚点变化，因此新交易日不能简单向旧 `bars.json` 追加一行。刷新任务只对
“是否需要构建”做增量探测；一旦发现新会话，仍完整重建并冻结新版本，旧版本及哈希保持不变。

## 2. 新鲜度与覆盖门禁

- 每次读取当前默认 manifest，并验证其中全部资产哈希；默认清单损坏时不得联网构建。
- 最近 14 个自然日按证券探测；A 股以三个行业基准的共同最新日期判断市场会话。
- 三个 A 股基准最新日期不一致时整批失败，不能把单接口延迟误判为新交易日。
- 港股以研究范围内港股证券的最新观测判断；个股停牌不会要求伪造行情。
- 任一源返回晚于 `--as-of` 的日期时阻断，防止时区或上游字段错误引入未来数据。
- 同一日期已有冻结候选时验证并复用；不覆盖目录，异常残留目录使用下一版本号。

## 3. 重试与告警

AKShare 初始化、证券行情、原始行情、行业基准、Tushare 初始化、`daily` 和 `pro_bar` 均使用默认
3 次有限重试。每次失败记录操作名、尝试次数、异常类型、脱敏原因和等待秒数；最终错误统一转换为
`MarketSourceError`。Token 和长凭证形态在进入报告前清除。

报告契约：`quant-market-refresh-report-v1`。状态包括：

- `noop`：无新市场会话；正常结果，不告警；
- `dry_run_update_available`：只探测到更新，未构建；warning；
- `candidate_built` / `candidate_reused`：候选通过冻结适配器及双源能力复核；
- `failed`：critical；CI 失败且上传脱敏报告。

本地报告位于 `.runtime/quant-market-refresh/`，不提交仓库。GitHub Actions 工作日北京时间 19:30
执行，要求仓库 Secret `TUSHARE_TOKEN`；报告保留 14 天，只有产生候选时才上传候选目录。工作流没有
contents 写权限，不提交版本，也不能自动切换默认数据集。
