# P0-3 资产备份、恢复与历史回填

## 数据保护边界

- PostgreSQL 是元数据、研究结论、版本与衍生产物的事实源。
- MinIO `copilot-documents` 保存按 SHA-256 寻址的不可变原件；bucket 启用版本控制、
  Governance Object Lock 和非当前版本生命周期策略。
- 文档删除采用墓碑：立即从活动检索索引移除并同步修订状态，原件仍受保留期保护，
  避免业务删除绕过合规保留。

首次启动或升级后执行 `dev.ps1 up`。它会等待 PostgreSQL、Redis、MinIO、API 和 Worker
全部 ready；对象存储不可用时上传会返回 503，不会降级成开发机绝对路径。

## 备份与 PITR

本地 Compose 已开启 WAL archive，归档到独立 `postgres-wal` volume。每天至少执行：

```powershell
cd E:\product\AI-Investment-Copilot
.\scripts\backup_local.ps1
```

脚本生成 PostgreSQL custom-format dump、SHA-256、全部对象版本清单、每个对象版本的实际内容
副本与内容 SHA-256。试点环境还必须把 `.runtime/backups` 与 `postgres-wal` 复制到另一台机器
或受控备份库；仅有 Docker volume 不是跨机备份。

本地隔离恢复演练：

```powershell
.\scripts\restore_drill.ps1
```

脚本验证备份 manifest 与文件哈希，在一次性 `copilot-restore-drill-*` PostgreSQL 容器中
执行 `pg_restore --clean --if-exists`，核对 `alembic_version`，并将数据库中的 object key、
version ID、content hash 与备份对象内容逐一交叉核验。演练结束删除临时容器，不覆盖开发库。
试点环境的 PITR 还须设置 `restore_command` 从异机 WAL 归档恢复并设定
`recovery_target_time`；本地基础备份演练不能替代异机 PITR 演练。

## 历史资产治理

```powershell
.\.venv\Scripts\python.exe -m scripts.asset_inventory
.\.venv\Scripts\python.exe -m scripts.backfill_asset_derivatives
.\.venv\Scripts\python.exe -m scripts.rebuild_search_index
```

回填脚本从保留的 `document.body` 追加 `semantic-v1` 运行，生成运行级切片、事实、事件
产物和权限索引；旧 `legacy-single-v1` 运行与规范段落不被覆盖。`missing_object_archive`
不能由正文反推解决：历史原件不存在时必须保持缺口，找回来源文件后再按哈希归档。
