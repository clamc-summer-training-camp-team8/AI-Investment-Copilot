## 1. 凭证与来源身份

本地配置同时包含 10k Token 和 `pro._DataApi__http_url`。系统现将二者作为同一凭证配置读取：

- Token 只留在进程内，不进入日志、报告、缓存或冻结资产；
- 自定义地址必须是无路径、用户信息、查询参数和 fragment 的 HTTPS Origin；
- `pro_bar` 显式复用已配置 API 客户端，不能回落到 SDK 默认地址；
- 缓存状态绑定 API Origin，不允许把原 120 积分官方端点缓存与新端点混用；
- 来源登记为 `tushare-compatible-supplement-v1`，不标记为 Tushare 官方服务。

来源策略为 `tuaremax-user-authorized-research-v1`：用户提供有效访问凭证，仅限内部研究、交叉核验
和字段补充，禁止对外再分发；商业化前必须单独复核服务条款及数据授权。

## 6. 受控发布机制与本地登记

2026-08-31 增加 `scripts.publish_quant_market_dataset`：发布人必须同时提供候选清单、审批后的
`dataset_id` 和 Manifest SHA-256。命令先校验受治理目录边界、清单与全部资产哈希、来源授权、
候选编号和审批哈希；`--dry-run` 不连接数据库，`--register` 只幂等登记，不改变在线默认配置。
同一数据集编号或数据版本出现不同清单时硬失败。

Catalog 新增 `default_market_dataset_id`，只在配置清单已经登记且清单哈希匹配时返回。前端按该
字段选择和标记默认版本，不再把“最新登记”推断为“默认版本”。集成 Compose 允许通过
`QUANT_DEFAULT_MARKET_MANIFEST` 显式切换，默认值仍为原 120 积分版本。

本地 PostgreSQL 已登记 `MDS-akshare-qfq-tuaremax10000-20260831-v3`，审计操作者为
`phase3-local-release`；登记后显式默认仍为
`MDS-akshare-qfq-tushare120-20260830-v1`。v3 使用现有两条真实人工确认信号完成回测，关闭市值
中性时与旧版本得到相同收益结果。市值中性正向/缺口门禁继续由单元与 API 契约测试覆盖；当前
真实信号集只有两只证券，不以虚构第三条信号生成产品级 Alpha 运行。
