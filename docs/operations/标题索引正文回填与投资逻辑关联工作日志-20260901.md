# 标题索引正文回填与投资逻辑关联工作日志（2026-09-01）

## 1. 工作目标与治理边界

本次把数据中心内仅保存公告标题的历史资料，按已归档原件批量解析为可检索完整正文，补齐
“文档—证券主体—当前投资逻辑”的可追溯关系，并让全局搜索和知识库 AI 问答只使用可核验
正文回答事实问题。

运行级 `thesis_relation` 只表示“已确认证券主体对应当前投资逻辑”，不表示文档中的某段事实
已经支持或反驳某条假设。本任务不自动创建、确认或升级正式证据；AI 回答继续标记为候选，
研究判断仍需人工确认。

## 3. 实现内容

### 3.1 可恢复正文回填

新增 `scripts/backfill_title_index_fulltext.py`，支持 dry-run、单文档重跑、并发解析、滚动窗口、
批次报告和数据库瞬时断线重试。每份文档独立事务提交，重复运行只选择仍处于“标题索引”的
活动文档。

回填保留原有 `title_index` 片段及 locator，新正文从当前最大 ordinal 后追加；成功事务同时写入：

- 文档正文、正文哈希、解析器版本和“完整正文”状态；
- 规范化段落/表格片段、确定性同比事实；
- 不可变摄取运行和 segment/fact/thesis_relation 制品；
- 权限感知全文索引与审计日志。

### 3.2 PDF/OCR 稳定性

扫描 PDF 使用线程内复用的 RapidOCR，会话限制 ONNX 线程并保证异常时释放原生句柄。PDFium
无法渲染的异常页按 180/150/120 DPI 降级到 Poppler；正文统一去除 NUL 字符，避免 PostgreSQL
拒绝文本写入。集成镜像增加 `poppler-utils`。

### 3.3 大文档分批写入与索引重建

正文制品和 `segment_search_index` 改为每 4,000 条分批 upsert，规避 PostgreSQL 单语句
65,535 参数上限。全量重建改为 `TRUNCATE ... CASCADE` 后每 100 份文档分批生成 tsvector，
避免约 48 万片段在一次执行器调用中占满内存/临时空间。

### 3.4 重复文档受控归并

新增 `scripts/merge_duplicate_title_documents.py`。只有同时满足以下条件才允许归并：

1. 源文档仍是活动标题索引、目标是活动完整正文；
2. 双方至少一份活动归档原件字节哈希一致；
3. 正文摄取失败运行明确记录目标为重复文档；
4. 所有证据 locator 都能映射到目标正文的真实片段。

归并只软删除别名文档，保留原修订和原标题片段作为血缘；事件、指标、证据、证券关系和当前
投资逻辑血缘转移到完整正文，并追加 `document_alias` 制品和双向审计记录。

### 3.5 检索血缘对账

新增 `scripts/reconcile_search_segment_lineage.py`。对旧摄取运行中的临时文档 ID locator，仅在
“目标文档存在同序号 locator 且片段文本逐字一致”时重定向，同时补齐历史索引缺失的
`segment_id`。知识问答层新增硬校验：引用 locator 必须以当前 `document_id#` 开头，漂移索引
不得进入模型上下文。

和原索引计数全部一致。

MinIO 并完成 WAL/健康检查。旧 Visual Studio 安装器解压目录、远程桌面诊断输出、VS Code 安装
缓存和 Torch 缓存均从 C 盘移动到 `E:\product\.runtime-recovery\`，未删除，可按原路径恢复。
