# 0002. AI 语义理解与确定性计算分属不同模块

- 状态：已接受
- 日期：2026-08-08
- 决策人：架构负责人、数据分析负责人
- 影响模块：`app/ai`、`app/calc`、`app/services`、`analytics`

## 背景

PRD 10.5 要求「数值计算由程序完成，模型只解释结果及其与假设的关系」。数据分析说明书 T13 同样规定「计算由确定性程序完成；AI 负责解释指标与投资逻辑的关系；研究员负责确认结论」。DA-AC-04 要求预期差、同比环比、趋势和简单同业比较可复核。

如果模型和计算在同一个模块里，实现上几乎必然出现模型顺手产出数值的情况。这类数值无法复算、无法写回归测试，也无法在提示词升级后保证历史结论稳定，直接违反可复核要求。

## 备选方案

**A. 一个 `app/ai` 模块同时负责抽取与计算**

优点：调用链短，一次模型调用可以同时拿到结构化字段和数值结论。
代价：数值不可复算；提示词一改，历史数值可能变化；无法对阈值边界写单元测试；违反 DA-AC-04 与 FR-V-002。

**B. 拆成 `app/ai`（语义）与 `app/calc`（数值与规则），由 `app/services` 汇总**

优点：`app/calc` 是纯函数模块，可脱库单测，可对阈值边界穷举分支；数值结论稳定、可复算；提示词与模型版本变化不影响数值。
代价：调用链变长，`app/services` 需要负责把两边结果拼装并处理不一致情形。

## 决策

选 B。

- `app/calc`：确定性计算与状态规则引擎，纯函数，`Decimal` 精度，禁止 import `app.ai` / `app.db` / `app.services`。输出携带计算所依赖的口径信息。
- `app/ai`：文档理解、抽取、影响分析。输出必须过 `contracts/ai/` 的 JSON Schema 校验，低置信度按 FR-R-007 降级进人工队列。禁止在提示词中要求模型计算关键数值。
- `app/services`：汇总两侧结果，生成状态建议，交人工确认。

规则阈值参数化在 `app/core/config.py:RuleThresholds` 中，带版本号；阈值变更记版本，历史结论不被新阈值覆盖。

## 代价

- 一次业务动作需要两次调用（模型 + 计算），编排复杂度落在 `app/services`。
- 模型输出的定性判断与规则计算的定量结论可能冲突。冲突不做自动仲裁，一律呈现给研究员确认，这会增加人工处置量。

## 影响

- `.importlinter` 中为 `app.calc` 配置独立性约束。
- `tests/unit/` 要求覆盖阈值的四种情形：达到、接近、未达到、数据缺失。
- `analytics/` 复用 `app.calc` 保证离线实验与线上口径一致，禁止在 `analytics/` 里另写一套计算。

## 回退条件

若出现某类计算无法用确定性规则表达、必须依赖模型判断（例如非结构化文本中的口径识别），不合并模块，而是在 `app/calc` 中定义显式的「信息不足」出口，把判断交回人工。
