# 架构决策记录（ADR）

记录影响多个模块或难以回退的决策。目的是让新成员知道「为什么是这样」，避免同一个问题被反复争论或被无声推翻。

## 什么时候写

需要写：

- 改动分层依赖或模块边界
- 改动 `contracts/` 中的跨模块契约
- 引入新的框架、存储或外部依赖
- 改动与产品红线相关的实现方式（人工闸门、计算归属、时间语义、版本策略）

不需要写：新增一个接口、修 bug、补测试、改文案。

## 怎么写

复制 [`template.md`](template.md)，命名 `NNNN-短标题.md`，序号连续。在 PR 里连同代码一起提交。

状态取值：`提议` / `已接受` / `已废弃` / `被替代（指向新 ADR）`。

被推翻的 ADR 不删除，改状态并在文末指向替代者。历史决策的上下文本身就是资产。
