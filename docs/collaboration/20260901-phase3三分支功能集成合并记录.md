## 4. 核心冲突与裁决

### 4.1 API、服务与仓储

| 冲突面 | 最终裁决 |
| --- | --- |
| API 路由注册 | 在同一应用中保留认证、助手、搜索、覆盖管理、自动采集、研究动态、复盘中心和数据中心路由，不用单侧入口覆盖另一侧 |
| Unit of Work | 同时注册量化、复盘、覆盖管理和逻辑变化汇总仓储，保持统一事务边界 |
| 文档归档 | `archive_upload` 同时支持用户上传与自动采集来源，并继续写入授权和来源字段 |
| 文档仓储 | 同时保留恢复能力与近期文档查询，供数据中心、采集任务和动态流复用 |
| 调度配置 | `WorkerSettings` 同时保留 Eastmoney、公司指标、Investoday 新闻和研报任务 |
| 模块分层 | 为 `app.collection` 增加明确的 Import Linter 边界，没有通过放宽既有契约规避依赖问题 |

### 4.2 AI Provider、Prompt 与 Skill

两侧都修改了 AI Provider、Gateway、Prompt 和 Skill 目录。最终处理如下：

- `knowledge-answer` 与 `logic-change-consolidation` 两个 Skill 同时注册；
- HTTP Provider 同时支持知识问答所需的同步调用和变化汇总所需的异步调用；
- Local Provider 为两类能力提供确定性回退，模型不可用时不阻塞搜索、采集和人工流程；
- 合并 Prompt 模板、输出 Schema 和 Gateway 方法，不用变化汇总覆盖知识问答；
- AI 只生成候选回答、汇总或草稿，不自动覆盖人工投资逻辑、复盘正文和正式证据。

### 4.3 前端路由与工作台

最终前端保留下列能力集合：

- 动态公司详情与指标编辑；
- 逻辑变化列表、影响详情和文档阅读器；
- 复盘总览、创建、详情与编辑；
- 数据中心及其资料、来源、运行和量化数据集子路由；
- 全局搜索与知识库助手；
- 工作台使用自动采集分支的实时研究动态，同时接入 Phase 2 Agent 的新建操作能力。

趋势数据结构没有二选一：最终同时保留预期下界、预期上界、失效规则和验证窗口元数据，避免公司指标页与逻辑影响页对同一趋势产生不同解释。

### 4.4 OpenAPI 与前端类型

三个分支都扩展了 API Schema 和前端类型，直接选择任一侧都会删除其他能力。最终以集成后的 FastAPI 应用重新导出 OpenAPI，并同步生成前端客户端：

- OpenAPI 共 121 条路由；
- 认证、搜索、公司覆盖、采集、研究动态、复盘和数据中心契约并存；
- 修复重复 Schema、可空字段、Decimal/整数边界以及采集状态和动态载荷类型；
- 前端编译结果作为契约合并的最终校验之一。
