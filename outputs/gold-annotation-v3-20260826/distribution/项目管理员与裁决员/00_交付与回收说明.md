# 独立金标 v3：交付与回收说明

版本：`independent-gold-v3-20260826`

## 先说结论

可以直接把本目录中的 A、B 工作簿分别交给两名专业研究员。工作簿已经预装全部待标注样本、原文链接、公司投资逻辑、三条核心假设、下拉枚举和进度检查；研究员不需要自己整理样本。

这些文件在回收、双人比较和裁决前仍是“待标注输入”，不能称为最终金标。

## 本轮覆盖

- 事件语义：120 条，双人全量独立标注。
- 正文事实：60 条，双人全量独立标注。
- Graph RAG 假设—公告关系：180 对，双人全量独立标注。
- 覆盖三行业九家公司；样本外 61 条、样本内 59 条。
- 保留相关样本与噪音样本，支持计算 Precision、Recall、F1、Cohen κ、Recall@K、MRR、NDCG@K 和路径正确率。

## 分发规则

- 标注员 A：只发送 `01_独立金标_v3_标注手册.docx` 和 `02_标注员A_独立盲标工作簿_v3.xlsx`。
- 标注员 B：只发送手册和 `03_标注员B_独立盲标工作簿_v3.xlsx`。
- 裁决员：在 A/B 回收并生成分歧队列后，再发送 `04_裁决员_分歧裁决工作簿_v3.xlsx`。
- 不要向标注员发送 `internal/`、历史金标、模型输出、检索排名或量化结果。

## 回收命名

- `annotator_A_completed_研究员ID_YYYYMMDD.xlsx`
- `annotator_B_completed_研究员ID_YYYYMMDD.xlsx`

两名研究员不得查看对方文件或讨论具体样本。固定列、样本 ID、工作表名和行数不得修改。

## 回收后验证

```powershell
python -m analytics.pipelines.gold_annotation_v3 validate <A回收文件.xlsx> --annotator A
python -m analytics.pipelines.gold_annotation_v3 validate <B回收文件.xlsx> --annotator B
python -m analytics.pipelines.gold_annotation_v3 compare <A回收文件.xlsx> <B回收文件.xlsx> --output <比较结果目录>
python -m analytics.pipelines.gold_annotation_v3 finalize <A回收文件.xlsx> <B回收文件.xlsx> <已完成裁决.csv> --output <最终金标目录>
```

比较命令会生成 `adjudication_queue.csv` 和 `agreement_report.json`。将分歧队列导入裁决工作簿；`裁决结果` 按 A/B 结果相同的 JSON 字段结构填写。完成后导出 CSV 并执行 `finalize`，生成三份最终金标 CSV 和 `final_gold_manifest.json`。

## 哪些文件不是人类金标

量化模块的收益、超额收益、最大回撤、换手和覆盖率由冻结信号、行情和基准确定性计算，不需要研究员标注，也不得反向用于决定“支持/冲突”等语义标签。
