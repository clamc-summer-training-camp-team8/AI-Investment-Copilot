# web — 前端应用

主要维护：接口与前端方向（问谁，不是评审权限）
PRD 层级：用户交互层

## 职责

PRD 6.1 的四个一级导航：

| 导航 | 内容 | 核心用户 |
| --- | --- | --- |
| 工作台 | 待确认卡片、待处理变化、复核任务、重大风险 | 研究员 / 基金经理 |
| 变化雷达 | 候选证据、影响分析、筛选与处置 | 研究员 |
| 逻辑卡片 | 创建、编辑、查询、版本、时间线 | 研究员 |
| 复盘库 | 逻辑时间线、复盘与经验沉淀 | 研究主管 |

技术选型待前端负责人在 [ADR](../docs/adr/) 中确定后落地，目录先占位。

## 工作台的产品要求

PRD 6.4：MVP 首页以任务为中心，**不做复杂可视化驾驶舱**。优先展示「今天需要我处理什么」。

四个卡片队列即可：待确认逻辑草稿、待处理变化、即将到期复核、重大风险。不要加大盘走势、词云、雷达图这类装饰性图表。

基金经理视图可按授权自选或试点组合聚合逻辑状态，但不做组合优化。

## 逻辑卡片详情页（PRD 6.2）

| 区域 | 展示 | 操作 |
| --- | --- | --- |
| 顶部摘要 | 证券、标题、方向、周期、负责人、状态、版本 | 编辑、发起复核、关闭、订阅 |
| 逻辑链 | 核心观点及假设树 | 增删改假设、设置重要性 |
| 指标与预期 | 口径、原始预期、实际值、预期差、趋势、同业位置 | 录入预期、查看计算依据 |
| 证据 | 支持 / 冲突证据，带原文定位 | 确认、驳回、修改关联、暂不判断 |
| 风险与失效条件 | 风险清单、失效条件与当前距离 | 编辑 |
| 版本与时间线 | 历史版本、变更原因、审计 | 查看差异 |

卡片由六个业务区块和一个系统区块组成，同时承担创建、编辑、跟踪、确认、复核和查看历史版本的职责。不是静态摘要页。

## 变化卡片（PRD 6.3）

必须展示的字段：

- 发生了什么：一句话事件摘要，**区分事实与推断**
- 影响对象：证券、投资逻辑、具体假设
- 影响方向与强度：相对具体假设，不是通用情绪
- 传导路径
- 原文引用：可点开定位到段落
- 模型版本与置信度
- 处置操作：确认 / 驳回 / 修改关联 / 暂不判断

## 三条界面红线

**1. AI 产出必须视觉上可区分。** 未确认的 AI 内容需要明确标识（草稿 / 候选 / 低置信 / 解析失败），不能和已确认内容长得一样。研究员必须一眼看出哪些是机器说的、哪些是人确认过的。

**2. 事实与推断要分开。** 事件摘要区分事实陈述与模型推断。无引用的结论标记为推断或不确定（PRD 10.5）。

**3. 引用必须能点开。** `evidence_locator` 要跳到原文并高亮段落。这是产品可信度的基础，点开对不上比不给引用更糟。

## 数值展示

预期差、趋势、同业分位来自后端 `app/calc`，**前端不做二次计算**，包括不做四舍五入以外的换算。

展示数值时同时展示口径信息：报告期、单位、数据版本、来源文档。FR-V-001 要求「展示口径、报告期、来源和差异」。

## 权限

前端不做权限判断，只按后端返回渲染。后端对无权限对象返回 404，前端不需要区分"不存在"与"没权限"。

不要在前端缓存跨用户的对象列表。

## 接口对齐

以 `contracts/api/` 为准开发，不读后端源码。接口未就绪时用契约生成的 mock。

需要后端加字段时提 PR 改 `contracts/api/`，需 1 个 approve。

## 性能

对齐 PRD 12.2：列表 P95 ≤ 2 秒，详情 P95 ≤ 3 秒。列表必须分页，时间线与版本历史按需加载。

## 埋点（PRD 11.5）

需要记录：创建入口、文件类型、AI 生成耗时、字段修改、草稿发布、变化曝光、原文查看、确认、驳回、无关、关联修改、状态建议接受/拒绝、复核创建、逻辑关闭、复盘发布。

事件需关联用户、逻辑、假设、证据、模型版本和时间。

这些埋点直接支撑北极星指标（经研究员确认并触发后续行动的「有效逻辑变化」数量及占比）与 AI 草稿接受率。漏埋点等于验收指标算不出来，不是可选项。
